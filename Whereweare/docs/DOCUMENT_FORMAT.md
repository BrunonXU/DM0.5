# 可选的文档约定

沿用现有项目文档结构。无需迁移全部文档，也无需复制另一份当前状态。

中台直接展示权威入口摘录；如果希望项目标签、路线图和复选框更稳定地自动更新，可以在原有状态文档采用下面的最小格式。示例内容不是实际项目状态：

```markdown
---
status: active
project_status: 进行中
stage: 数据验证
updated: 2026-10-12
evidence_date: 2026-10-10
---

# 示例项目

## 当前状态

这里写现在已知的事实、限制与阻塞，并链接完整实验记录。

## 里程碑

- [x] 冻结评测协议
- [ ] 完成固定场景评测

## 下一步

- [ ] 整理失败样本并记录失败类别
```

- `updated` 是文档实际更新日期；`evidence_date` 是本次摘要所依据的证据日期。未知时省略，不用修改时间猜测。
- `status` 是文档属性，`project_status` 才是项目标签。`stage` 是项目所处阶段。
- “当前状态／当前进展”节优先用于摘要；“里程碑／路线图”中的列表用于路线展示。有序列表仅表示计划，复选框的勾选才表达显式完成。
- 只有注册为权威入口的文档清单才会导入任务。历史、示例、模板章节及冻结、归档、草案文档不进入当前待办。
- 同一份文档里避免两个完全相同的复选框标题；歧义项不会自动导入，避免回写错误的位置。
- 清单文字就是稳定标识的一部分：改名会识别为原项移除和新项出现。手动创建的任务不受此规则影响。
- 旧文档含有更正、混合历史或相互冲突的状态时，先保留证据边界；不能为了让界面显示完整而勾选未验收事项。

注册表中的阶段、日期提示和路线摘录仅为登记时的上下文。来源变化后，中台会提示复核；可将明确的当前状态和结构化路线维护回该项目的唯一权威文档。
