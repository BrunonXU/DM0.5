# Whereweare 产品设计

2026-10-13 · 以现在为中心的并行时间线 v0.4

后续待评审方案见 [桌面界面与外置大脑方案](../EXTERNAL_BRAIN_UIUX_PROPOSAL.md)及[真实产品参考](../DESKTOP_DESIGN_REFERENCES.md)。用户已明确只做桌面网页，本文旧版中的手机要求不再作为后续范围。回顾只读与证据记忆重构仍待实施；本文保留 v0.4 设计记录，不代表新方案已经上线。

**打开即看到多线并行的变化、当前验收点和下一步；整体链路说明任务做到哪一环。**

## 1. 首页：项目时间树

- 横轴是事实日期，所有项目共用刻度；同一竖线表示同一天。未注明日期在独立区域，不混进历史。
- 首页只显示人工选定的当前主线，初始为 F1 · π0.5 积木分拣。4242、DAgger 默认作为并行支撑线展开；其他项目统一在项目库，主次由用户选，不由改动数量猜。
- 一条线只留项目名、当前一句话，以及影响目标的少数变化节点。普通维护改动进入详情。
- 点击线名进入项目，保留返回入口；详层显示决策、验证、任务与来源。返回恢复日期范围和查看位置。
- 手动暂时归档后默认隐藏；“已归档”中以灰色查看和恢复。归档不删历史，也不代表项目失败。

## 2. 每条项目线究竟追踪什么

| 信息 | 人看到的内容 | 约束 |
| --- | --- | --- |
| 目标 | 要交付什么、如何验收 | 建议和用户确认分开 |
| 现在 | 一句话现状 | 不抄项目简介 |
| 变化 | 上次审阅后改变了什么 | 事实、决策、阻塞、更正分开 |
| 下一步 | 最小可验收结果 | 不自动变成承诺 |
| 阻塞 | 卡在哪里、依赖谁 | 未知就说明缺证据 |
| 依据 | 日期、出处、验证边界 | 默认折叠，随时可追溯 |

目录与项目多对多：饮料瓶使用 DM0.5 和 g2_robot；DAgger 同时支持 F1 与 G2；PI0.5/RLinf 是共享依赖。登记每个顶层目录，同时避免把共享改动计成多个业务突破。新目录自动发现后应进入“待归类”，不自行升级主线；依赖仓库只关注版本/合同/本地接入变化。

## 3. 更新制度

- 后台轻量扫描发现文档变化，只标记“有变化待审阅”。不运行模型、不自称已理解。
- 聊天中 `whereweare？`，或网页点更新，触发同一套审阅约定。
- AI 读上一快照、改动和权威入口，必要时补读相关文档；不默认扫代码。
- 发布前校验来源指纹和上一版本。审阅期间文档变了就拒绝覆盖旧结论。
- 相同事件沿用稳定 ID；更正保留历史版本。一次变更跨多个目录，只计一个结果。
- 前端分别显示“文档已同步”和“AI 审阅截至”；断线/失败保留旧结论并明确它较旧。

## 4. 日报与周报

| 入口 | 回顾范围 | 输出 |
| --- | --- | --- |
| 每日总结 | 配置时区今天 00:00 至点击时刻 | 核心变化、主要阻塞、明天 1 个建议结果 |
| 每周总结 | 本周一至点击时刻，通常周五审阅 | 本周结果/转向、未完成目标、下周最多 3 个建议结果 |

时区在 `config/preferences.json` 设置，目前按用户会话环境采用 America/New_York。已有文档的纯日期保留原文，不擅自换日。首次导入历史只建基线；没找到今日新证据就如实说明。反复点击同日/同周产生修订，历史可回溯，不重复累计成果。总结保存截至时间与引用，下一次与前次比较；不直接拼接日报成为周报。

回顾内选择今日／本周立即增量审阅，手动触发。自动执行时点、通知渠道和成本上限尚未指定，不创建定时任务。

## 5. 进一步值得做的能力

**目标与偏航提醒。** 给每条主线维护一个确认的阶段目标和验收点，再观察活动是否支撑它。工具优化可以是必要依赖；没有主线进度证据只说明需要核对。提醒应形如：“连续几次更新都在采集工具，任务数据验收仍未推进；是否继续？”不推断工作时长，不替用户切换方向。

**开发建议。** 根据失败证据提出一个最小区分实验或下一验收点，说明它解除哪个阻塞；标明建议，允许采纳、推迟或忽略。不输出泛泛的“完善测试、优化性能”。

**学习路线。** 将知识缺口挂到当前阻塞。先区分“现在必需”和“之后再学”，完成一次能验证理解的小实验才记为掌握；不靠阅读量评分。

**决策记忆。** 保留为什么选这条路线、放弃哪种方案，以及什么新证据会触发重评，减少反复走回旧分支。

**一次短补充。** 对文档没有覆盖的线下进展，用户可补一句。后续应作为“用户记录”保留来源，不能伪装成文档或实测日志。

**撤回与更正。** AI 发布历史可追溯；下一步补一键撤回/纠错入口。错误摘要不会覆盖原 docs。

## 6. 信息与权限边界

Git 和 docs 仍是工程证据；Whereweare 是面向人的审阅入口。摘要 JSON 不替代原始实验记录，不修改原项目验收结论。

事实发生日期、文档日期、首次观察时间、审阅截止时间分别保存。部署/离线/现场验证不能互相替代；不用文件修改时间或提交量计算完成百分比。

原项目默认只读。AI 候选经发布器校验后更新 Whereweare；主次、归档由人工保存，与 AI 内容隔离。网页只监听本机，沿用现有可信访问通道。

## 7. 实现结构

```text
Whereweare/
  AGENTS.md                  固定协作约定
  skills/whereweare/          聊天触发入口
  prompts/                   共用审阅与日报/周报提示
  config/                    项目来源与输出结构
  tracking/directories.json  目录 → 项目映射
  tracking/current.json      已发布精炼快照
  tracking/history/          可追溯历史
  review_store.py / review.py 审阅输入、校验与发布
  review_jobs.py             网页触发本机 Codex 审阅
  web/                       时间树与细节
  runtime/                   索引、任务、候选与私有运行日志
```

复用 Python/SQLite/原生前端，不为首版增加向量库或第二套任务系统。来源指纹负责减少重复读取，语义审阅负责判断什么值得显示。

聊天 skill 与网页 worker 共用 prompts/schema；网页通过本机 `codex exec` 只读生成候选，再由受限发布器落盘。它是独立进程，不是唤醒当前聊天。[官方 skill 发现机制](https://learn.chatgpt.com/docs/build-skills)与[非交互调用](https://learn.chatgpt.com/docs/non-interactive-mode)是接入依据。

## 8. 打磨顺序与验收

1. **真实内容闭环**：每条业务线有可信现状、最新改变、下一步；读完首页可在 30 秒内说出最重要的变化。
2. **更新可靠**：来源变化可见、日期一致、不把历史当今日、同次变化不重复、失败不覆盖。
3. **层级和回顾**：主次/归档、点击进入详情、日报周报和修订可用。
4. **目标协作**：确认目标、证据驱动提醒、建议采纳和学习依赖，再打磨视觉。

衡量理解和纠错成本，不用节点数量、报告字数或通知频率当产品成绩。当前实现与验证只在 [STATUS](../STATUS.md) 维护，不把设计清单当成已上线功能。

## 以“现在”为中心的界面约定

米白纸面、32px标题、18px核心文字保留；主线红色最突出，支撑线低饱和。现在位于桌面约六成处，当前阻塞在其附近，下一步沿虚线接到右侧；后者是未排期建议，不是虚构日期。取消大块说明底色、重复主线/平台标签与长文摘要。

首页主线和人工 current 支撑项目同时显示。默认最近14天及未来7天，每条线最多两个日期组，同日多项点击展开。窗前最后记录标记真实日期；没有记录不填空话。普通记录沿线，人工 parent_id 才分叉；节点标题不截掉验收边界。

stages 压为紧凑阶段导航，名称与符号可见，详细状态/依据点开。状态来自审阅证据，不计算百分比，不写死完成阶段。更新时间、仓库链接与运行信息收进项目库/状态详情；首页只在异常时显示单个可展开提示。

普通上下滚轮自然滚页面。触控板横滑、Shift+滚轮、鼠标空白拖动移动日期；浏览器缩放保持原生，不再绑定滚轮缩放或阈值钻入。近两周/近一月/全部切换范围，偏离默认位置显示回到现在；日期映射对所有线一致。进入详情再返回恢复视角，后台更新不移动视图；重开首页回到近期，不恢复旧极端缩放。

线名与内部时间内容分离。桌面横移历史时当前阻塞与下一步仍固定；手机按屏宽形成局部横向滚动区域，线名固定，上下滚动仍是页面。手机左右箭头直达近期/下一步，范围使用原生选择器；不要求用户猜手势。

workspace_repository_url 放在 config/preferences.json，GET /api/state 与 /api/briefing 的 whereweare 中返回。缺字段的旧配置仍可读；菜单提供 Projects · GitHub。该配置不改变 Git remote、不授权提交或push，独立仓库不继承此远端。

项目登记 platform/supports 与人工 activity/tier/archived 保持独立。prepare 的 Git/dirty/mtime 只定位证据，不改变状态、不触发自动模型。
