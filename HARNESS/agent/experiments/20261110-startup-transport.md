## 连接与交互优化实现及部署

| 部分 | 本轮行为 | 保留边界 |
|---|---|---|
| 常驻网络 | 协调服务启动时只读预连接；闲置30秒检查，同一HTTP池跨planner生命周期复用；预热与生成不重复建链 | 不保存对话／任务状态；真实生成仍由授权planner触发；不改变代理路由或模型身份 |
| 取消和网络故障 | planner已断开时不发送仍在排队的请求；IPC回执未知时不自动重放／切回直连；连接池不存在时仅在尚未派发前退回原直连 | 原CONNECT阶段最多一次重试、请求写出后不重放保持；STOP不等待云端结果 |
| 首轮上下文 | `robo.inspect_plan()` 一次取得新鲜观察、几何与预览，默认approach在首次模型请求前准备 | 只读预览不授权动作；不强制使用默认候选，Astra仍可给连续新方案，动作前重新验当前测量 |
| 观测过期 | 只读preview明确报stale_observation_measurements／scene_expired时，本地observe并重试一次 | 不捕获未知提交、通信、反馈或身份故障来重放动作；新观察仍经原任务绑定 |
| 异常证据 | 首次几何缺失或相关工具失败时，自动通过现有show路径读取right／head，附失败原因、原请求及验证checkpoint后直接进入下一模型轮 | 每个诊断去重，最多3组自动补图；图像与源帧、ROI、任务绑定保持；没有添加动作重试或将深度缺失当成功 |

常驻网络服务使用私有目录和同UID Unix socket，权限700／600；套接字只传给planner，不进入PyRUA沙箱。凭据只由网络服务／原认证加载器使用；响应只保留受控诊断头，不保存HTTP认证头。原通用IPC大小默认保持64KiB，仅网络专用通道放宽至16MiB以传输入图像。

本轮没有自动把pending_review升级为成功，也未让本地程序替Astra决定所有恢复分支。最终模型finish仍保留；“已确定人工处理后的总结异步化”需另定义可靠终态条件，不借此次减少往返改变用户正在修复的抓后行为。

### 优化顺序与能力边界

1. **连接链路**：无任务状态的网络客户端提前准备并可跨运行复用，连接建立做有界协调；生成仍须用户开始，不能简单把连接数改1导致失败串行排队。需要按相同请求对照连接成功率及P50/P95，当前未测新的链路方案。
2. **观察与预览一起返回**：首轮提供新鲜几何、预览及视野摘要；同任务观测过期由本地helper有界重采样，再做预览。执行前保留当前观测重验，不延长旧观测有效期。减少让Astra仅为写observe而往返。
3. **恢复证据一次带齐**：发现深度不足，自动收集相关头／腕图、有效深度与已尝试分支后再交模型。只改框不能生成缺失深度；要改善可观察抓姿和实际证据恢复。明确需要人工处理后可先本地停止收尾，说明生成放后台，不能把未验证抓持当成功。
4. **验证程序直接执行**：保存任务相对的程序、适用条件及参数；熟悉场景依当前几何重新算轨迹，正常路径目标零次或一次模型规划。未知场景或分支再交Astra处理，允许其提出连续新动作。当前快照selected_strategies为空，失败只登记候选，尚无自动归纳任意分支并上线的完整闭环。
5. **常驻只读准备与精简摘要**：进一步减少6.78秒准备中的重复进程和静态装配；动态反馈、任务绑定、授权仍重新核验。上下文由6255增长到16959 tokens，可去除重复原始矩阵和日志，但既有缓存已命中，应排在往返与连接之后。

20秒若指点击到完整放置／复位，目前没有完成样本能证明达标。只把首动前三轮改成一轮仍不等于全程20秒；需要分别验点击→首发与首发→完整放置／复位，并区分熟悉场景正常路径、陌生场景和故障恢复路径。改动收益须冻结对照，不能把当前前两轮耗时直接相减作为承诺。

首发采用6000D接收事件的时钟，是发布回执而非精确物理起动；owner内部区间采用owner同机时钟，不跨主机相减。网页结束为墙钟，后台导出在终态后继续，不计入92.471秒。
