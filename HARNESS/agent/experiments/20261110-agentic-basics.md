# 参数化单块全流程：实现、部署与验收边界

**参数化抓姿、失败换方案、固定运输、按需视觉及参数经验消费已接通并部署。** 当前可以从 infra 的 Astra 模式开始单竖直方块的位置／平面朝向泛化测试；正常抓持后不需模型逐段指挥运输、插孔和返程。

**发布后的真机仍未闭环。** 用户随后两次 Astra 运行均异常：前一次首次模型连接超时；后一次接近实际到位，但压腕导致可观察性恶化，动作后感知失败，随后第二次模型连接超时。部署阶段没有发送 START 或调用付费模型；后续用户真实运行的模型与运动证据单列在下方，不能与离线验收混为一谈。

下一步只需在原任务页运行，先完成当前摆放，再独立改变朝向和位置。人类操作见[完整真机运行](../../docs/DIRECT_ROLLOUT.md)，当前事实以[STATUS](../STATUS.md)为准。

## 原因与修正

| 类别 | 之前 | 本轮修正 |
|---|---|---|
| 模型动作表达 | `skill(name)`，无法改变倾角／方向 | 连续 `pitch_offset_deg` 与 `variant` 进入 SkillIntent 和原生规划；默认自动搜索保持 |
| 零发布拒绝 | 候选耗尽也占用“已尝试动作”状态 | owner确认没有发布后恢复请求前状态，模型可换方案；有发布或未知执行不适用 |
| 抓取接缝 | 只选到规划候选，不保证下一阶段保留实际抓姿 | 实际到位＋独立验证后提交 owner 选择，新观测对齐方块对称坐标，抓取继承该选择 |
| 持物运输 | 对孔朝向提前限制搬运；固定倾角导致不可达 | 保留已部署的运输／精对孔拆分，加入桶外定点转腕备用路线，使用当前阶段实测关节软参考 |
| 验证等待 | 首个新场景缺held证据即结束；旧窗口噪声长期污染判断 | 有界补验证、兼容最新后缀、受限时间内恢复旧跟随证据；缺证据不冒充夹持成功 |
| 方块朝向 | 面内点云裁剪影响方形方向估计 | 平面完整边界的稳健方向估计；旧3静止帧方向跨度约8.60°降至1.01°，不视为接触精度认证 |
| 模型反馈 | 汇总可能丢失失败字段，普通图片关闭 | ledger保留 outcome/reason/checkpoint/诊断；PyRUA按需show/image/display，源图身份留证 |
| 固定程序 | 模型可能每阶段重新编写恢复判断 | baseline同源helper＋`place_held_block`；抓持后连续运行，只有异常或歧义才需要新模型回合 |
| 经验参数 | 主要复用登记恢复顺序 | 实际参数候选独立验证后形成Markdown元数据与固定JSON快照，baseline/Astra都消费；新场景不通过则回退默认搜索 |

参数是物体相对几何选择，不是关节角命令。倾角范围沿已有登记抓姿约定为-45～45°，方块方向0～3表示90°对称选择；当前没有通用任意6D位姿、自由中间路点或其他形状抓姿生成器。

## 经验使用及限制

每次正常任务结束仍从原owner日志整理诊断。只有真实放置验证和返程成功、且确实使用过参数的运行才形成参数经验候选；仅“规划成功”不会成为抓取经验。独立验证需要不同场景、实际参数使用、发布证据、同一运行身份、完整放置与返程，然后才能晋升。

已晋升经验写入RPent Markdown语料，具体参数在YAML元数据，执行读取内容固定的JSON快照。自由文字不eval、不改代码、不训练权重。加载时核对标定与参数schema；冲突偏好不自动选择；参数在新场景被原生规划拒绝且确认为零发布时回退自动搜索。当前真实参数经验晋升数为0，首次现场运行不依赖已有经验。

独立验证／晋升仍由已有受信维护入口操作，尚未新增infra经验审核界面。常规操作者只需使用任务页；不能把备注文字或一次模型总结当作经验已验证。

### 姿态为何偏离成功示教

模型实际发出 `motion("approach_grasp")`，没有指定 pitch 或 variant，也没有请求图片。底层先试额外倾角 0° 的四方向，均被工具与桶／目标物的模型扫掠拒绝；之后选中 +30°、variant1，第七个候选是首个可行项。

当前固定 `candidate_order=[3,0,1,2]` 使 `candidate_ranking.py` 提前返回，跳过路径、旋转、示教姿态和可见性的软排序。排序又发生在应用 pitch 之前；非零 pitch 会在 `skills.py` 跳过原示教接近曲线，保留的示教 IK 软参考不能保证自然动作。故“已复用示教”不等于最终执行了示教轨迹。

| 指标 | 最新接近实测 | 历史成功示教对应段 |
|---|---:|---:|
| 右腕 J6 | 3.50→50.23° | 0.94→6.92° |
| 右腕 J7 | −2.89→−38.70° | −2.11→−5.50° |
| 登记 TCP 轴相对水平向下倾角 | 7.90→47.70° | 5.50→15.53° |
| 末端总旋转 | 46.42° | 10.42° |

本次腕部参考点按实测 FK 上升约 88mm，TCP 下降约 62mm；J6 目标50.32°、实测50.23°。历史示教不是相同摆放的受控A/B，不能据此宣称直接搬用必然通过。对本次保存输入检查四个0°端点及直线路径，当前几何模型均拒绝；因此仅删除中间路点不足，必须核对工具／桶／目标包络和目标位姿构造。没有物理碰撞或穿透毫米的独立证据。

### 视觉和恢复为何没有接上

本次选中目标与原手眼投影预测方块顶面 y≈−40～64px，部分跨出640×480腕图。封存的运动末段画面也看到顶面被裁出、头部被手及支架遮挡。两组保存帧独立重放中，一组头部mask304像素、有效深度38点；另一组头部配对有 `duplicate_source_stamp:head`。这些不是完整终止时刻逐帧复现，不能将单个38点结果认定为唯一根因。

`surface_points_missing_or_invalid` 是物体表面几何不足，不能自动解释为外参身份改变。当前仍有两类代码缺口：

- `conditions.py` 未把该类视觉质量失败归入可恢复采样；`remote.py` 因而在补验证提交前返回 needs_attention，新结果还丢失原 verification checkpoint。helper 的确调用过补验证，但 owner 未收到该次请求。
- `scene_pipeline.py` 的备用视图错误名单未覆盖该原因；但实际也可能是已经切到头部后才深度不足，不能将名单遗漏当成唯一现场原因。

双视图均不可见时，在同一姿态等待不能创造新证据。需要有界重采样、视图选择，以及使用原 owner 检查的可观察位置恢复；不能伪造观察成功或单纯把深度条件删除。

### 本次证明／未证明与执行顺序

已证明本条生效：新包身份、Astra一次真实代码生成、单cell全流程组织、有界等待、0.402°末端关节误差未被旧0.3°条件阻断、实测停止和后台封存。未证明：显式参数换方案、按需图片、实际抓持与抓姿继承、固定运输、插孔释放返程、真实经验晋升；快照count=0。

1. **P0 抓姿与可观察性一起修**：当前／成功模板平推、小yaw优先，实际pitch×方向组合统一软排序；核对名义端点模型碰撞来源，避免第一个能过的极端抓姿直接获选。不另加可见性一票否决导致新的中断。
2. **P0 感知恢复合同**：结构化区分分割、有效深度不足、遮挡、重复帧及身份错误；保留已执行动作的验证checkpoint；先只读重获，再从已知实测位置有界调整视点。动作执行状态与验证状态分别显示。
3. **P0 模型网络连续性**：查代理／连接复用；对确认发生在connect且未发送请求的失败有界重连，保持原工具账本，绝不重放已执行动作。读写阶段未知状态不套用该策略。网页并列动作失败与网络失败。
4. 用本条保存输入核对自然抓姿、原生输出及感知恢复，再真机接近→抓取→固定运输→精对孔→释放→右移复位。完整当前摆放通过后，分别改变yaw和位置验证泛化。
