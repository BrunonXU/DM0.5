# HARNESS：实验索引与记录方法

这里按日期索引实验和工程验收。追查一次判断时，先看对应报告采用的输入、版本和验证层级，再沿证据链接核对原始输出。

理解长期设计请读[核心思路与设计原则](../../docs/ARCHITECTURE.md)。核对当前部署、实际结果与下一步请读[当前状态](../STATUS.md)。

## 记录规则

- 先在下表找同一问题的报告。补测写入原报告，保留旧结论适用的版本。问题、数据版本或评估协议发生实质变化时，用真实日期新建 `YYYYMMDD-question.md`，并在下表登记一次。
- 报告应能回答：用哪个版本和输入，与什么基线比较，实际运行到了哪一层，结果支持什么判断，还缺什么证据。把配置、一次性驱动、日志和回执放进同一问题的产物目录，正文链接可复查的原件或清单。
- 文档、代码与证据的维护归属见[项目协作规范](../../AGENTS.md#代码与实验归属)。结果改变当前判断时，更新[状态](../STATUS.md)中的结论和证据链接。
