# HARNESS：实验索引与记录方法

这里保存供 agent 接续与追证的实验和工程验收复盘。当前只有项目初始化检查，没有模型、感知或真机实验；工程文件和阅读页面通过不表示机器人闭环已通过。

人类方案在 [IMPLEMENTATION_PLAN](../../docs/IMPLEMENTATION_PLAN.md)，当前事实在 [STATUS](../STATUS.md)。实验报告回答一个具体问题，完整原始输出保存在对应产物目录，不把每次命令结果追加到首页或状态文件。

## 记录规则

- 使用真实实验日期和问题命名：`YYYYMMDD-question.md`。同一问题的多次检查更新同一报告；数据版本、评估协议或核心问题改变时再新建。
- 报告开头用 2–3 个短段说明结果、影响与下一步，然后记录问题、假设、版本身份、输入来源、方法、结果、失败与限制。
- 明确区分计划、已实现、离线通过、集成通过和现场结果；记录采用的配置与基线，不把计划中的检查写成已通过。
- 日志、逐次模型输出、CSV／JSON、截图与测试回执放对应 `artifacts/YYYYMMDD-question/` 或实际 run 目录，报告仅保存结论与必要引用。产物保留来源，不原地改写原件。
- 秘密值、认证头和 `API.MD` 内容不得进入报告或产物。确需记录调用诊断时只保存脱敏字段。
- 历史失败与被替代结论保留，注明适用范围并链接后续报告；实验涉及 F1 时链接其权威事实，不复制一份当前部署状态。
