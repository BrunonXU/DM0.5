# 按阶段推进、观测与重规划

原子技能应帮助任务继续取得进展：只要求当前阶段需要的信息；一个候选失败后，保留可行候选、局部推进和补观测的机会。质量不确定性用于选择方案与说明缺口，实际运动仍经过原控制的碰撞、限位、反馈与授权保护。

这是项目内手工引用的开发与验收技能，不是已学会的物理技能。写入提示或接口合同不代表运行链路已经实现；建立本技能时，通用可执行局部前缀与已观测自由空间能力仍缺。使用前核对 [AGENTS](../../AGENTS.md)、[当前状态](../../agent/STATUS.md)和[故障合同](../../docs/FAULT_POLICY.md)，按真实代码与证据更新结论，不把本文件当作功能完成证明。

## 开发与审查原则

1. **从当前子目标确定信息需求。** 明确操作对象、相关障碍、支撑／持物关系及完成证据。抓取可以不依赖精确桶孔几何；桶位于运动扫掠区域时仍须处理其障碍约束。后续阶段的信息缺失不能无差别阻断当前阶段，未知空间也不能记为已确认自由空间。沿现有状态与证据合同表达这些事实，不另造任务分类器或并行状态机。
2. **分开候选拒绝与任务终止。** 区分物体身份／测量不可用、质量告警、搜索未找到、真实控制约束及执行故障。低分、处理年龄或静止历史不足不能在另一层换名成为硬拒绝；错误身份不能伪装成有效几何。候选耗尽、求解超时或一次 IK 失败只说明本次尝试未找到方案，不证明物理不可达。
3. **选择有证据支持的可执行方案。** 比较已有几何、路径约束与失败结果，保留可解释的排序依据。不可把未经标定的分数叫作成功概率，不引入任意数值阈值，也不选取已被真实碰撞／限位检查拒绝的轨迹直接执行。粗模型疑似误挡时复核模型、坐标、附件及最终实际输出检查的一致性。
4. **缺信息时规划取得信息的动作。** 若完整动作暂不可行，检查是否存在经过原控制验证的局部推进或新视点，说明它将改变哪些观测或可达条件，执行后用新观测重算受影响后缀。没有实现局部前缀、已观测自由空间表示或相关动作接口时，明确报告能力缺口并交回可行动反馈；不得用一句“先靠近”冒充已经可执行的恢复。
5. **让正常失败成为结构化结果。** 在既有回执中保留失败原因、作用域、实测证据、动作是否发布、已试方案和可继续位置。未找到目标、候选不可行、观测待更新等应允许调用程序分支处理；参数／API 误用与基础设施异常单独诊断。不要用笼统异常抹掉已有结果，或把一次普通失败直接升级为整条任务结束。
6. **恢复遵循实际发布状态。** 零发布重规划与已执行动作修正使用各自已有预算；不知道是否发布、部分发布或回执丢失时先查询／停止并按 owner 合同核实，不重放请求。动作已完成而成功证据不足时先补验。反馈失联、实际碰撞／限位、停止和撤权保留原保护；观测恢复本身不重新授权运动。
7. **本地处理已知恢复，Astra 决定新策略。** 在已有有界恢复机制内，凭新观测或不同参数继续有意义的尝试；没有信息变化的原地重复不算推进。新抓法、路线、接触方式或观察策略交给 Astra，提供当前阶段、发布状态、已试结果和剩余能力。默认只传数值；只有 LLM 明确指出数值无法分辨并请求视觉辅助时才发相关图像。不得预写横躺扶正的动作答案，也不把开发者修复记成自主发现。

## 验收矩阵

按本次改动选择受影响路径，使用真实失败记录与正常对照；以下是可观察的验收要求，不是新增运行准入门槛。

| 情形 | 应观察到的行为 | 不能据此宣称 |
|---|---|---|
| 后续孔口几何缺失，当前抓取相关几何可用 | 当前阶段按所需信息继续；相关障碍仍参与原检查 | 桶附近任何轨迹均安全 |
| 分割质量下降，但身份与本阶段测量仍可用 | 保留告警与来源，允许候选比较／原控制复核 | 分割分数就是成功概率 |
| 当前对象身份或几何不可用 | 返回具体缺口；定位、补观测或请求新策略 | 未知物体可直接执行抓取 |
| 一个候选失败，仍有不同候选或新观测 | 失败以结果返回，剩余方案能被实际调用，不直接结束任务 | 所有候选必有一个物理可行 |
| 完整动作失败但局部推进可能可行 | 已实现的规划器验证该段与实际输出，随后消费新观测；未实现则明确缺口 | 有提示就已具备主动观测能力 |
| 实际碰撞／限位、失联、停止或撤权 | 原保护生效，拒绝该运动或停止，结果留证 | 为取得进展可以绕开保护 |
| 未知／部分发布或已到位但缺成功证据 | 不重放；查询原请求或补验，保留已完成阶段 | 回执失败等于动作没发生 |
| 本地恢复无进展或已有预算耗尽 | 给 Astra 具体失败、已试变化和能力缺口；结束时说明真实原因 | 搜索未找到等于任务物理无解 |

涉及执行链时沿正式入口跑零硬件输出验收，覆盖候选被拒后继续、实际动作接收及停止收尾；修改 owner／恢复还需原生集成检查。模型响应、后续反馈或场景若模拟，逐项标明。汇报分别列出合同／代码实现、离线与集成结果、部署身份、真机证据和下一步；不能用测试数量或程序返回成功替代物理成功。

## 依据与使用边界

[PyRUA-Lean](https://github.com/DAGroup-PKU/PyRUA-Lean/blob/main/docs/getting-started/how-it-works.md)支持同一 Python 程序内检查结果与重试，并将普通运动／分割失败作为返回结果。[ASPIRE 的初始分析](https://github.com/NVlabs/ASPIRE/blob/main/.claude/skills/iterative-debugging/skills/task-exploration.md)把任务、几何和策略作为可由后续证据修正的假设。这里复用开发原则；不引入上游具体动作 recipe，不声称上游已替 F1 实现局部推进或真机验证。
