# HARNESS：协作入口

本页约定 HARNESS 全树的稳定协作方式，遵循 [Projects 根规则](../AGENTS.md)与[项目规则与协作习惯](../PROJECT_RULES_AND_PREFERENCES.md)。用户指定本项目位于 `projects/HARNESS`；不因通用任务目录约定擅自迁移。

人类说明从 [README](README.md) 进入，当前事实只维护在 [agent/STATUS.md](agent/STATUS.md)。本页保存读取路由、边界与验收规则，不累计运行结果、部署版本或实验流水账。

## 每轮接续

1. 先读本页与 STATUS，核对当前目标、已确认决定、实际完成范围、未验收项和下一步。新用户指令优先；计划和历史记录不能覆盖新的真实证据。
2. 设计与实现读取 [IMPLEMENTATION_PLAN](docs/IMPLEMENTATION_PLAN.md)，依赖选型和源码来源读取 [UPSTREAM_REUSE](docs/UPSTREAM_REUSE.md)；仅按本轮需要读取实验与代码。
3. 涉及 F1 积木时，先读其 [AGENTS](../tasks/F1_ComplexyToys/AGENTS.md)与 [STATUS](../tasks/F1_ComplexyToys/STATUS.md)。修改 DAgger、RLinf、F1-4242 或其他工程前，再读对应局部规则；HARNESS 不另维护 F1 当前状态。
4. 结束前核对对应正文、STATUS、TODO 与证据链接，只更新发生变化的内容。未完成时留下已做、未验收、阻塞与可继续执行的下一步。
5. 并行工作只修改约定文件，合并前重读最新内容；保留他人的未提交改动，不擅自提交、推送或覆盖历史证据。

## 实现与执行边界

- 优先复用已固定身份的上游源码与现有 F1 能力；先查现成接口，再做任务适配，不复制一套通用模型、机器人或控制框架。
- 项目初始接入默认只读与离线。日志、保存观测、几何计算及接口模拟通过，不代表控制网关、模型调用、标定或硬件动作已经实现。
- 真实运动继续由实际控制所有者负责授权、锁、通信与保护。未来 HARNESS 的物理执行须在该所有者下取得新鲜的本地真实 START 授权；不得远程伪造 START、复用旧授权或绕开原控制保护。
- 模型输出是待校验的计划或建议；不能直接冒充可信硬件状态、成功判据或已执行动作。执行与反馈分别留证，失败、保持、取消和恢复不得合并成成功。
- F1 RLT 可沿原任务并行推进，资源、数据准入、训练身份和部署状态仍以原任务为权威。HARNESS 的阶段推进不隐含切换模型、启动训练或替换生产控制。
- 每次训练包括预检与恢复都遵循根规则接入 W&B，分类和 run 身份明确；没有发生训练时，不创建虚假的训练结果或在线监控结论。

## 私密配置与源码身份

- 根 `API.MD` 是已有本地私密文件。凭据只能由已授权调用所需的本地认证组件读取；正文与取值不得进入终端输出、日志、模型上下文、网页、导出包或 Git。文档仅记录配置来源和可用性，不记录秘密值。
- 认证字段与业务输入分开，必要诊断只输出脱敏结果；不得为检索、摘要或说明将凭据文件发送给模型。
- 上游独立检出保持各自 Git 身份，忽略的源码目录由锁定清单索引来源、提交和适配关系。不要把嵌套 Git 目录误加入根仓库，也不关闭稀疏检出或改现有上游远端。
- 保留源码、配置、数据与运行身份的对应关系。对人的框架版本按“产品／技术＋V整数”独立登记，先核对发布登记与已预留编号；未分配时写未分配，不猜测 V1，也不套用 F1 控制版本号。

## 文档与证据职责

| 内容 | 唯一维护位置 |
|---|---|
| 人类导航 | README |
| 目标、架构、实施顺序与验收合同 | docs/IMPLEMENTATION_PLAN.md |
| 上游来源、复用与适配边界 | docs/UPSTREAM_REUSE.md；具体源码身份以锁定清单为准 |
| 当前事实、已确认决定、未验收边界与下一步 | agent/STATUS.md |
| 待办、前置条件、负责人和暂缓事项 | agent/TODO.md |
| 同一问题的实验结论与完整复盘 | agent/experiments/YYYYMMDD-question.md |
| 原始日志、逐次输出、测试回执与机器清单 | 所属 artifacts 或实际 run 目录 |

- 使用准确文件名 `AGENTS.md`；不另建 `agent.md`、`agents.md` 或第二份 Current／Latest 正文。
- 每份 Markdown 标题与必要 metadata 后先用 2–3 个短段说明结论、影响和阅读时机；详细命令、参数和证据后置。人类文档不复制 agent 运行流水。
- 明确区分方案、实现、离线通过、集成通过与实际部署；每一项事实有适用版本和证据。旧结论注明被替代关系，原件与历史失败记录保留。
- 同一问题的多次检查汇入一份日期报告，不为每次命令生成文档；机器输出不逐个包装成 Markdown。实验发生前不预写成功结果。
- 教学阅读复用 6000D 的 Why&How 4243。只登记公开人类原件并限定读取范围；`API.MD`、agent 运行材料和原始产物不纳入网页，不另建站点或占用 4242。
