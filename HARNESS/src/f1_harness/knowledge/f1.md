# F1 单块任务执行知识

你通过受限的机器人对象完成一块积木到对应孔口的任务。机器人只接受现场已经准备并授权的任务；工具返回的测量与验证证据决定是否完成。

依次接近、抓取、验证抓取、转移、检查在手姿态、对准、插入、释放并验证放置。正常运输由本地程序执行；新朝向、路径受阻或视觉丢失时，模型根据实测几何和必要图像重新提出方案。

抓取方向相对当前物体坐标计算，物体位置与朝向改变后由当前观测重算。只在几何有歧义时按需看图；模型提出的参数仍由原生规划器求解，规划可行不等于实物成功。

- 使用 `robo.geometry()` 获取当前 TCP、物体、孔口、障碍物和名义物体相对 TCP 抓姿。矩阵是16个按行排列的 SE(3) 数值，平移单位米；world 指返回的原生世界系，不是图像像素或 IK 内部坐标。
- `geometry_status='partial'`可能表示已经认出积木，但当前可见面不足以估计抓姿。`pose=None`不等于目标消失，`held=None`不等于空手。先读当前TCP、已测表面／可能占据范围、各相机的几何失败数字及局部运动能力；没有完整抓姿时不反复调用默认抓取。深度网格留在本地检查，数值摘要不会把未知空间标为空闲。
- 目标姿态与环境完整性分开看：`object_pose_available=True`而整体`geometry_available=False`时，保留并使用真实目标数值，不把桶体缺测说成积木不可见；仍按返回的`available_skills`选择观察运动。`quality_warnings`说明测量局限，不自动否决已可用的几何。
- 初始预览存在时，Python 已有 `initial_plan` 和 `g=initial_plan['geometry']`，直接复用。默认不可行时，把本地建议或模型提出的最多6个不同参数字典交给 `pick_with_candidates`：同一程序预览、执行并连续抓放；提交因新观测失败且owner明确零发布时才换下一候选。已运动、未知状态、STOP和续接失败立即返回，不重复已发生的动作。不在外层另加重试循环。
- `tool_geometry` 给出TCP坐标系下注册的保守碰撞包络，其中可能包含夹爪空腔；TCP点避开桶不代表整个夹爪／腕部包络避开桶。失败的 `collision_location` 区分起点、终点和中间扫掠，`segment_start_tcp_pose`／`segment_end_tcp_pose` 与 geometry 使用相同原生world系。终点被阻挡应改姿态或预抓位置；两端都清晰但扫掠被阻挡才考虑改变连接路径，不反复修改无关实体提示。余量区与几何重叠的区别由公共规划／执行检查处理，不修改门槛或自行跳过复核。
- 用 `robo.preview(name, **parameters)` 只读检验候选，查看碰撞／不可达原因后改变方案。`planned=True` 不是已执行，也不保证下一帧仍可执行。候选耗尽只说明已尝试方案失败，不能据此声称整个任务无解。
- 接近／重抓接受连续 `grasp_tcp_pose`（物体相对TCP）、`approach_direction_object`（从抓取点指向预抓位置的方向）和 `approach_distance_m`。可改变抓取点、yaw、roll、pitch和接近方向，不限四个注册方向。不能与旧 `pitch_offset_deg`／`variant` 混用。目标物体、标定、关节限位和碰撞模型仍由控制端管理。
- `motion('move_tcp', target_tcp_pose=..., target_frame='world', via_tcp_poses=[...])` 提交自由空间目标与中间路点；也可用 object／hole 坐标系。仅在本次允许技能包含 move_tcp 时使用。持物运动必须有实测在手变换；自由移动会使旧的接近、对准和插入结论失效，不能凭到达某个坐标直接松手。移动完成后重新观察并走语义验证。
- 默认技能和历史成功路线仍可直接使用。旧 `pitch_offset_deg`（-45到45度）与 `variant` 0..3 是便捷参数，不是模型全部的动作空间；不要为了尝试固定编号而忽略当前几何。
- 规划候选耗尽且 `no_motion=True` 表示没有物理动作：读取 `planning_diagnostic`，改变倾角或方向后重新规划，不重复相同参数。未知／部分发布不能按此重试；已完成接近后的 `grasp` 自动继承真实执行的抓姿。
- 确认 `verify_grasp` 成功后，可直接调用 `place_held_block(withdraw=True)` 连续完成运输、桶上方在手姿态复核、精对孔、插入、释放验证及右移返程；不需要在正常运输期间调用模型。宏失败时读取结果，从尚未完成阶段继续，不能重新播放整段。
- 用 `robo.show('right')`／`robo.show('head')` 请求必要画面，或 `display(robo.image('right')[y0:y1,x0:x1])` 查看裁图。头部模型图使用既有ROI并可能缩放，不能将其像素直接当原分辨率标定坐标。
- 几何缺失先读取 `missing_entities` 和当前子目标；只恢复相关证据。数值不足且明确请求后才使用右腕／头部图；在同一cell按相机调用 `robo.locate_entities(camera, entities)`，再用 `robo.inspect_plan()` 获取测量。只提示实际可见且身份明确的实体，不重复索取相同图。当前完整抓放接口仍可能要求桶体参考；这属于接口依赖，不代表精孔位是所有抓取的物理前提。提示坐标相对刚显示的完整图归一化到0到1；工具还原ROI／缩放，提示不是三维位姿或成功证据。
- 感知恢复失败不能只原地空等；考虑有观测收益的接近或换视点。若本次允许`move_tcp`且局部环境回执说明其所需证据可用，可提出world坐标的观察目标，独立预览，通过后执行并重观测。局部环境不是抓姿，不能据此使用object／hole相对目标、接触或松爪。路径仍受当前实测夹爪、环境覆盖及原控制检查；拒绝时读具体未知区域／障碍后改变观察方案，不重复相同参数。已运动阶段有验证checkpoint时只补验，不重放动作；不伪造新鲜测量或盲目撤离。
- 抓取失败可重新观察后重新抓取；插入失败先撤退、重新观察和对准。物理修正次数以本任务owner返回的预算为准；明确零发布的规划搜索不等于已经执行一次重抓，未知／部分发布不能按零发布重试。
- `completed` 只表示调用完成，必须查看 `outcome`；`verify_placed` 的独立成功证据表示已放置。若准备的任务包含 `withdraw_reset`，随后调用它完成离孔、右移避桶和复位，复位成功后才能宣布完整任务成功。
- 放置确认后不得重新抓取、插入或释放。返程失败保留放置结果，有已停稳 checkpoint 时按预算 resume；有验证 checkpoint 时只 recheck，不重放已执行动作。
- 插入未验证时不能释放；图像不明确时保留待审。停止、人工接管和控制故障服从原控制端。
- synthetic 明确表示软件测试，不得描述成真实机器人结果。关节位置误差不是已测接触力。
