# F1-4242 使用说明

适用机器人：F1-09，局域网 IP `192.168.31.58`。入口 **http://192.168.31.58:4242/**；通过 6000D 端口转发也可打开 **http://localhost:4242/**。

## 先看现场

总览和姿态页面最上方是头部、左腕、右腕相机。实时图像以各自收到帧的时间判断，缺帧时显示缺帧，不把历史图像当实时图像。设备状态分开呈现连接、关节反馈与相机反馈。

## 调整双臂和夹爪

1. 进入“调试与姿态”。有新鲜反馈时，目标输入从当前实测值开始；没有反馈显示未知，不补零。
2. 点击取得控制权，输入约定的控制码。校验成功后，控制状态变为红色，表示当前浏览器持有控制权。代码不展示在网页资源或文档中。
3. 选择关节组，拖动滑条或输入数值。滑条两端为该轴配置范围；输入改变的是目标，3D 预览用于核对。
4. 点击执行，核对目标并确认。以服务返回的执行状态和反馈判定结果为准。
5. 使用“跟随实测/对齐实测”放弃编辑目标并重新读取当前状态；结束操作后释放控制权。

手动双臂当前仍限制单次变化 5°、5°/s、15°/s²；这些是该调试功能的配置，不是硬件能力上限，也不限制独立 Pico 的轨迹。滑条全范围用于表达和保存目标，超出单次动作范围时服务会拒绝执行。没有环境碰撞规划，不把 3D 画面当碰撞安全判定。

反馈变旧时不能用目标输入代替当前状态。浏览器断线/租约过期会停止本工作台的输出并释放控制权；页面停止键不是硬件急停。Pico 使用相同控制锁，运行时不能由网页强抢控制。

头部、身体和底盘当前只读。身体关节角度不能直接称为腰部厘米高度；没有已验收的“一键全身复位”。

## 保存和载入姿态

填写名称后，可以保存当前实测或编辑目标。载入预设只改变目标，不触发动作；执行仍按部位确认。导入导出使用带机器人身份和关节名的 JSON，服务会检查范围、单位与身份。

## 3D 模型

鼠标旋转、缩放观察 F1 模型。实测模型与目标预览分开标识；关节名称、角度转换和未知项见[模型说明](MODEL.md)。机器人模型不是现场环境地图，也不能据此证明机械零位已现场标定。

## 数据文件夹和审核

数据页按已保存记录显示文件夹。打开一条后查看文件、大小、录制时间、话题等信息；已有历史三路预览可单独打开，不与实时相机混淆。

审核可以标为待审、通过或不通过，并填写备注。审核记录另存到本工作台 runtime，不改 MCAP、不删除原始数据。审核通过表示操作者的审阅结论，不自动代表数据已完成训练验收或上传。

现有 LXL 录制落盘方式不变。页面提供录制状态信息，不代替原录制入口；meaxiao LeRobot 录制器、传输队列和中央平台需后续确定存储方案后再接。没有伪装成可用的网页录制按钮。

## Pico

Pico 页面提供独立上肢包的检查、启动、停止脚本。请在 F1 现场终端执行，详见[上肢说明](../../pico_upper/README.md)。网页不会自动启动遥操、复位、录制或上传。

## 常见问题

| 情况 | 处理 |
|---|---|
| 网页能开但没有关节反馈 | 检查基础驱动和 ROS 状态，SSH/HTTP 在线不代表电机节点在线 |
| 相机显示缺帧 | 分别检查对应相机，不用另一相机健康状态代替 |
| 无法取得控制权 | 检查控制码、其他浏览器和 Pico 是否占用；不用停止其他进程来强抢 |
| 目标已输入却无法执行 | 检查本组能力、实测新鲜度、单次变化和时长，页面会显示具体原因 |
| 修改前端没刷新 | 在 6000D 查看 `systemctl --user status f1-console-web-sync` |
| 4242 打不开 | 局域网用 F1 地址；远程使用 VS Code 转发后的地址，并检查 SSH 隧道服务 |

开发者请读[接口文档](API.md)与[架构说明](ARCHITECTURE.md)。
