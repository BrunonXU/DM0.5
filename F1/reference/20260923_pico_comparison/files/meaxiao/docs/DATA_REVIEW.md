Clash 的“proxy enabled”提示不等于网页开放到公网。端口占用时不会抢占/终止其他服务。

自动传输由独立的6000d接收服务负责，网页本身不访问机器人。逐文件SHA-256、视频帧数/帧率和源数据契约校验通过后，

```bash
cd /home/user/meaxiao/pico

```

在**浏览器所在电脑**开终端，建立转发并保持运行：

```bash
ssh -N -L 8765:127.0.0.1:8765 F1_D070
```

浏览器打开 **http://127.0.0.1:8765/**。如果直接使用机器人的浏览器，无需转发。
SSH 别名必须是该电脑上可用的 F1_D070。端口冲突时服务器改为 `./dashboard.sh --port 8775`，

`Ctrl+C` 只停止该网页服务；`stop.sh` 不管理网页，不影响已保存数据。

参数 `--root /path/to/dataset --cache /outside/dataset/cache --logs /path/to/logs` 可查看其他本机数据。
缓存不可放入数据集内部。页面无远程运动、开始录制、删除 episode 等接口。

## 每次存盘后的流程

1. B 单击保存 episode，录制器最后更新 `meta/info.json` 作为提交标记；F1后台冻结完整条目并排队。
2. 6000d通过SSH接收、校验、重新编号并原子发布；网页每5秒检查中央索引，只分析已发布数据，未完成传输不展示。
3. 完成后刷新计数、分布和当前条目。扫描耗时另计，5 秒是轮询周期，不是完成 SLA。
4. “跟随最新”默认选最新条；点击历史会关闭跟随，避免复核过程中跳走。
5. 点击曲线/时间条定位三路视频，核对四个阶段后确认边界；只写带原数据哈希的标注副本。

初次扫描需检查全部历史；分析进程降低调度优先级，BLAS 限一线程，不导入 ROS、不发布控制。
历史很多时仍有 CPU/磁盘开销；如影响数采，应把完整数据复制到分析机独立运行，不承诺零资源影响。
三路视频共享定位和播放/暂停入口，浏览器独立解码，播放过程中不保证硬件级逐帧同步。

## 四阶段与一张综合图

默认任务：抓取手机 → 移动到放置点 → 放入盒 → 返回并复位。全部帧（含 X+Y 复位）共用实际源时间轴，
四行依次为位置、速度、加速度、jerk，背景色和文字标明阶段；下拉框可选择全部 27 轴。
采用青 `#4DBBD5`、绿 `#00A087`、朱红 `#E64B35`、靛蓝 `#3C5488` 的 Nature 风格配色。

自动分段是**候选**：底盘线速度模长 >0.04 m/s 或角速度绝对值 >0.08 rad/s 视为活动，合并不超过
2.5 秒的停顿，保留至少 0.6 秒的持续运动，取最长两段作为去程/返程。其余时间分别归入操作阶段。
没有足够运动段时显示“无法分段”，不强行四等分。长纠错、多次往返、原地操作都可能误分，
必须回看视频人工修正；姿态或夹爪变化不能证明手机抓取和入盒成功。

## 技术指标的含义和边界

| 指标 | 计算和用途 | 不能据此断言 |
| --- | --- | --- |
| 源实测 fps | `(N-1)/(最后源时间-首帧源时间)`；同时检查名义 30 fps 时间轴 | 仅修改 fps 元数据就有真实 30 Hz |
| 完整性 | 27D 名称顺序、行数/索引、有限数、时间单调、补充图像哈希及覆盖 | 检查通过就代表任务成功 |
| 最大相机时差 | 同一组三路源时间最大值减最小值，检查 ≤50 ms | 三个非硬同步相机同时曝光 |
| 状态/动作年龄 | 已记录对齐年龄，检查 0–50 ms | 电机内环无延迟 |
| 视频容器 | ffprobe 的尺寸、fps、时长；提供 nb_frames 时核对独立文件帧数 | 无 nb_frames 时自行用时长乘 fps 当实测帧数；容器检查不是解码检查 |
| 跟踪 RMSE | 同帧 state 与 action 差值的均方根；双臂聚合 14 轴 | 末端定位精度、接触精度、补偿时间延迟后的误差 |
| v/a/jerk | 实际不等间隔源时间上 11 帧局部三次最小二乘，取一/二/三阶导；边缘 5 帧不外推 | 电机 1 kHz 内环的真实瞬时 jerk；过强滤波可降低峰值，不代表更好 |
| P95、峰值 | 绝对导数分位数描述常见高强度，峰值定位突变；阶段值先取每帧14臂轴最大绝对值，再求 P95 | 越低越好；需同时看任务时长、运动范围和跟踪误差 |
| 根位移/路程 | 底盘体坐标速度旋转积分到本 episode 初始坐标；路程积分速度模长 | 无漂移全局定位；当前数据不含所有关节根节点世界位置真值 |
| 长尾候选 | 时长、路程、累计转角、误差的分布；n≥20 且 IQR 非退化时显示 Q3+1.5IQR 高尾 | 20 条足够代表全部场景；高尾样本应直接删除；已解决语义长尾 |

关节位置单位是 **度**，夹爪是 **0–100%**，底盘速度为 m/s、rad/s。底盘图的位置为积分估算，
后三行为实测体坐标速度及其一、二阶导数；不能当作世界坐标加速度。末端 Cartesian FK/物体位姿真值未实现，
不伪造手机接触成功率或毫米级精度。导数缺失画为断线，不填零、不抽点隐藏峰值。

完整逐帧视频审计可在非数采时单独运行（耗时显著大于网页容器检查）：

```bash
PYTHONPATH=src ./.venv/bin/python scripts/check_lerobot_v3.py mocap_data
```

默认是完整审计；不要把 `--startup-only` 启动结构检查当作完整解码结果。

## 用于训练前复核

- 先排除索引、时间、视频文件缺失等结构问题，再逐条确认抓取、搬运、放置和返回是否完成。
- 对高 jerk/误差的时刻用综合图定位视频，区分碰撞、纠错、复位、传感器噪声和正常快速动作。
- 阶段边界未人工确认前不得直接作为可信监督标签；罕见但有效的纠错应保留，不应仅按高尾删除。
- 当前没有光照、手机姿态、盒位置、操作者、失败类型等场景标签，不能评估未采场景覆盖或预测模型成功率。
- 当前日志摘录仅取该条源时间前 3 秒至结束后 30 秒的现存 recorder.log；被覆盖历史不可恢复，可能含下一条的少量日志。

## v1.4.1 单臂独立门控验收

停机部署后、空载且备好急停，先 X+Y 复位，再只按右 Grip 小幅操作，确认左臂无新的运动目标；
换左侧重复，两 Grip 都释放时检查保持。不要用大幅度带载动作作为首测。
软件测试验证未启用侧的输出位置逐元素不变；实际机构仍可能有跟踪收敛、重力形变或反馈噪声。
