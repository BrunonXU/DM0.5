## 运动和保护设计

1. 逐关节验证名称、维度、有限数值、递增源时间戳、源时间差及接收时效，禁止以补零/缓存充当反馈。关节和夹爪超过 300 ms 无更新即拒绝。
2. 必须收到驻车、静止底盘反馈和 STM32 连接/急停状态（兼容 D070 的数组错误码和 D072 的单整数错误码）；缺失、过期、急停、错误码或操作手柄活动均阻断。
3. 核对唯一的本机 `motor_ctl_node` 进程，从其 `/proc/<pid>/cmdline` 指向的实际启动参数读取关节顺序、限位和夹爪类型，并与部署时核对的配置一致；不采用旧 PICO 中与当前固件不符的关节限位，不做静默裁剪。
4. 使用统一五次曲线，起终点速度和加速度为零。双臂速度/加速度/跃度上限 3°/s、2°/s²、4°/s³；头身 1.5°/s、1°/s²、2°/s³；夹爪 5%/s、5%/s²、10%/s³。时长依最大位移自动增加，至少 12 秒。
5. 100 Hz 目标发布、20 Hz 夹爪目标发布；调度延迟不补发突发队列，单次周期超过 150 ms 即中止。普通 Linux/Python 不是硬实时控制器。
6. 全路径按最大关节位移 **0.1°** 间隔检查，长路径审计每批处理反馈回调，防止计算阻塞导致假超时；执行时再次检查实测和目标姿态。MuJoCo 正运动学 + Coal 碰撞网格检查覆盖臂身、双臂、同臂非相邻连杆，另检查静态质心位于轮子支撑多边形内。模型/依赖缺失则拒绝运行。
7. 手臂表面外扩 10 mm、额外净空阈值 5 mm，末端保留 100 mm 延长包络。相邻关节及模型中的固定连接排除；同侧腕部 `Link5/Link7` 原始碰撞网格在现场无碰撞初始姿态及腕俯仰 -50°/-25°/0°/25°/50° 均相交，作为显式装配排除对记录。腕部自身检查使用原始网格，末端延长代理仅用于臂身/异侧碰撞，避免把延长代理误当作同腕部实体。
8. 执行前要求其他关节/夹爪/TCP 控制发布者为零；执行中每 100 ms 复查。电机服务使用该进程自己的 RMW（D070 为 Fast DDS），退出拖动和进入位置模式后再稳定采样，状态变化过大时停止，不直接跳转目标。
9. 关节跟踪误差达到 2°、夹爪达到 5% 或任一健康条件失效时停止发送后续轨迹。无自动重试、清故障、解急停、自动重新使能或断电动作。

**物理边界：** 离散模型检查不是连续碰撞证明，也不包含桌面、物品、人员、持物、所有线缆/软包和动态惯性。末端包络需匹配实际安装工具。腕部装配排除、URDF 与电机映射和净空都应随硬件改装重新审核。不能声称从任意姿态复位必然无碰撞；不满足条件时程序拒绝动作，由现场人员先恢复到可验证姿态。精确关节反馈不能独立证明电机健康，遇到本体故障必须走厂商恢复流程。

## 验证与故障处理

详见 [VALIDATION.md](VALIDATION.md)。离线测试：

```bash
python3 -m unittest discover -s tests -v
```

| 失败信息 | 含义与处理 |
| --- | --- |
| `other command publishers` | 仍有上层控制器占用；退出对应程序，勿绕过 |
| `missing/stale` | 检查 ROS 环境、DDS 网卡、底层节点；程序不会补零 |
| `service timeout` | 电机服务不响应；确认底层节点/网络，不自动重试运动 |
| `current feedback outside ... limits` | 当前位置已超出当前固件限位，先检查标定及本体状态 |
| `Collision` / `CoM` | 当前姿态或中间路径未通过，现场回到安全姿态或重新审核模型 |
| `pose moved when enabling` | 切换模式产生位姿变化，停止并重新核验 |
| `joint tracking error` | 实际关节未跟随目标或发生外力/故障，现场停止检查 |
| `target hash mismatch` | 基准被修改，勿直接重写哈希掩盖问题 |

复位结束后保留位置模式和驻车状态；后续 PICO/模型任务应通过自身启动流程设置所需控制模式，不自动恢复旧模型或拖动状态。

卸载只需停止本项目进程并移走 `/home/user/meaxiao/reset`。本项目不注册开机服务、不修改系统 DDS、不自动恢复其他控制任务。

`profiles.py` 按机器人身份选择并校验基准，`core.py` 负责轨迹和数据约束，`ros_io.py` 负责 ROS 适配，`collision.py` 负责路径几何检查，`reset.py` 负责复位流程。`vendor/f1_safety` 来自本工作区 `F1/PICO/pico/vendor/f1_safety`，随项目保存，包含本项目对同侧末端代理检查的修正；不要求远端安装 PICO 项目。未经核对不要替换 URDF、关节映射或工具包络。

`python3 scripts/compare_reports.py <071成功日志.json> <072成功日志.json>` 仅接受不同设备、相同目标哈希、`RESET_VERIFIED` 且终态达标的日志。输出明确标记只比较原生 ROS 反馈。

070 与 071/072 使用不同目标，脚本拒绝把其原生角度差作为一致性结论。跨结构比较需查看实际连杆角、机身高度和工具位置。历史三机共用 D070 目标的日志保留用于追溯，不再作为当前基准的验证依据。
