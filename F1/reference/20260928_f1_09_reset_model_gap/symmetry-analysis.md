# 左右手高度差：复位 / 积木目标 / 当前反馈（只读计算）

## 可直接下结论的部分

**标准 pose_2 的理想关节目标是对称的，但现用 URDF 会把左侧 Link7 原点画高 24.154 mm。**这不是透视截图判断，也不是符号修正造成：在原始 URDF 上按当前 `configs/model_mapping.json` 计算，与应用 `robot.geometry.frames()` 数值一致。

理想 pose_2 时，左右 Link7 在 `body_Link5` 内分别为：

| 末端 | x / mm | y / mm | z / mm |
|---|---:|---:|---:|
| `arm_L_Link7` | 203.669009 | 217.996271 | 80.577857 |
| `arm_R_Link7` | 220.583654 | −217.999789 | 56.423904 |

此时身体目标 `[0,0,-5,-10,-5]` 的累计旋转使 `body_Link5` 与 `base_link` 方向一致，因此这里的24.154 mm也等于网页Z向上的高度差。两侧 Link7 坐标轴方向仅差0.000930°，接近URDF原始RPY小数舍入量级；不是末端朝向一高一低。

## 几何差异能解释多少

当前URDF的左 `arm_L_joint4.origin.x`、`arm_L_joint5.origin.x` 都是0，右侧对应值都是18 mm。既有独立原生FK和轴线不变量审计已经证明两处18 mm属于模型之间的真实运动学几何差异，不是仅换base/TCP名称可消掉的差异。

本次只在内存副本尝试补齐左侧这两处18 mm：左Link7移动约 `[+16.914467, −0.000072, −24.156363]` mm，左右高度差变成 **−0.002409 mm**，前后差也缩小到约−0.000177 mm。两个18 mm在此姿态的垂直贡献约为 `18 + 18 sin(20°) = 24.156 mm`，完全解释了原图中模型左高约24 mm的量级和方向。

两侧同时把311 mm改成314 mm，在标准pose_2下仅使两侧末端各向前约3 mm，左右高度差仍为24.153932 mm。因此纵向3 mm差异不是此复位姿态左右不同高的主要原因。

当前显示的三个符号修正是左J7、右J5/J6；这些目标在pose_2中都是0°。而且URDF中J5/J6/J7原点重合，所以这些符号在任何姿态都不会改变Link7原点位置，只影响末端方向及偏移工具点。不能用撤销这三个已核验符号来“调平”高度。

## 原生TCP的坐标合同与方向证据

沿用已用16组原生纯FK响应交叉验证的MDH：`Rx(alpha) Tx(a) Rz(theta+q) Tz(d)`，第8行固定角并包含95 mm末端偏移。标准pose_2在各自原生臂base内的TCP分别为：

- 左 `[327.754686, +293.848145, 174.5]` mm；右 `[327.754686, −293.848145, 174.5]` mm。
- 左原生base的Y对应躯干−Z，右原生base的Y对应躯干+Z，所以在同高度肩安装假设下两侧TCP高度一致。直接比较这两份原生数据的第三项作为世界高度是错误的。
- 共同躯干的名义变换使用已审角度方向：左 `B=[[1,0,0],[0,0,1],[0,-1,0]]`，右 `B=[[1,0,0],[0,0,-1],[0,1,0]]`；平移分别为 `[-9.1722,±43.5,350.27]` mm，来自URDF肩坐标和DH首段174.5 mm。这与此前模型对齐拟合一致，但不是厂家实物安装标定。
- 标准pose_2在该共同躯干frame中的TCP均为 `[318.582486, ±218, 56.421855]` mm，方向也一致；Link7与TCP相差工具偏移，不能混称为夹爪接触点。

## 能修模型，但不要伪造实机标定

这次计算足够证明当前网页复位时左高约24 mm来自所用URDF不对称的几何定义。可以据此准备清楚标注的模型几何修正候选，并以已有多姿态FK重验；是否把这些名义尺寸作为实物模型仍需确认F1-09两臂适用型号与厂家几何。

如果用户在真实标准复位时肉眼看到左手略高，不能把上面的24 mm直接当成实物误差：没有该时刻完整精确HAL快照和左右同一实体测量点的外部测量。当前demo的HAL不可回填为此前复位反馈，左右工具安装/肩安装/机械零偏也未独立验收。不应为了画面齐平去改真机目标或塞入经验角度补偿。
