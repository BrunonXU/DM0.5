# F1动作接口映射：19D目标如何对应机器人

本文只维护本任务的字段到执行接口的映射及证据，原始接口说明见[F1系统接口清单](../../F1系统接口清单.md)和[底盘接口文档](../../通用机器人软件接口文档.md)。数据布局与处理参数见[F1处理管线](data_cleaning/f1_data_pipeline.md)，实际执行步骤见[replay操作](replay_runbook.md)，当前缺项见[当前方案](training_plan.md)。

## 字段与控制链路


| 部分 | 文档支持的执行/反馈合同 | 仍须核对 |
|---|---|---|
| 双臂14D | `/motion_ctl/joint_ctl`，`sensor_msgs/msg/JointState`；每侧传完整7关节；候选普通遥操作源码的`/lead`与UDP共用硬件度数缓存，左7右7原值送桥 | 采集版本、异步发送时差、有效限位和HAL对应仍待核实；不能把`/lead`当实际执行ACK |
| 双夹爪2D | `/motion_ctl/gripper/left`、`right`；`GripperCommand.position`：0全开、100闭合；反馈同尺度 | 0–100不是已标定的开口毫米；`max_effort`与保持方式取当前验证过的配置，不能随便套示例10 |
| 底盘3D | `/move/ManualMoveCmd`，`TwistStamped`；`twist.linear.x/y`单位m/s，`twist.angular.z`单位rad/s；示例frame为`base_link` | 车体轴正方向、允许频率/速度/加速度、超时与停车行为、当前部署版本 |
| 身体反馈5D | `body_j1..5`是躯干电机通道，UDP电机ID为3..7，角目标单位度；j3..5参与站立 | 各轴的物理含义、机构耦合和姿态保持方式仍缺完整映射；不是底盘3＋腰2 |
| 三路相机 | 压缩topic与现有数据吻合，相机独立节点 | 相机实际型号/驱动版本、header时钟来源、曝光到消息的延迟 |

本文的 **state21 / 关节目标19D** 是当前清洗与关节回放来源合同。
2026-09-16正式训练输入修订为 **19D状态（双臂14＋夹爪2＋当前底盘速度3）→ 23D EEF相对动作（模型补齐32D）**，编解码、FK/IK验收及来源见
[单版训练recipe](training/dm05_eef_delta_recipe.md)。原数据包布局保留；已有任务侧reader和FK派生缓存，完整训练配置及策略执行适配仍在迁移。
body5留在来源包和部署姿态检查，不进入模型输入；身体与头部保持相容姿态，不加入动作头。
训练状态的底盘3维取已复核重建轨迹在当前观测时刻的速度，未来时刻用于动作监督；推理状态从
`/move/State.speed.linear.x、speed.linear.y、speed.angular.z`读取，顺序为vx/vy/wz，单位m/s、m/s、rad/s。
重建估计与在线反馈使用一致坐标、尺度和状态归一化，分别保留来源属性；输出仍下发速度命令接口。
本轮由同一个策略输出双臂、夹爪、底盘速度，不改成导航接管。
2026-09-16[运动学数值验证](../results/kinematics_validation_20260916/README.md)已确认原生FK可用于EEF转换，
但原生连续IK有实际限位与冗余姿态分支问题；服务`success=true`不能单独作为可下发条件。
任务已实现[受限连续IK数学适配](../results/continuous_ik_20260916/README.md)，以控制器矩形范围＋SDK的J6/J7耦合条件求解并复算末端误差；SDK原矩形范围与控制器的差异保留在报告中。固定观测锚点还原action23，当前反馈/上一接受解选择冗余姿态，失败不返回可执行关节轨迹。离线数学验收与F1运行、首步过渡、速度/加速度及碰撞验收分别进行，不能直接将数学`success=true`作为全身下发条件。
候选主从链路的代码证据见[依赖核对](../../reference/20260914_action_mapping_followup/README.md)；
Placo变号和动态偏置发生在硬件目标生成上游，不能对已录`/lead`再应用一次。
该代码允许录制中复位绕过普通`/lead`，复位/缺口须结合反馈和图像复核，不能跨缺口补目标。

底盘 `/move/State` 是反馈接口，文档写200 Hz，不能把这个频率当作指令频率。
`ManualMoveCmd`示例用0.05秒定时器，即20 Hz示例；这也不是已确认的控制频率限制。
30 Hz是当前数据整理频率，真正下发频率要对照部署控制器，保持动作时间轴可追溯。

文档的软控制模式服务 `/move/SetControlMode` 请求值为0自动、1手动；这与反馈bool `is_soft_auto` 的含义不同。
`ManualMoveCmd` 属软手动接口。准备实际执行时需核对软/硬模式、驻车状态和控制权，不能直接按“模型自动运行”就把服务设成自动。
这些是执行接口设置，不是按任务阶段切换导航的策略。

**修正此前的字段判读：** 底盘文档在 `/move/State` 明确约定 `odometry.orientation.w` 直接存yaw弧度。
本批 `(0,0,0,0)` 在这一约定下表示yaw=0，并非仅因四元数范数为0就构成坏数据。
读取时用明确的yaw标量；只有导出到要求标准四元数的工具时才按目标格式转换。
这项协议解释不改变“当前底盘数据为后补弱标签”的来源属性，也不能修复实际错标。

文档包含不同阶段的示例：旧限位报错、0608版限位钳位和不同IK限位表并存；身体旧ROS控制入口已标弃用。
不能从某一段例子推导当前机器行为，尤其不能用旧限位把原始数据整体裁平。

2026-09-16回放更新：用户已明确采用关节上下限截断，与系统接口0608章节的逐关节钳位语义一致。
当前运行控制器的固定限位已经按二进制SHA核对；只在回放下发映射中截断14个臂目标，原始lead/HAL不改写，
其他关节和夹爪、底盘字段不受该映射影响。源目标与实际下发值都记录，依据见
[运行配置修复记录](../results/replay_runtime_fix_20260915/README.md)。

文档证据位置：双臂全7维要求见F1清单73行，控制topic在81行，FK单位在1109行；
夹爪方向在694/710/781/800行；body电机映射在1224–1231行；0608限位在1529–1541行。
底盘文档的`move/State`反馈频率/速度/yaw约定在3116–3149行，模式请求在3241行，
`ManualMoveCmd`类型与示例在3439–3474行。这些是文档证据，不代表已经读取当前F1运行版本。

### 新增全量范围核对

本次用0608文档表对照801个信号包，报告与每字段极值见
[文档范围审计](../results/interface_review_20260914/documented_range_audit.md)。只读比较，没有改变第一版数值或mask。

- 双臂HAL反馈979,690个样本均在该文档范围内；四路夹爪命令/反馈都在0–100内，右夹爪恒100，即文档所说的闭合。
- `/lead`左J4在230份录制中严格低于−145，最大差仅0.000872；它是很小的边界差异，不能机械地删掉230条。
- `/lead`左J6在5份录制、643个目标点高于60，最高68.746571。按`/lead`原值为度的假设，它高出文档上限8.746571°。
  这5份是`all_data_3_derived/episode_000111、000113、000134、000178`和`all_data_derived/episode_000045`。
  在确认主从转换与实际控制器版本前，不能把这些目标解释为已经验证可直接执行的角度。

这些结果说明“数值不缺失、时间也对齐”仍不够：还须明确模型学的是主端目标还是经限位等处理后的执行目标。
不能仅依据HAL没达到某个目标就认定限幅，因为控制延迟、插值和标定也会造成差异。

## 离线命令映射核验

双臂将 `arm_L_joint1..7/arm_R_joint1..7` 映射到 `arm_l_j1..7/arm_r_j1..7`，
并核对主从是否还有数值变换。底盘从动作后三列构造 `TwistStamped.twist`，而不是发布 `/move/State`。
命令时间戳在执行时重新生成，源时间只用于调度和日志；调度不压缩掉等待，不在延迟后突发补发旧命令。

不能只用topic remap直接播 `/lead`：topic改名不会改JointState内部关节名字，也不会验证数值映射。
接口文档末尾的TCP位姿topic remap示例属于另一个接口，不能直接套到本批关节＋底盘数据。
先输出待发送命令日志核验，再接实际控制器。

1. `/lead`发布及主从映射到`/motion_ctl/joint_ctl`的代码、校准和参数。
2. `motor_ctl.launch.xml`、当前控制节点版本、相关`f1_msgs`/`move`消息定义与命令频率/超时约定。

4. 三路相机launch和时间戳生成逻辑；底盘坐标约定与当前DDS配置。

接口文档已足够推进离线整理；这些资料用于消除执行与曝光时钟的不确定性。

资料按实际涉及的字段核对；已取得的参考快照及版本状态以当前方案为准，不按此清单重复收集。
