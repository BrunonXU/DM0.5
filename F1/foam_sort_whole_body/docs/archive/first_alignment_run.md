## 时间轴和有效性处理

1. 以 MCAP log 时间建立 30 Hz 网格。每个时间点选择此前最近的反馈/命令，以及此前最近的相机时间戳候选帧，不取未来消息。
2. 数值样本和当前相机帧距离网格时刻最多 100 ms，超过则标记无效。这是本版数据新鲜度筛选参数，不是机器人限速或滤波。
3. 相机 header 合法且递增，且相对本流稳态 header−log 中位数偏离不超过 250 ms，才可作为时间戳候选。
   稳态从录制开始 5 秒后估计。三路原始时间均保留，没有因左腕约 1.317 秒的时钟偏移就直接平移图像内容。
4. 50 步动作片段约覆盖 1.67 秒。整段数值观测和动作必须有效，图像只要求片段起点的三路当前观测有效；未来图像不是该动作片段的模型输入。
5. 不跨数值断档构造动作片段，末尾不足 50 步不以重复末动作补成监督。以后加入人工干预/循环边界后，还要在相应边界重新生成片段 mask。
6. 已确认错配的底盘标签保留数值供审计，其 action 的第 16:19 列有效性置 false；在要求完整 19D 动作有效的候选中排除，待重标后再纳入。

`state_valid`、`action_candidate_valid` 是逐维标记；`observation_candidate_valid` 要求当前 state 和三路图像均有效。
`joint_frame_candidate_valid` 还要求当前 action 全部有效。
`future_signal_action_candidate_valid` 不包含未来图像条件；`chunk_start_candidate_valid` 综合 50 步数值条件和当前图像条件。
`training_approved=false` 表示尚未经过任务内容和标签质量验收，不是新增用户权限确认流程。

log 时间是记录接收时间。本次完成了时间索引和异常筛选，尚未证明三路曝光时间与控制命令严格同步。
后续训练 loader 必须使用这些索引/mask，不能把原始 MCAP 顺序或全部有限数值直接当作有效训练样本。

## 全量发现

数值提取覆盖全部 801 份录制，信号数量与既有独立 MCAP 消息索引一致，源文件指纹未变化。
相机索引覆盖全部 2,908,206 帧：

| 相机 | 原始帧数 | 时间戳候选中排除的帧数 |
|---|---:|---:|
| 头部 | 968,706 | 21,967 |
| 左腕 | 969,831 | 626 |
| 右腕 | 969,669 | 624 |

头相机记录到 21,772 次相邻 header 时间重复，39 次时间倒退（分布在 38 份录制）；
2591 次 log 间隔超过 100 ms，分布在 777 份录制。重复时间戳不等于已经证明图像像素重复。
三路共 2403 个流都存在连续可用时间戳候选区间；没有因为出现一帧异常就整条删除。

多次夹爪数值变化的启发式筛出 8 份录制待核对。
该规则仅找相隔至少 8 秒的低值区段，开头 3 秒内的区段不计入；它会把初始化、重试和多循环混在候选中，不能据此宣称有 8 条多循环。
对这 8 条实际查看图像后的结论和证据见[本轮循环复核](../../results/cleaning_v1/cycle_review/findings.md)：

- `all_data_2_derived/episode_000055` 包含两轮运输及人工补料，原一组出发/返回标签跨错阶段；沿用已有屏蔽。
- **新确认 `all_data_derived/episode_000079` 的 162.98 秒录像有两轮。** 约 87–94 秒人工补料，原标签漏掉第一轮返程和第二轮去程。
  48–61 秒、108–124 秒共 879 个底盘样本的 vx/vy/wz 全为 0，但画面在移动；已将整条底盘监督暂屏蔽，等待逐循环重标。
- 另外 6 条稀疏画面只观察到一次搬运，早期夹爪事件在首次抓取附近；没有据此强行拆分。
  其中 `all_data_derived/episode_000012` 在 51.5 秒有人前臂靠近右夹爪，是否实际介入被遮挡，保留精查项，不直接判失败。

本轮只复核了上述 8 条，规则对其余 793 条的漏检率未知，不能声称全量只有两条多循环。
单纯将两条错标长录像切成两份不会修复底盘速度，必须同时核对标签。

现有元数据审计还提示 61 份录制使用 fallback 移动窗口、81 份估计速度峰值超过 2 m/s 的复核阈值，二者可能重叠。
本次保留这些原因供后续看图核对，不把估计峰值视为 F1 实测速度，不自动限幅，也不自动证明其标签正确。

## 分组与训练前剩余工作

已按每批原录制的时间顺序，固定后 10% 作验证：720 份训练来源、81 份验证来源。
这不是最终可训练循环数。同一原录像后续切成两段、三段，仍归同一分组，避免相邻片段进入两侧。
归一化尚未计算；应在最终筛选后仅用训练部分统计，右夹爪和 wz 等常量维使用非零尺度。

接下来需完成：

1. 根据实际画面标注循环、人工补料/复位和失败重试，优先处理多事件候选及已知底盘错配。
2. 对照最终视频核对移动阶段、方向与底盘标签；修复错误标签后重新生成 mask。单条较长本身不是删除理由，不按 30 秒机械切分。
3. 核对 F1 字段/单位和相机时间来源，完成图像与动作的对时抽查。可以从 F1 项目代码和消息定义隔离查看，不需要启动机器人动作。
4. 导出训练器可读的图像与样本，接入 DM0.5 的 21D/19D 编码、归一化和片段 mask；做样本回放和小集过拟合验证后再正式训练。

## 验证

数值提取和相机索引各自的全量验证均通过。独立验证器不导入组装脚本，对全部 801 份对齐包进行检查，最终 **0 错误**：

- 所有 state21/action19 值逐帧、逐列对照提取的数值流，字段布局一致；源文件指纹未变化。
- 网格、数组类型、有效性标记、相机原始索引、因果选择和年龄一致。
- 50 步片段不跨无效数值窗口、不越过末尾；两条已知错误底盘监督均被屏蔽。
- 逐条 JSON、CSV、全量清单、原录制分组和 summary 统计一致；所有训练质量验收标记仍为 false。
- 3 项针对因果采样、反馈断档/末尾动作片段、夹爪局部变化的回归测试通过。

验证入口为 [validate_cleaning_dataset.py](../../scripts/validate_cleaning_dataset.py)，机器结果见
[validation.json](../../results/cleaning_v1/validation.json)。这是数据结构与对齐验证，不是全部图像像素、任务成功率或真机验证。

## 复现和后台运行

在 **6000D 终端**执行；工作目录为本任务目录，输出保存在 `results/cleaning_v1/`。
依赖版本见 [requirements-audit.txt](../../requirements-audit.txt)，当前解释器 `/tmp/f1-foam-audit-venv/bin/python` 是临时环境，跨重启需重新确认存在。

```bash
cd /home/xza_100850113/projects/F1/foam_sort_whole_body
./scripts/run_cleaning_v1.sh all
```

`all` 会先检查/补齐信号与相机索引再重建对齐产物；完整且指纹匹配的提取结果可复用。
仅调整对齐规则或有证据的标签屏蔽后，使用 `./scripts/run_cleaning_v1.sh assemble`，不必重新解码原始数据。
全链路通过文件锁防止重复运行；逐条 NPZ 和完成标记原子替换。
`all` 和 `assemble` 结束后均运行独立验证器；只复查已有结果用 `./scripts/run_cleaning_v1.sh validate`。

本次对齐已由独立于对话的用户 systemd 服务完成，退出码 0。源定义见
[f1-foam-cleaning-v1.service](../../scripts/f1-foam-cleaning-v1.service)。已有中间提取结果时可后台重建：

```bash
systemctl --user start --no-block f1-foam-cleaning-v1.service
journalctl --user -u f1-foam-cleaning-v1.service -n 60 --no-pager
```

服务是一次性任务，成功结束后显示 inactive 属正常状态；FTP 同步服务保持停止。
本轮未启动模型训练或 F1 真机执行。
