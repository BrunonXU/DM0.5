# F1 训练前补充：身体映射、多循环与右侧禁用

这份补充保留body5映射、多循环错标的证据，以及此前右侧禁用的讨论。
用户后续已明确恢复双臂与双夹爪，右侧禁用候选已撤销；当前选择统一见 [训练方案](../training_plan.md)。
训练仍未启动，原始数据未修改。

## 身体反馈不是已确认的“底盘3＋腰2”

最终 `/hal/joint_states` 有 `body_j1..5` 五个独立反馈字段；`/move/State` 另有后补底盘位姿与速度。
五个body字段在全批几乎恒定，没有表达后补路线中的0.5m/1.6m位移。不能据字段名拆成底盘3维加升降/俯仰2维。

前文把body5简称为腰部5D不够准确。F1实际升降、俯仰与这些字段如何对应，要看发布源码、URDF或映射配置。
机械自由度、任务空间目标和反馈数组长度未必一一对应；这里不从类似G2的构造推出F1映射。
21D输入/19D输出仍是此前双臂候选设计，不是已经验证的F1控制合同。

## 已确认一个多循环底盘标签问题

`all_data_2_derived/episode_000055` 长80.65秒，画面中有两轮搬运/放置/返回，中间人工补料。
原JSON仅有一组outbound=24.558–33.166秒、return=54.828–62.134秒，分别落在第一轮返程、第二轮去程。
这属于循环/阶段错配，不能仅用“后补标签有一点噪声”概括，也不能只裁成两份就继续使用这些标签。

证据及粗略时间见 [有界核查](../../results/20260914/cycle_review/findings.md)。目前只检查三个视频，
另外66.21秒、53.46秒两条只见单轮；不按视频时长判断循环数量，也没有推断全801条的多循环比例。
原801条是录制文件数量，独立任务循环数须另统计。
此项已加入 [人工复核覆盖项](../../configs/review_overrides.yaml)，复核脚本会保留该证据。

## 长短录像如何转换

DM0.5当前 `BuildActionChunk` 根据当前帧取固定长度的未来动作，不要求每条原始录像等长，
也不是把完整一分钟视频当作一次模型输入。因此长短本身不造成错误监督。

本任务建议以完整任务循环为派生episode。保留原MCAP，以source_episode、cycle_id、start/end时间、
成功状态、人工介入、标签版本记录切片；先用夹爪变化和场景变化找候选，再人工复核切点。
不按30秒等分，不变速凑长度，三路图像和所有状态/动作一起按时间裁剪。

需要注意：

- 多循环样本先重建每轮对应的底盘标签，再导出；裁片不能修复原动作标签错配。
- 人工补料、复位、无效长等待和失败重试分开标注，不能默认为自主成功示教。
- 同一原MCAP的子片段属于同一训练/验证分组，防止数据泄漏。
- 按帧均匀抽样时，长记录贡献更多样本；按episode均匀抽样时权重又不同。明确抽样单位，检查各阶段覆盖，避免等待段占比过大。
- 旧 `BuildActionChunk` 尾部重复最后动作且mask全true。若切在非零底盘速度处，会制造继续移动的尾部目标。
  转换时保留真实有效的停止/返回段，对超出片段的未来目标使用正确mask或不采该窗口，不直接沿用该填充行为。
- 已知2.6秒反馈空洞仍需单独隔离；切点也不得让chunk跨越人工重置与无效反馈窗口。

## 右手禁用如何影响维度与数据（已撤销的候选讨论）

以下保留当时分析：曾讨论整右侧保持固定，但用户现已选择双臂19D输出，不再等待禁用范围澄清。
该候选从未修改或运行任何机器人控制参数。

若整右侧固定，有效可学习动作是 **左臂7＋左夹爪1＋底盘3＝11D**。
也可保留19D外部接口并明确固定其中右侧8D，但需与“网络实际学习11D”区分；不训练右侧再仅靠现场截断掩盖不匹配。
若仅右夹爪固定，右臂仍参与，则是不同设计，不能混用。
输入维数不随输出自动相等，身体和右臂是否保留作观测，要在确认反馈语义和部署固定姿态后决定。

当前右夹爪全批恒100，但右臂不是固定的：既有审计中800/801条有明显右臂关节变化（原始单位粗筛）。
筛选时要看右臂是否参与整理/辅助，或其运动是否改变左臂可达性与画面。可以保留符合左手独立任务的区间；
不能直接把运动中的右臂动作改成常量，再声称这是原样示教，也不能据整条有右臂运动就全部删除。

## F1需要提供的最小资料与访问方式

首要资料是机器人字段与控制接口，而非再复制一份639GB数据：

1. `/hal/joint_states`发布代码、joint name/index映射及F1 URDF/身体关节说明。
2. 手臂、夹爪、底盘命令和反馈类型，单位、坐标系、更新频率、位置/增量/速度语义。
3. 保持身体姿态的现有接口及采集时姿态配置；双臂与双夹爪的执行接口。
4. 相机驱动、header时间来源；采集时和当前部署代码commit与最小配置。

建议把版本固定的源码与必要配置快照复制到6000D的F1共享参考目录，在6000D独立环境分析和转换训练。
同时保留SSH用于只读核对当前配置与消息样本，不需要把训练环境安装到F1。
代码复制与SSH访问相互补充；SSH用于连通，运行环境仍然各自隔离。

若由6000D发起SSH，密钥对应在6000D生成，私钥保留在那里，将公钥加入F1授权账户。
密钥不解决网络路由问题，连机后还需确认6000D能够访问F1的SSH端口。
先提供IP、端口、用户名与项目路径，再做对应的只读检查；本轮没有连接F1或生成密钥。
[OpenSSH密钥说明](https://man.openbsd.org/ssh-keygen)

## 到训练前的推进顺序

1. 核对F1字段映射、身体保持姿态与双臂/夹爪/底盘接口，落实当前21D输入/19D输出合同。
2. 对801份原记录建立循环候选和人工介入标记，核对独立循环数量及右侧参与情况。
3. 按循环修正底盘阶段错配，同时解决相机时钟、启动帧和反馈空洞。
4. 导出版本化训练样本、有效窗口/损失mask，保持原来源与全部修正依据。
5. 按原记录分组划分数据；仅用训练部分统计归一化，检查静止/移动及抓放样本占比。
6. 完成DM0.5数据与动作头适配，验证样本shape、动作回放对齐、尾部mask和分组损失；准备独立训练环境及配置。

到第6步才具备开始小集训练的条件。本轮没有启动模型训练或真机执行。
