# 清洗决策记录：问题、依据、处理与验证

用户目标是修复到可作为端到端 VLA 数据集来源，或推进到确实需要人工补充证据的位置。每解决一类问题，在这里记录所依据的事实、变更和独立验收；当前发布版本、数量与待办统一见[训练方案](../training_plan.md)。

判断一项处理是否必要，先问：**它是否使“当前观测 → 随后目标动作”更可信？** 不以文件可读、模板自洽或排除了若干条目代替真实性判断。缺失的事实不能通过填零、固定时间比例或重复旧目标变成已知事实；采用先验时明确其来源和适用边界。

## 已遇到的坑：证据、处理与边界

### 2026-09-17：来源数量与reader通过不能替代动作覆盖

全量读回已证明当前740条包的数值、图像索引、来源与统计绑定自洽，但连续全维H50准入会把底盘unknown附近原本有效的双臂转换一起排除。应以原父mask中有效的转换为分母，同时报告筛选前后事件保留率；不能因为保留了变姿前后的持位片段，就宣称保留了变姿动作。全池归因及两项最小修复试验见[转换缺口记录](../../results/transition_retention_20260917_v1/README.md)。

搜索窗口是寻找候选运动组的范围，紧邻窗口外的真实前后状态仍可作为边界证据。已增加显式上下文选项，但边界最大包络、方向冲突拒绝与像素阈值稳定性不变；默认保留旧行为。修复须分别验证是否恢复窗口、是否恢复所需动作，新增窗口数量不能代替后者。这次试验没有更改loss，也未用零值填充没有证据的区间。

### 2026-09-17：训练来源资格、局部监督和完整replay资格分别判断

要求一条来源的全部运动边界稳定、全部抓放变化都被H50覆盖，曾把单个阶段未知放大为整条来源淘汰。模型可以学习有证据的局部片段，完整replay则要求连续且可执行的整段；两种资格不能使用同一个整条门。原因及历史清单见[全量目标纠偏](../../results/full_pool_scope_correction_20260917/README.md)。

修正为逐阶段生成、逐区间隔离：未定边界不取消其他可靠阶段，运动/静止反证只隔离冲突区间，未知保持NaN，原双臂/夹爪、时间、相机索引和复位mask保留。每次仍重新展开实际H50，独立验证来源一致、父mask不放宽、未知不跨界、选中夹爪变化与非零底盘标签不冲突；方法和证据见[局部阶段修复](../../results/partial_phase_pool_20260917_v1/README.md)。已有对照包按身份与SHA原样优先，不能在扩池时静默替换经过回放的基线，见[reader准备](../../results/full_pool_reader_20260917_v1/README.md)。

保留大量来源也不等于保留了关键动作。右臂实际监督的全局跨度较大，但连续H50内明显变姿主要仍出现在少数旧对照；变姿前后两个持位片段之间可能有被mask隔开的过渡。统计时应同时检查“来源内监督并集的跨度”“连续窗口内变化”和事件覆盖，不能由前者推断模型已经看过转换过程。见[右臂活动证据](../../results/right_arm_supervision_discussion_20260917/README.md)。对有效但缺口隔离的过渡继续局部恢复，对缺失目标的复位继续隔离；不能用运动阈值自动免除保持动作loss，也不因发现局部覆盖问题重新整条删除。

本轮不修改训练loss。当前冻结状态、实际规模与剩余工作只见[训练方案](../training_plan.md)，上述独立结构检查不替代全量reader、原图读回和数据发布验收。

### 2026-09-17：关键事件覆盖、执行可行性与输入范围分别验收

短unknown洞可能切掉整段放料监督。仅对相邻静止证据包围的短洞，另取较长基线原图做多区域位移和相关性检查；运动、缺图、身体/相机姿态变化的洞不补。最终用reader实际H50覆盖检查完整开闭爪命令事件，而非只检查事件帧valid。没有足够证据的来源不纳入本版，不能把unknown默认填零。

底盘标签积分自洽，不代表控制器能在原时长内完成。此次保留相机和双臂时间，按已核定加速度缩小超限底盘段幅值；明确牺牲距离而不是偷换时间轴，且保留弱标签属性。离线变化率检查仍不能替代现场抓放时实际停车检查。

新训练来源重算q01/q99后，真实train关节姿态曾被截断达45.91°。用户确认改用有效train关节min/max，保留底盘输入及动作统计规则；validation不参与拟合，其超范围误差独立报告。除有限值和归一化往返外，还应分别报告train/validation的范围裁剪角度与量化档宽，不能仅以token合法认定状态信息保留。

复现脚本、冻结来源、全原图读回及限制见[首版收口证据](../../results/demo_training_release_20260917_v1/README.md)，当前推进状态仍只维护在[训练方案](../training_plan.md)。

### 2026-09-17：mask没有改坏原值，也可能删掉模型要学的关键动作

独立展开密集重标草案的全部H50起点后发现：3份train草案的放料夹爪变化均未被训练窗口覆盖；仅validation来源有覆盖。某些放料帧自身有效，但两侧unknown使50帧窗口无法成立。生成器此前检查了移动边界、明确静止反证和逐窗有效性，却没有检查关键任务事件是否仍出现在实际训练样本中；“窗口数多”和“包含静止/移动转换”都不足以证明会学到放料。

这是派生样本覆盖问题，不能据此说原始双臂已经损坏，也不能扩大为全部来源都缺失。证据及可复算脚本见[本轮4份草案复核](../../results/arm_guided_dense_20260917_v3/README.md#后续独立复核转换窗口数量不能代替放料覆盖)。

收尾采用实际reader窗口检查抓取、停稳放料及保留返程的覆盖和冲突；无法确认的来源/区间不纳入首版，不放宽mask伪造停车。精确路程与逐条实机replay不再阻塞demo冻结。正式导出、最终train-only统计和split绑定属于交付收尾，当前决定集中在[训练方案](../training_plan.md)。

## 阶段顺序

按输入证据 → 字段和时间 → 动作语义修复 → 训练读取与独立验收推进。各阶段可以回查上游；重标后必须重新检查有效性与未来动作窗口，不能沿用旧包的通过结论。原始文件和历史派生包保留，实际变更落在明确的新版本。

每条记录使用下面的结构。只有实际产物与独立验证结果已经存在，才写“完成”；只产生候选则写“候选已生成”，依赖人工事实时写清具体缺少什么。自动化代码通过不能将未知动作升级为有效监督。

```text

1. 所需监督事实
   模型在何时看到什么，应当学习哪种目标；本类问题破坏了哪一项关系。

2. 已知证据
   原始消息或图像、字段与时间基准、来源身份、覆盖范围；区分直接观察与推断。

   采用的方法、修改范围、新产物路径、输入/配置/算法身份及保留的原始基线。

6. 下一步
   本类问题是否关闭；剩余哪项事实或验证阻止进入下一阶段。
```

## 2026-09-15 / 阶段1 / 显式重标规则与版本身份 / base_relabel_v1

**所需监督事实。** 对每个时刻，需要知道希望底盘执行的速度。原始底盘命令丢失后，时间戳本身不能恢复命令；同样的图像位移也可能对应不同距离、深度或相机运动。因此先区分真实记录、视觉证据和路线先验，不能用一个模板把缺失事实全部填满。

**已知证据与不可辨识项。** 原脚本按两个窗口固定切六段，并通过fallback猜时间；缓存还可能错误复用旧输出。证据见[源码审查](../../results/base_script_audit_20260915/report.md)。实际时段、真实路程和控制器响应不能由“模板积分正确”证明。0.5m/1.6m仍只是当前路线先验，未提升为实测。

**处理。** 新增[base_relabel.py](../../scripts/base_relabel.py)：直接接收任意数量的显式移动/静止段，不调用原48/52%窗口判断、fallback或六段比例。支持多轮和同时两轴移动；使用明确位移及真实审核时长计算smoothstep速度。未知间隙为NaN且无候选有效性，不填零；静止必须显式记录证据。段使用`[start,end)`，非法或短到纳秒后倒序的窗口拒绝，不拉长。输入、脚本、参数和产物SHA一致才可复用；变更须使用新版本，原始数据不覆盖。

**独立验收。** [31项测试记录](../../results/base_relabel_v1/import_validation/tests.json)中21项验证引擎，覆盖积分、短窗、多轮、显式静止、未知间隙、边界、输入/算法/参数变更、产物损坏和失败重试。它证明构造及缓存规则正确，不证明某段物理动作真实。每段报告解析峰值与加速度；不通过自动限幅掩盖坏时长。

**下一步。** 确定性构造和错误缓存复用这类工程问题已处理；真实阶段仍须提供证据，不能因为工具通过就恢复训练监督。
