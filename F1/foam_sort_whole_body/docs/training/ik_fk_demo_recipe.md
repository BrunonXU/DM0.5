## 3. 数据与动作合同

模型沿用[DM0.5单版训练recipe](dm05_eef_delta_recipe.md)：state19＝双臂14＋夹爪2＋当前底盘速度3，物理动作23维补齐到模型32维，body5留在来源和姿态检查。

| 物理action23切片 | 含义 |
|---|---|
| `0:3`、`3:9` | 左臂相对位置xyz＋旋转矩阵前两行6D |
| `9:12`、`12:18` | 右臂相对位置xyz＋旋转矩阵前两行6D |
| `18:20` | 两夹爪绝对目标，沿用源0–100尺度 |
| `20:23` | 底盘vx、vy、wz，单位m/s、m/s、rad/s |

源state21/action19继续保留。双臂目标先沿既有执行映射得到`q_command_mapped`，再生成EEF标签；原关节目标与映射值均保留。输入关节角和输出IK关节角使用**度**，数学接口4×4位姿的平移使用**m**；原生SDK的mm只在原生接口边界换单位。

每臂独立使用原生FK参考系和配置定义的默认端点。记观测锚点为`T_anchor = FK(q_feedback[t])`，则：

```text
训练目标：Delta[k] = inverse(T_anchor) @ FK(q_command_mapped[t+k])
推理还原：T_target[k] = T_anchor @ decode(Delta[k])
k = 0..49；整个chunk使用同一个观测锚点。
```

rotation6D按前两行做Gram–Schmidt恢复旋转；全零或近共线输入拒绝。模型32维输出先反归一化并取物理23维，再交给数学接口。不是将每一步delta接在上一预测位姿上积分。

## 4. FK与IK算法、固定参数

**FK：** 从已核实F1配置读取改进DH参数，包含第8行固定末端变换；与原生SDK的数值一致性已有独立对照。

**IK：** 受限SLSQP求解。常规路径在末端等式与关节约束下，局部最小化与参考关节的平方距离。优化器失败，或J4距离矩形边界≤`1e-8 rad`时，使用受同样限位约束的位姿残差求解；后备路径从参考起点重新开始，避免继承失败迭代点的姿态偏移。

| 参数 | v1取值 |
|---|---:|
| 位置数值验收容差 | 0.01 mm |
| 旋转数值验收容差 | 0.001° |
| 常规最大迭代 / `ftol` | 80 / `1e-11` |
| 后备最大迭代 / `ftol` | 150 / `1e-20` |
| 后备参考正则系数 | `1e-10` |
| 关节约束复核容差 | `1e-9 rad` |
| 初始求解参考 | 当前反馈；新请求可使用较新的反馈，但不改变该请求的EEF观测锚点 |
| 后续求解参考 | 本chunk上一接受解 |
| 数据频率 / 预测长度 / 初始执行长度 | 30Hz / H50 / 前20步 |

每臂矩形限位（度）：

```text
lower = [-178, -94, -178, -145, -178, -60, -90]
upper = [ 178, 120,  178,   60,  178,  60,  90]
腕部额外约束：1.025*abs(J6) + abs(J7) <= 110.5
```

矩形范围来自已核对的控制器执行映射，腕部耦合来自SDK配置。它们与原生SDK矩形范围的差异见[算法报告](../../results/continuous_ik_20260916/README.md)。输出不通过事后clip伪装成满足EEF目标的解。

确定性含义为：相同目标、参考、配置与数值环境得到可复现的局部解。7关节存在冗余，EEF本身不唯一指定原示教7个角度；不保证全局最近解或跨平台逐bit一致。

## 5. 已实现接口与demo接线合同

- `ArmModel.fk(arm, joints_deg)`：关节7维→4×4末端位姿，`arm=0/1`为左/右。
- `ContinuousIK.solve(arm, target_m, reference_deg)`：单臂求解；独立复算位姿误差与限位。失败时`joints=None`，诊断候选不能当作命令发送。
- `solve_eef_prefix(actions23, anchor_joints14, reference_joints14, execute_steps=20)`：固定锚点恢复并求解两臂前缀；任一步失败，整个请求前缀不返回关节轨迹。

上述函数均为纯数学接口，不调用ROS或控制机器人。**目前没有自动下发、自动停车或重观测闭环。** 下一步客户端接线时，应先完成双臂前缀转换，再统一处理该chunk的手臂、夹爪和底盘；转换失败的chunk不得只发送其中底盘/夹爪部分，已执行命令的有效期与停止处理按现有控制合同接入。记录EEF目标、反馈参考、IK状态、关节变化、耗时与端到端结果，便于区分policy和执行转换的影响。

保留已有误差、限位、退化旋转与失败拒绝；不加入尚未验证的固定肘角偏置、分支搜索、滤波或新的关节速度阈值。速度/加速度、碰撞和大幅首步处理没有由当前数学`success`自动覆盖。

## 6. 验证证据与接受的缺口

- [原生接口验证](../../results/kinematics_validation_20260916/README.md)：SDK/ROS接口10组一致，FK模型对照60,806条请求。
- [原8条验证](../../results/continuous_ik_20260916/README.md)：19,900次连续IK及199个float32双臂前20步窗口通过；相关22项测试通过。
- [新增64条验证](../../results/ik_coverage64_20260916/README.md)：四批各16条、146,600次求解，76次拒绝集中于3个左臂块，其中9次在前20步；另有8个关节变化放大的诊断标记。累计72条，772条仅做关节覆盖扫描。
- 接受解未发现所用限位违例；失败目标已证实可达，缺口主要是当前参考路径上的分支选择。76/146,600约0.052%，不是闭环任务失败率，也不代表每次拒绝是独立事件。
- 数值误差小不等于机械精度；既有SHA对齐不等于本轮F1现场版本重新确认。本版尚未完成F1运行和真实policy执行验收。

**demo的当前取舍：** 保留这些已知缺口，先完成单版policy链路，以实际demo结果决定是否重启IK优化。此前“先修全部分支再继续”和“立即扩大到772条IK”的优先级由本次用户决定调整；多候选整段选解作为后续可选改进保存，不再阻塞本版离线移植。
