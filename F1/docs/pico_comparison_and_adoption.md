## 2. 同源关系与关键差异

两套共同使用 Pico/XRoboToolkit 输入、F1 模型/IK、UDP 桥和 ROS 控制/反馈，均依赖机器人已有驱动、相机和 SDK。meaxiao 是沿这条链路改造，不是换了底层机器人平台；旧版已经存在的模型和控制桥不应算成新版从零新增。

| 维度 | 本次读取的 lxl 归档 | meaxiao v1.4.4 | 对我们的价值 |
|---|---|---|---|
| 启动组织 | conda + 多个绝对路径；后台起 remote / teleop / PC Service；打印成功不等于三者均就绪 | 项目相对根目录、独立环境；预检、进程身份/锁、XR 就绪、启动失败清理；recorder、bridge、teleop 分离 | 复用新版生命周期，减少“头显已连但机器人链路没启动”的排查 |
| 启动姿态 | `all_remote_lxl.py` 先调用固定双臂目标初始化，再启动桥/录制；初始化异常返回后主流程仍继续 | 每次读取当前姿态作为会话起点，启动不主动走旧固定臂姿态；仍会管理手柄占用和底盘控制模式 | 将“建立控制链路”与“执行复位”分开；不把 allow-motion 入口称为纯只读 |
| IP / 端口 | `ip_config.py.local_ip` 为 LAN 地址，UDP 动作 8888 / 录制 8899；原路径硬编码 | 同样 8888 / 8899，本地内部链路默认 127.0.0.1；XR 与头显网络另管 | 不照抄旧版改 LAN IP 的步骤到新版；也不反向修改未经核实的 lxl |
| 臂控制 | 原遥操/IK/桥链；固定初始化与复位角度 | 独立单臂 Grip、交接保持、连续轨迹、输出限速/加速度/jerk、慢速增量精调、输入与输出异常锁存 | 新版更适合长期示教；软件精调倍率不等于实测毫米精度 |

| 训练格式 | 原始 ROS MCAP，后续转换 | 三路视频 + Parquet + 元数据，LeRobot v3 风格合同，名义 30 Hz、27D state/action | 缩短采集到审阅的路径，但与我们的模型 reader 合同仍需适配 |

## 5. 数据“预处理平台”已经具备什么，还缺什么

**本轮数采逻辑完全不变。** lxl原录制先写F1本地MCAP，未找到当前lxl自动上传服务器的运行证据；本机现有7条记录均为09-16，不算本次试用新数据。上肢试用包不运行任何录制器，4242也没有新增录制/上传按钮。

meaxiao的上游链路是：录制器管理start/stop/review/save/discard → LeRobot视频/Parquet与质量/恢复结果 → 会话冻结和持久传输队列 → 服务器独立拉取、hash/合同检查、幂等入库与回执 → 中央数据审阅。自动传输依赖独立配对/路径/服务配置，不能因为Pico能遥操就认定在传数据。上述链路本轮没有迁入F1-09，服务器与分析位置由用户后续确定。


现有代码已经覆盖：

`机器人录制 → episode提交 → 冻结传输 → 6000D校验/合并 → 视频/曲线审阅 → 人工阶段标注`

传输以 **机器人 ID + 数据集 UUID + 本地 episode** 去重，中央可重新编号，provenance 保留来源。最终目录通过符号链接指向不可变修订；训练时应固定解析后的修订，避免训练期间数据集随新增采集变化。复用这些设计能省下不少数据工程。

但它还不能直接替代我们完整的训练数据管线：

1. **动作来源有混合与回填。** `lerobot_recorder.py` 同时把 `/lead/joint_states` 和 `/motion_ctl/joint_ctl` 接到 `_joint_action_cb`；缺失/过期的关节、夹爪、底盘动作会用对应反馈补齐。相机历史对齐路径也在 action 查找失败后使用 state 样本。这样写出的行可能格式完整，但不是每一维都是真实命令。当前检查不能据此证明全部 action 可作为监督。
2. **建议先补逐维合同。** 保存 `action_source`（如 planner_target / executed_command / measured_fallback / missing）、`action_valid`、源时间与控制模式/复位事件；规划目标和最终控制目标最好分开记录。缺失目标可以保留用于观察，但默认不进入要求真实命令的监督，不把同帧反馈默认当作动作。
3. **27D 不能靠截取直接接模型。** 顺序是双臂14 + 头3 + 身体5 + 夹爪2 + 底盘3；当前任务已有19D/23D等不同合同。用名字、单位、坐标、动作层级明确映射；需要 TCP 时通过已核验的运动学转换，不用同维数猜语义。
4. **阶段分割只是候选。** 现有分段按底盘运动找去返程，并假设抓手机/放盒任务；泡沫分拣、积木操作或原地双臂任务不能直接套四阶段。任务成功/失败、人工干预、场景覆盖仍需标签。
5. **质量指标不是自动删数据规则。** 高 jerk / 高 RMSE / 长时长可能是有效纠错；跟踪 RMSE 在 action=state 回填位置还可能显得过小。应结合来源 mask、时间轴和视频判断。
6. **后续训练发布继续用我们已有流程。** 同源分组后 train/validation 划分、断档/人工干预处切断动作窗口、逐维 mask、只用训练有效值归一化、正式 reader 回读。原始 MCAP 仍有追溯价值，不能因改存 Parquet 就丢弃历史。
