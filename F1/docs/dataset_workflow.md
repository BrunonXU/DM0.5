# 机器人示教数据：采集、清洗与发布流程

适用于新任务的数据准备，不绑定机器人关节数、相机数量或模型。目标是得到可信的监督关系：
**当前看到什么、处于什么状态，对应随后应当执行什么动作。** 时间对齐、标签正确、接口可执行须分别验收。

正常采集的命令和反馈齐全时，按下面主流程完成检查即可；不需要额外做视觉速度估计或逐段手工补标。
本次底盘漏录属于缺失监督事故，单独处理，不能把事故恢复流程变成每个任务的固定步骤。
本任务的具体字段、参数和证据见[F1清洗流程](../foam_sort_whole_body/docs/data_cleaning/f1_data_pipeline.md)，
实际发布门槛见[任务验收合同](../foam_sort_whole_body/docs/dataset_acceptance.md)。本文不维护任务当前数量与进度。

## 流程与完成条件

| 阶段 | 输入 | 必须留下的产物 | 本阶段何时完成 |
|---|---|---|---|
| 1. 定义监督合同 | 任务意图、接口与实际控制链路 | 字段/单位/坐标/时钟/任务边界合同 | 每个模型字段都有唯一来源与可解释含义 |
| 2. 采集前验证 | 合同、当前机器与录制配置 | 短录制及回读报告 | 必需流实际写入；全部控制模式与关键事件能回读 |
| 3. 原始数据入库 | 录制文件、采集日志 | 来源清单、完整性报告 | 文件身份固定；缺失、损坏与重复已列明 |
| 4. 因果对齐 | 原始消息、时钟证据 | 时间索引、逐维有效性、对齐报告 | 每个有效样本的来源和时间选择可复算 |
| 5. 内容与监督检查 | 对齐包、原图、任务结果 | 通过/修复/隔离清单及区间 | 已发现冲突全部有处置；验收覆盖达到合同要求 |
| 6. 训练样本构建 | 已验收区间、模型数据合同 | 分组、chunk、归一化与版本清单 | 无跨界监督或来源泄漏；统计只使用有效训练数据 |
| 7. 发布验收 | 正式训练reader、派生包、接口适配 | 独立一致性报告、replay报告、发布清单 | 满足预先约定的各项门槛；未完成项不会写成通过 |

先在覆盖关键事件的小样本上跑通整条链路，再批量运行；全量自动检查与分层人工复核可以并行。
某一阶段失败，退回造成失败的最早环节，重跑受影响的下游产物，不从原始采集反复全量重做。

## 1. 定义监督合同

- 列清输入、输出、任务文本及不由模型控制的部件。相同维数不表示相同字段，不沿用另一机器的切片或归一化。
- 每个字段记录消息名、字段名、顺序、单位、正方向、参考坐标、绝对量/增量/速度、有效范围及来源类型。
- 按名字映射关节；单位变换、符号和零点变换各发生一次。夹爪百分比、开口距离、力矩不能混用。
- 状态使用反馈；动作使用合同所定义的控制目标。遥操作主端、控制器收到的目标、实际反馈是不同来源。
- 查清限幅、插值、模式切换及一键复位是否绕过普通命令topic，明确模型应模仿哪一层目标。
- 写明一轮任务的开始、完成结果、允许的自主恢复、人工介入和下一轮准备；末态不必与初态完全相同。

**退出条件：** 每个字段都能定位到真实消息；控制目标的生成路径及特殊动作路径有依据。
尚无依据的字段保留未决，不靠字段名称或一张接口示例猜含义。

## 2. 采集前验证：先证明录到了

在本轮实际使用的机器、录制器、相机和控制版本上做一次短录制，覆盖抓放、保持、移动、复位和结束。
这些事件按任务涉及范围选择；涉及控制模式切换时必须包含切换前后。真机动作遵循现场操作约定。

- 从写出的文件检查topic存在性、消息数、首末时间、实际频率、最大间隔及字段内容；只看在线topic列表不够。
- 与录制时长及配置频率比对，识别空topic、只录了开头、后半程断流、重复旧值和相机时间戳停滞。
- 频率检查采用实际接口约定和抖动余量；不能把接口示例频率直接当硬件要求，也不能只看平均Hz。
- 独立回读图像及数值，核对一次明显事件的画面、命令、反馈顺序，并确认所有相机可以解码。
- 专门看复位/回零：机器人动时是否录下有效目标，控制模式和复位事件是否有记录。
- 保存实际配置、软件版本及必要的未提交修改；设备或采集链路变更后重跑这段验证。

**退出条件：** 短录制中的必需数据与全部控制路径完整，回读能够解释实际动作。
若这一项未通过，先修采集器；扩大采集量不能补回缺失目标。

## 3. 原始数据入库与完整性检查

- 原始文件只读保留，派生包另存；清单记录来源、采集会话、机器人/配置版本、文件大小及内容哈希。
- 检查容器可读、消息解码、字段长度/名称、非有限值、时间顺序、相机数量和图像解码结果。
- 记录空流、局部缺帧、长断档、截断录像、完全重复及跨文件时间重叠；技术失败与任务失败分开列出。
- 文件可读不代表有效：整段重复发布旧值、占位常量、录到了错误设备，同样要结合合同检查。
- 保存每次排除的原因、源时间区间、影响维度和证据。来源文件不因候选筛除而删除。

**退出条件：** 入库范围及异常列表确定，全部可用来源可追溯；不可读部分不会悄悄进入训练。

## 4. 因果对齐与有效性

先区分曝光时间、设备时间、消息header时间和记录器接收时间，再选公共时间轴。
统一日志时间可以建立索引，但不能自动消除设备时钟偏移、漂移、传输延迟或曝光延迟。

- 保存原始时间戳及映射依据。稳定偏移、漂移、倒退、重复分别处理，不把所有差异都平移成零。
- 对当前观测只取因果可用的数据；禁止为“对齐得更像”把未来帧或未来反馈放进当前输入。
- 重采样依时间索引取各路样本，不按相同帧号拼接不同采样频率的流；明确保持、插值及最大年龄规则。
- 新鲜度阈值、跨相机对时残差和动作响应延迟分别报告，不能用一个阈值代替三件事。
- 命令先变、反馈后动通常包含真实控制延迟；`action(t) != state(t)`本身不是错标证明。
- 有证据的零速/保持是有效标签；缺失、遮挡或不可辨识是unknown，需要独立有效性标志，不能填零冒充已知。

**退出条件：** 独立检查可复算每个索引及其年龄；入选区间没有未解释的持续对时冲突。
对时容差来自任务动态、传感器和控制合同，不照抄其他数据集的毫秒数。

## 5. 任务内容、监督语义与最小修复

将原图、目标、反馈、模式事件和有效性放在同一时间轴，检查模型将学到的动作是否符合实际任务。
微调也需要正确的任务文本、结果与干预信息；它通常不要求逐帧画框，但不免除监督质量验收。

- 全量规则检查负责发现异常；人工按采集批次、设备/配置、长短录制、阶段、异常类型分层复核。
- 异常样本优先看，正常对照也要覆盖。报告分母、已看范围和未决区间，不能把筛查阴性当作视觉通过。
- 等待、放稳、保持、返程和自主恢复可能是有效任务，不能为了录像整齐统一删除静止或重试。
- 长录像可以包含多轮。仅在明确不连续、人工介入或任务定义要求时逻辑分段；子片段仍关联同一来源。
- 夹爪事件只是定位线索：开闭可能发生多次，末尾也可能早已保持。事件个数不能直接当循环数。
- 目标保持而反馈持续变化时，先检查控制延迟、目标层级、限幅和旁路控制；不能直接判定录制bug。
- 证实目标缺失后，也不能把同一时刻的反馈直接替换成动作。反馈重建是另一种监督假设，须单独定义并验证。
- 最小修复先限定影响：坏帧影响对应样本，断档切断窗口，错标段局部隔离；整条不可信才整条排除。

**退出条件：** 已知错误不进入有效监督；每个疑点有通过、可验证修复、隔离或不纳入本版的结论及证据。
抽查用于检查工具和发现问题，不能代替任务合同已经要求的全量结果/干预覆盖。

## 6. 样本窗口、分组与归一化

- mask分别表达状态、动作各维、当前观测及未来动作窗口，实际粒度依模型reader能力确定。
- 一个无效时刻会影响所有未来chunk覆盖它的起点；不能只屏蔽异常段内的起点。
- 动作窗口不得跨未知目标、断档、人工干预或不连续任务边界；未来图像是否需要有效取决于模型实际输入。
- 尾部不足长度按明确的padding合同处理，padding不计真实监督；不能重复最后一个非零速度填满未来。
- 先按原录制、采集会话或已识别的重复组划分train/validation，再切片；相关片段继承分组。
- 不因后续筛选重随机划分，避免同源近邻泄漏；若合并重复组需要调整，发布新的分组版本与原因。
- 归一化只用入选训练来源的有效值，按字段统计；masked原值和验证集不得混入。
- 常量维提供明确编码与非零尺度，保留其常量事实；不要把未知字段补成常量后宣称稳定。
- 报告任务阶段和来源的采样占比。模型按窗口采样时，长录像会贡献更多样本，要检查是否偏向等待等阶段。

**退出条件：** 独立复算mask、分组和统计一致；样本量的含义明确，技术有效数量不会被写成质量通过数量。

## 7. 独立验收与发布

验证程序要有独立依据，不能只调用生成器自己的函数再比较一次。先冻结候选，检查通过后再发布。

- 用正式训练reader读回图像选择、原始状态、动作、时间及mask，与源消息和发布合同逐项对照。
- 验证归一化/反归一化往返误差及维度顺序，检查padding和随机采样实际行为。
- 离线replay使用同一reader和接口映射，显示当前观测、未来目标、反馈及异常边界；预览专用脚本通过不能替代它。
- 映射到执行接口后，核对名字、符号、单位、频率、初态、结束/中断行为；先生成待发送命令日志。
- 任务合同要求现场replay时，由现场操作者执行，记录实际命令、反馈、图像、控制模式和任务结果。
- 数据错误、接口映射、调度延迟、跟随误差、环境初态分别定位；现场通过也不表示模型已泛化。
- 发布清单绑定原始来源、修订区间、配置、工具/reader版本、mask、分组、统计和验收报告。

**退出条件：** 预先约定的发布门槛逐项通过；仍未达到的范围明确排除，不能用“demo”暗中降低门槛。
底层限幅、控制权变化或人工干预影响了结果时，应如实记录，不能算作原示教精确回放通过。

## 缺失监督事故：在主流程之外处理

先区分“数据存在但映射错”和“事实没录到”。前者从原始来源重新导出；后者只能从独立证据恢复可辨识部分。
图像运动、路线距离先验和任务顺序可以提出候选，不能恢复不存在的逐时刻测量，也不能强填固定段数。
候选保留实测/先验/人工判断的来源、时间边界不确定性和unknown；生成曲线自身积分正确只证明数值自洽。
先用代表样本及独立证据验证修复，再扩大；不可验证部分隔离或补采，不无限调参数“修到看起来正常”。

区分“边界有证据但只能估计”和“该时段不可辨识”。前者可保存边界点及误差范围，明确弱监督含义；后者保持unknown。
不要因为估计存在误差就把每个正常过渡切成许多短片段，也不能为了连续回放把所有空隙填零。
仅有运动内部的可靠匹配，仍不足以把已知总位移分配给这段内部；缺失加减速或局部调整时，应隔离受影响的整条运动腿或进一步获取独立证据。

视觉检查要防止匹配锁在静止前景、把透视变化当成运动方向。比较不同背景区域、相机/身体姿态及任务事件；
低光流不等于底盘静止。按画面相似度迁移阶段也必须在独立录制上检查边界误差，不能只看路径代价小就验收。

本次可复用的反例见[补标源码审查](../foam_sort_whole_body/results/base_script_audit_20260915/report.md)：
固定时间比例、兜底窗口与只按消息数续跑，会产出格式正确却监督错误的数据。

## 版本与收尾：防止重复劳动和范围失控

- 缓存身份包含输入内容哈希、配置、算法/代码及影响输出的依赖版本，并核对产物哈希；相同路径或条数不够。
- 长任务保存进度、日志和失败原因；续跑只复用身份一致的产物。新的修复另存版本，不覆盖已验证父包。
- 当前进度只维护一份；通用方法放本文，任务参数放任务流程，事故证据放独立结果，修复日记只记录变化与验证。
- 每类问题结束时写清影响范围、根因/未知、处理、独立验收、是否关闭。仅新增观察而无影响证据时不重开全量检查。
- 首版提前固定任务边界、来源范围及门槛。新异常若影响入选监督必须处理；只影响范围外的数据则记入后续队列。
- 需要人工事实时，提交最小样例、建议值和具体分歧；不能让操作者从头重标，也不能把等待回复算作已通过。
- 用户将审核交给助手后，记录实际复核者、证据和不确定性，继续自主处理；保留原人工草稿，不能把助手判断改写成人工确认。

清洗完成的标志是**发布范围内的监督满足合同，并有独立证据**。不是审计脚本越多越好，也不是把所有历史异常都修完。
