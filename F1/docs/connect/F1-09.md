## 2026-10-12：开机 Wi-Fi 失联与接口名绑定修复

**当前：Wi-Fi、反向SSH及4242已恢复。** 无线接口为 `wlP1p1s0`，永久/当前MAC均为 `02:00:00:00:00:01`，DHCP再次分配 `192.0.2.3/24`，网关 `192.0.2.19`。上表及旧记录中的 `wlan0` 是历史接口名，不应继续硬编码到连接或探针中。

### 已确认的故障链

1. 本次启动内核日志在约21.995秒记录 `cnss_pci 0001:01:00.0 wlP1p1s0: renamed from wlan0`。udev显示采用 `/usr/lib/systemd/network/99-default.link`，命名方案v255，路径名为 `wlP1p1s0`；这属于操作系统网卡命名，不是更换IP或MAC。
2. 已保存 `example-wifi`（UUID `00000000-0000-0000-0000-000000000001`）仍设置 `connection.interface-name=wlan0`。NetworkManager明确拒绝连接，错误为 `profile is not compatible with device (mismatching interface name)`。
3. 用户保持维护网线/NoMachine在线，清除该连接的接口名限制并保留自动连接。修改约766.909秒完成，约766.913秒出现 `policy: auto-activating connection 'example-wifi'`，约767.800秒激活成功，并获得 `.58`。
4. 上述自动恢复早于用户随后约778.290秒执行的显式 `connection up`。因此已经观察到自动连接成功，不能再表述为“只有手动连接成功”。反向SSH自行恢复；助手未重启隧道、驱动或机器人。

### 为什么这次才出现

本次开机的接口重命名机制与名称不匹配故障已有日志直接证据。但现存journal只有本次boot，缺少上一次保留 `wlan0` 的启动过程，不能断言是系统更新、驱动升级或某人改配置造成命名变化。已保存的其他Wi-Fi配置中也同时存在两种接口名，说明配置中已有命名差异，不能据此确定首次发生日期。修复不依赖解释此前每一次命名：移除无必要的接口名约束后，两种名称均不会再因该字段不匹配而被拒绝。

### 持久设置与验收边界

当前读回：接口名限制为空；`autoconnect=yes`、优先级999、重试0（持续重试）；无用户权限限制；已存认证信息可直接用于此次自动连接，未读取或导出密码。当前20个保存的客户端Wi-Fi中仅本条开启自动连接，其余19条保持关闭（包括同SSID的 `example-wifi 1`），不删除配置。NetworkManager已启用；隧道与4242的用户服务均enabled，`Linger=yes`。到6000D路由确认为经 `wlP1p1s0`，不是借维护网线联网。

`nmcli connection modify` 未使用临时模式，修改为持久连接设置。已验证自动激活、DHCP保留地址、远程恢复及自启配置；**尚未在这次修复之后重新整机冷启动**。因此预期正常重启会自动连接，剩余项是冷启动验收，不能将“未重启实测”说成“修复只临时有效”。后续正常现场关开机时，确认无需桌面操作即可出现D071连接、`.58`和22009入口；无需为查证主动打断数采/HIL。

### 同类故障的现场恢复

先用维护网线连NoMachine `192.0.2.11`，在F1终端查看 `nmcli device status` 和实际接口名，再检查目标UUID的 `connection.interface-name`。仅在SSID、UUID及名称不匹配均确认时清除旧限制：

```bash
sudo nmcli connection modify uuid 00000000-0000-0000-0000-000000000001 connection.interface-name "" connection.autoconnect yes
```

先等待自动连接，再用 `nmcli device status`、`ip -br address` 验证；仅未恢复时，针对**当时实际接口名**手动 `nmcli --ask connection up` 并检查原因。不要为了恢复无线重启整套NetworkManager、改机器人内部网口、重新建立路由器绑定或强制把网卡改名为wlan0。

## 排障与停用

F1 的 `user` 终端、任意目录：

```bash
systemctl --user status f1-6000d-tunnel.service --no-pager
loginctl show-user user -p Linger
tail -n 80 /home/user/Bruno/connect/tunnel.log
ip route get 192.0.2.1
```

需要手动重连时执行 `systemctl --user restart f1-6000d-tunnel.service`。
显式停用：`systemctl --user disable --now f1-6000d-tunnel.service`，会断开隧道，应从现场终端操作。
恢复：`systemctl --user enable --now /home/user/Bruno/connect/systemd/f1-6000d-tunnel.service`。
撤销服务器授权时仅删除 `f1-09-reverse-tunnel` 对应公钥行，不整体恢复旧备份。
初始备份为 `~/.ssh/authorized_keys.before_f1_09_20260922T072218Z`。
完整回退 Linger 变更前，先确认没有其他需要驻留的用户服务，再执行 `loginctl disable-linger user`。
