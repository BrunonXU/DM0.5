# 数据驱动的实机 Replay

2026-10-14。开发与部署事实以 [STATUS](STATUS.md) 为准。

## 现场入口

DATA → 一条 F710 人工示教 → 右上角「实机 Replay」。打开面板、检查、载入调姿草稿都不发送运动命令。原有原图/视频播放继续只用于历史回看。

首版支持原速、单次、整条或一个连续时间区间。时间零点是首条真实手臂命令的发布时间，与三图零点可能略有偏移；输入范围向内选择真实命令行，检查结果显示实际范围。不支持倍速、循环、任意跳转或自动续跑。

1. 打开面板自动只读检查，默认整条、原速、单次。主区显示起点状态、时长、命令数和开始/起点/停止操作；“回放区间”和“检查与诊断”分别默认折叠，历史事件在诊断中。
2. 起点不一致时直接点击「回到录制起点」，同页确认后复用已有整套pose规划/限位/到位合同。双臂、夹爪及头身上下文一起准备；启用的头部边界恢复需要明确显示并确认。到位后自动重新检查，但不会自动回放。
3. 点击「开始回放」会按需提示控制码、自动重新检查并显示一次运动确认。历史Home/人工停止保留为诊断，不再逐条强制勾选；异常在确认中摘要提示。
4. 停止按钮位于主操作区。运行期间显示当前执行状态，隐藏已经过时的起点就绪提示。运行结果区分「执行完成」与「两次实测对比」，以最大轨迹偏差为主指标，关节表和叠图按需展开；中断结果只代表已执行部分。失联不自动续跑，刷新不重新提交。

软件停止不是硬件急停；发布命令与进度走完不是成功。成功要求最终参与轴/夹爪在原有容差内，连续收到跨越至少150ms的新反馈。原有HAL接收新鲜度不冒充独立编码器采样或物理停止证明。

## 来源与动作合同

仅接受完整提交的 `f1_upper_16d_v1`、schema 3、真实 powered demonstration；不接受 shadow、恢复目录、策略HIL、旧LXL MCAP或训练导出。16D顺序为左右臂各7轴（HAL度），然后左右夹爪（0开100闭）。录制机器人ID及绑定profile SHA必须与当前机器人一致；更换配置后不自动迁就旧数据。

读取 `journal/manifest.json`、`control.jsonl`、`observations.jsonl`、`events.jsonl`，核对SHA、计数、episode/stream身份、严格递增的控制时间/序号、publisher GID、逐字段发布时刻和保持值。采用 `submitted` 和 `publications`，禁止以 selected、candidate、measured 或训练30Hz重采样结果代替。任一不完整发布阻塞检查，不静默删掉坏行。该检查范围不包含图像载荷全量解码或相机pack全量哈希。

夹爪沿原始事件发布时间发送，保持行不反复发布。裁剪起点可能继承更早的夹爪目标：在起点已对齐后，各缺失通道只用真实记录的保持目标初始化一次。原始Home/hold和异常事件保留，不自动拼接删减。

只回放双臂/夹爪。头/身8轴是前置上下文，持续核对当前反馈；片段内发生超过既有姿态容差的头身变化时拒绝。所有关节、夹爪、F1耦合腕部限位均检查。原始发布时间差分的速度/加速度仅为诊断，发布抖动及保持切换会放大这些数值，不能冒充电机实测速率，也不能拿手动pose轨迹生成参数作为新的回放阈值。保留真实目标与时序，不再次滤波、不改写原件；原手动调姿限速不变。

## 执行与接口

`robot/replay_data.py` 独立读取；`robot/replay_action.py` 通过现有RosAdapter输出；`replay_service.py` 绑定目录身份、只读检查与一次性执行票据。无需安装DAgger Python包，不复制旧F1项目。

| 接口 | 合同 |
|---|---|
| GET `/api/replay/review?episode_id=<24位ID>&start_s=0&end_s=<可选>` | 只读数据/状态检查，无租约、无发布者。成功响应含 `review`，`executable` 与HTTP成功独立。可执行或可准备起点时发放 `review_id`，绑定浏览器、来源、范围与profile，120秒有效；重新检查使旧票据失效。 |
| POST `/api/replay/start` | `{review_id, lease_id, confirm:true}`；同源、登录和有效控制租约。重读来源、消费票据后提交单一action；重复点击不排队。客户端不能提供任意路径/轨迹，`/api/actions` 不接受客户端 `kind:replay`。 |
| POST `/api/replay/align` | 同样的票据、同源、租约与confirm；仅接受后端由录制生成的整套pose，重新核对规划后消费票据。可选 `head_boundary_recovery_ack:true` 仅用于已显示的原生边界恢复；完成后不自动回放。 |
| GET `/api/replay/reports/<32位记录号>` | 只读执行结果和两次实测比较；严格记录号/大小/符号链接校验，不返回原始高频samples。 |
| GET `/api/actions/<id>`、`/api/state` | 沿用进度/终态；action的 `replay` 含来源指纹、范围、录制ID、结果记录号。 |
| POST `/api/stop`、`/api/control/release` | 沿用取消语义；执行线程退出前不释放控制锁。 |

HIL、Pico、数采及其他工作台动作占用时拒绝。磁盘验证在控制互斥区外完成，避免阻塞停止/续租；核对期间停止或释放控制权使票据失效，不会随后启动。提交等待期间确认框保留「停止回放请求」。创建发布端后再次检查起点；运行时持续检查新鲜反馈、外部命令、头身上下文和双臂跟随，夹爪沿原有超时检查。

命令调度表与目标向量在计时开始前构建。沿原始相对发布时间、绝对时钟、原顺序逐条发送，不丢命令、不改目标、不重采样。日志中亚毫秒的发布间隔不额外作为超时阈值：正常OS/检查耗时可导致相邻命令较接近，实际下发误差逐条记录；绝对迟到或连续手臂下发间隔超过既有25ms预算时停止，不无限追赶。保留反馈、独占及限位检查，比较计算在执行结束后完成。

总预算独立使用 `max_replay_task_s`（默认600秒、允许1–1800秒、包含末端确认）；普通pose/旧API预算不变。执行结果、来源指纹、最多50Hz当前实测和反馈时间写入独立 `runtime/replay_runs/<id>.json`，不是DDS送达或硬件ACK。停止只在独占且反馈新鲜合法时发送实测保持。

## 两次实测对比

保留原始 `state16` 与逐字段 `state_timestamps_ns`，按首条命令的相对时间，与本次反馈接收时间逐通道对齐。原始相邻反馈之间线性插值；不外推、不跨越大于现有feedback_max_age_s的间隙、不时间扭曲、不用命令回填实测。缺少旧版反馈时明确无法比较，不宣称一致。

每个双臂关节/夹爪给出平均绝对偏差、RMS、最大偏差及发生时间、比较点数/采样点数。重复接收时间不重复计数；指标使用全部最多50Hz样本，图线最多每轴1500点。夹爪额外比较跨越50%开度的次数与时间差（不是推断电机启动时刻）。界面提供按部位选择的原始/本次实测叠加图和下发时间误差；没有约定验收阈值时不自动判定硬件合格。

## 离线脚本与验证

开发机终端，工作目录 `F1-4242/`；检查本地原件，不连接机器人，报告写 `/tmp/f1-replay-inspect.json`：

```bash
python3 scripts/replay_episode.py /绝对路径/某条F710原件 \
  --start 0 --end 10 > /tmp/f1-replay-inspect.json
```

可加 `--profile /绝对路径/机器人配置.json` 核对配置绑定与静态轨迹限制。脚本只输出JSON，没有远程启动动作选项。现场执行统一走4242控制租约与确认。

软件验证入口为 `python3 -m pytest -q tests/test_motion_replay.py` 与 `node scripts/check_motion_replay_browser.cjs`；浏览器脚本仅启动回环假API，不连接机器人，截图/报告在 `results/motion_replay_browser/`。软件验证不能替代目标ARM节拍和现场短片段验收。

`scripts/check_replay_timing.py <原件目录>` 用真实时序、内存假传输与墙钟做节拍演练；不加载ROS，不能代表DDS或硬件验收。
