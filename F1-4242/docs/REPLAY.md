# 数据驱动的实机 Replay

数据页为各来源录制保留统一 Replay 入口；是否能复现取决于原始发布证据和机器人绑定，不按人工示教/HIL/rollout名称限制。视频回看与机器人复现分开操作。

按原始轨迹单次复现，普通开始仍要求起点对齐。2026-10-23新增的单次强行回放允许跳过手臂起点偏差检查，从当前姿态执行录制目标；反馈、限位、夹爪起点、头身上下文与独占控制检查仍有效。功能开发、界面确认与实际部署分别以 [STATUS](STATUS.md) 为准。

短时系统调度抖动使后续轨迹整体顺延，保持所有目标及顺序；总用时可能略增加，不把瞬时调度迟到直接当成数据错误。历史数据缺少可核验发布日志时显示原因，不能强行执行。

## 现场入口

DATA → 录制列表的「Replay」，或录制详情的「机器人复现 Replay」。打开面板、检查、载入调姿草稿都不发送运动命令。MP4播放只用于历史回看。

支持原始节奏、单次、整条或一个连续时间区间；短时系统卡顿时剩余轨迹可顺延。时间零点是首条真实手臂命令的发布时间，与三图零点可能略有偏移；输入范围向内选择真实命令行，检查结果显示实际范围。不支持倍速、循环、任意跳转或自动续跑。

1. 打开面板自动只读检查，默认整条、轨迹复现、单次。主区显示起点状态、时长、命令数和开始/起点/停止操作；沿用原米色面板与黑色主按钮；“区间与诊断”默认折叠，历史事件放在其中。
2. 起点不一致时直接点击「回到录制起点」，点击后复用已有整套pose规划/限位/到位合同。双臂、夹爪及头身上下文一起准备；启用的头部边界恢复包含在本次对齐点击中。到位后自动重新检查，但不会自动回放。
3. 点击「开始回放」会取得本浏览器控制权、重新检查并直接提交。历史Home/人工停止保留为诊断，不需要密码、勾选或二次确认。
   手臂起点偏差超标而其他检查通过时，可单独点击「强行 Replay」。此选择仅对本次开始生效，直接执行原始目标，不自动对齐、不改变后续普通开始的检查；首个目标可能与当前位置不同。检查失效、断联或其他动作占用时不能开始。起点偏差及是否强行开始写入本次执行记录。
4. 停止按钮位于主操作区。运行期间显示当前执行状态，隐藏已经过时的起点就绪提示。运行结果区分「执行完成」与「两次实测对比」，顶部显示平均偏差、最大瞬时偏差和覆盖关节数；左右臂7关节并列显示共同尺度偏差条；点击关节查看偏差曲线或轨迹叠加，完整统计表默认展示，曲线默认折叠；中断结果只代表已执行部分。失联不自动续跑，刷新不重新提交。

软件停止不是硬件急停。Replay 的执行完成表示原始命令已全部下发，且末端收到跨越至少150ms的新反馈；不表示实测到位或硬件一致。双臂运动中及结束时的跟随偏差只记录，不以1°容差中断或判执行失败。起点对齐、独立pose动作和夹爪运行超时仍保留原检查。仅连续到位反馈才设置 feedback_verified；final_target_reached 单独记录结束时到位状态。原有HAL接收新鲜度不冒充独立编码器采样或物理停止证明。

本地精修候选进一步按阶段突出检查/起点/开始/停止，过期禁用开始并清除旧就绪；最近报告和失败重试均只读。任务用时与录制区间分别显示，反馈匹配数不作为整段覆盖率。用户新增的报告组件继续保留，样式独立于原主题。见 [精修交付](UIUX_UPGRADE.md)。

## 来源与动作合同

原生命令适配器接受完整提交的 `f1_upper_16d_v1`、schema 3 双夹爪及 schema 4 明确移除左夹爪的真实 powered 记录，包括人工示教、策略HIL与真机rollout；不检查purpose名称。schema 4 必须有匹配的硬件声明、逐行有效掩码及缺失反馈语义；左夹爪零值只是存储占位，不用于发布、起点对齐、实测比较或到位判定。右夹爪和双臂的真实发布／反馈检查保持。仍拒绝shadow、恢复目录、缺失/不完整发布证据。旧LXL/Pico记录保留入口，但若缺少这一可核验发布日志及机器人绑定，会显示具体原因并阻止执行；不使用MCAP观测、候选目标或训练导出替代真实命令。16D顺序为左右臂各7轴（HAL度），然后左右夹爪（0开100闭）。录制机器人ID及绑定profile SHA必须与当前机器人一致；更换配置后不自动迁就旧数据。

读取 `journal/manifest.json`、`control.jsonl`、`observations.jsonl`、`events.jsonl`，核对SHA、计数、episode/stream身份、严格递增的控制时间/序号、publisher GID、逐字段发布时刻和保持值。采用 `submitted` 和 `publications`，禁止以 selected、candidate、measured 或训练30Hz重采样结果代替。任一不完整发布阻塞检查，不静默删掉坏行。该检查范围不包含图像载荷全量解码或相机pack全量哈希。

夹爪沿原始事件发布时间发送，保持行不反复发布。裁剪起点可能继承更早的夹爪目标：在起点已对齐后，各缺失通道只用真实记录的保持目标初始化一次。原始Home/hold和异常事件保留，不自动拼接删减。

只回放双臂/夹爪。头/身8轴是前置上下文，持续核对当前反馈；片段内发生超过既有姿态容差的头身变化时拒绝。所有关节、夹爪、F1耦合腕部限位均检查。原始发布时间差分的速度/加速度仅为诊断，发布抖动及保持切换会放大这些数值，不能冒充电机实测速率，也不能拿手动pose轨迹生成参数作为新的回放阈值。保留真实目标与时序，不再次滤波、不改写原件；原手动调姿限速不变。

## 执行与接口

`robot/replay_data.py` 独立读取；`robot/replay_action.py` 通过现有RosAdapter输出；`replay_service.py` 绑定目录身份、只读检查与一次性执行票据。无需安装DAgger Python包，不复制旧F1项目。

| 接口 | 合同 |
|---|---|
| GET `/api/replay/review?episode_id=<24位ID>&start_s=0&end_s=<可选>` | 只读数据/状态检查，无租约、无发布者。成功响应含 `review`，`executable`、`can_force_start` 与HTTP成功独立；`start_deviations` 记录实测起点偏差。可普通开始、强行开始或准备起点时发放 `review_id`，绑定浏览器、来源、范围与profile，120秒有效；重新检查使旧票据失效。 |
| POST `/api/replay/start` | `{review_id, lease_id, confirm:true}`；可选严格布尔 `force_start:true`，仅跳过双臂起点容差。本次显式选择不保存为默认。保持同源、浏览器会话和有效控制租约；重读来源、消费票据后提交单一action，重复点击不排队。客户端不能提供任意路径/轨迹，`/api/actions` 不接受客户端 `kind:replay`。 |
| POST `/api/replay/align` | 同样的票据、同源、租约与confirm；仅接受后端由录制生成的整套pose，重新核对规划后消费票据。可选 `head_boundary_recovery_ack:true` 仅用于已显示的原生边界恢复；完成后不自动回放。 |
| GET `/api/replay/reports/<32位记录号>` | 只读执行结果和两次实测比较；严格记录号/大小/符号链接校验，不返回原始高频samples。 |
| GET `/api/actions/<id>`、`/api/state` | 沿用进度/终态；action的 `replay` 含来源指纹、范围、录制ID、结果记录号。 |
| POST `/api/stop`、`/api/control/release` | 沿用取消语义；执行线程退出前不释放控制锁。 |

HIL、Pico、数采及其他工作台动作占用时拒绝。磁盘验证在控制互斥区外完成，避免阻塞停止/续租；核对期间停止或释放控制权使票据失效，不会随后启动。停止/租约取消使该会话的检查票据失效。创建发布端后再次检查起点；强行开始仅在两次检查中豁免双臂位置容差，实测合法性和其他前置条件不变。运行时持续检查新鲜反馈、外部命令、头身上下文；双臂跟随误差只记录，夹爪沿原有超时检查。`/api/replay/align` 不接受强行开始，仍执行完整姿态到位检查。

命令调度表与目标向量在计时开始前构建。沿原始相对发布时间、绝对时钟、原顺序逐条发送，不丢命令、不改目标、不重采样。原始命令间隔属于录制时间轴，包括大于25ms的间隔，不补发保持命令、不压缩空档；这不等于证明任意原始动作可安全复现。日志中亚毫秒的发布间隔也不额外作为超时阈值。

短时卡顿后采用剩余时间表顺延：`replay_reschedule_after_s`默认25ms，是顺延触发值，不再是整条失败阈值。在调度、反馈检查后和发送返回时检测本条迟到，超过触发值时保留本条和全部后续目标，将剩余计划整体后移，不补发积压命令来追赶、不跳点、不重采样。触发值允许大于0且不超过25ms；旧`max_replay_lateness_s`不再用于此模式，身体调姿配置保持独立。发送返回时已交给传输层的命令不可撤回，顺延只作用于尚未发送的事件。

程序仍必须持续检查机器人状态。用既有`feedback_max_age_s`作为监控连续性窗口（F1-09为250ms）；调度/监控/发送若使检查中断超过该窗口则停止，不能因为后台持续收到新反馈就掩盖执行线程长时间失去监控。原始等待期间最多每10ms等待一次，持续检查反馈、外部命令与取消。夹爪到位超时按实际目标改变的发送时刻计算；整体顺延不会重置这个时限。预计结束时间包含顺延，总任务上限不变。

最大原始间隔与顺延触发值分别记入只读metrics，实际顺延事件、累计时长和监控窗口记入结果`playback_timing`。界面正常只显示轨迹复现；技术数值在报告说明里。底层配置、驱动合同、限位、起点和租约保持，比较计算在执行结束后完成。

总预算独立使用 `max_replay_task_s`（默认600秒、允许1–1800秒、包含末端确认）；普通pose/旧API预算不变。执行结果、来源指纹、最多50Hz当前实测和反馈时间写入独立 `runtime/replay_runs/<id>.json`，不是DDS送达或硬件ACK。停止只在独占且反馈新鲜合法时发送实测保持。

## 两次实测对比

保留原始 `state16` 与逐字段 `state_timestamps_ns`，按首条命令的相对时间，与本次反馈接收时间逐通道对齐。原始相邻反馈之间线性插值；不外推、不跨越大于现有feedback_max_age_s的间隙、不时间扭曲、不用命令回填实测。发生轨迹顺延时，对比仍使用真实经过时间，时间偏移造成的差异计入偏差，不事后挪动曲线来制造更小误差；超过原始区间的反馈不外推，原始samples保留。缺少旧版反馈时明确无法比较，不宣称一致。

每个双臂关节/夹爪给出平均绝对偏差、RMS、最大偏差及发生时间、比较点数/采样点数。左右臂偏差条默认可见，完整表格按需展开。左臂、右臂、双臂汇总：先按关节计算，再对至少有2个比较点的关节等权平均；汇总RMS为各关节RMS平方平均的平方根，最大偏差取参与关节中的最大值。显示参与关节数/应有数，缺失关节不填零；夹爪以开度百分点单列，不参与角度平均。中断任务保留部分执行标记；旧报告不编造整体均值。重复接收时间不重复计数；指标使用全部最多50Hz样本，图线最多每轴1500点。夹爪额外比较跨越50%开度的次数与时间差（不是推断电机启动时刻）。界面提供按部位选择的原始/本次实测叠加图和下发时间误差；没有约定验收阈值时不自动判定硬件合格。

## 离线脚本与验证

开发机终端，工作目录 `F1-4242/`；检查本地原件，不连接机器人，报告写 `/tmp/f1-replay-inspect.json`：

```bash
python3 scripts/replay_episode.py /绝对路径/某条F710原件 \
  --start 0 --end 10 > /tmp/f1-replay-inspect.json
```

可加 `--profile /绝对路径/机器人配置.json` 核对配置绑定与静态轨迹限制。脚本只输出JSON，没有远程启动动作选项。现场执行统一走4242控制租约与明确的执行点击。

软件验证入口为 `python3 -m pytest -q tests/test_motion_replay.py` 与 `node scripts/check_motion_replay_browser.cjs`；浏览器脚本仅启动回环假API，不连接机器人，截图/报告在 `results/motion_replay_browser/`。软件验证不能替代目标ARM节拍和现场短片段验收。

`scripts/check_replay_timing.py <原件目录>` 用真实时序、内存假传输与墙钟做节拍演练；不加载ROS，不能代表DDS或硬件验收。

呈现入口为 `web/replay-report.js`，只使用后端已有指标。默认曲线展示「本次实测减原始实测」，保留正负方向；可切换两次轨迹叠加，移动指针或拖动时间游标查看实测值。灰色零线帮助辨认一致程度；颜色与柱状条不作为硬件合格阈值。完整表仍包含MAE、RMS、最大值与有效/采样点，夹爪以开度百分点单列。

## 2026-10-22 原始间隔误判修复

14:13:26的Full625 rollout共7,915条命令、38.784903秒，原件SHA/计数/序号与发布证据通过。仅在26.031938→26.058223秒有26.284843ms间隔，目标最大变化0.035766°；原逻辑沿用身体调姿25ms间隔预算，在预检和实际发送间隔两处拒绝整条。首轮版本区分原始时序与执行迟到，并补齐等待期间的持续检查以及最后一次发送阻塞检查；其25ms迟到即停止策略已由下节顺延策略替代。

25ms来源是本项目身体轨迹软件调度配置，不是已验证的手臂硬件看门狗阈值。现场运行控制器SHA与本项目既有驱动审计一致；审计能确认手臂位置目标调用路径，不能证明封闭SDK的所有保持/超时行为。本次不修改或绕过驱动校验，不新增目标、不伪造命令心跳。软件与ARM内存假传输验收、部署状态以[STATUS](STATUS.md)为准；真实动作留给现场用户执行。详细证据保存在私有`results/replay-timing-fix-20261022/`。

## 2026-10-22 连续执行与短时系统卡顿

现场127.647806秒录制在21.299秒中断：已发送5,131个事件，报告为调度迟到42.707660ms；此前平均下发迟到0.918ms、最大18.062ms。数据文件和执行均在F1本机，网页只发开始请求，后续不是逐帧经过电脑/6000D/H20。现有日志能定位应用调度迟到，不能进一步证明具体是OS调度、Python竞争或哪把锁阻塞。2026-10-23的[同机延迟排查](incidents/20261023-replay-latency.md)抓到模拟发送副本累积触发的GC停顿，但尚未证明历史现场同因；只读DDS测量未复现长锁等待。
