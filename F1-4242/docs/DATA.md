## 存储概览

DATA 录制库下方“存储与录制状态”默认折叠：展开显示金色 LXL、蓝色 DAgger 的容量与条数、系统及其他、剩余空间，单个圆柱展示整盘存储。LXL 包含旧 LXL、独立 Pico 原始录制和兼容的旧独立 LeRobot 录制；DAgger 包含人工示教与策略 HIL。按路径/身份去重，派生 `unified_dataset` 的训练片段不重复计条；“条数”不代表审核通过或训练就绪。容量使用十进制 GB（1GB=10⁹字节）。

分类容量是目录接口列出的录制文件逻辑大小，不是整个磁盘扫描：未索引目录、独立派生视频、缓存、模型资产或导出副本不自动加进原始录制分类。圆柱使用现有磁盘健康快照，按整盘真实比例显示，原始录制较小时色层也较薄。系统文件、派生数据、缓存和系统预留合并为灰色“系统及其他”，不算作可用空间；浅色部分为剩余空间。

沿用原有目录刷新与状态轮询，不新增磁盘扫描。读取失败/失联显示上次读取，部分目录失败显示部分统计；缺失的磁盘容量显示破折号。目录入口按LXL/DAgger组织；DAgger按人工示教/策略HIL浏览，历史根路径合并，详情保留真实存储路径。导出与原件未自动删除，上传策略不受此显示改动影响。

## 此版可以做什么

1. 自动发现现有 rosbag2 的 `metadata.yaml` / MCAP / DB3 目录；目录清单缓存 3 秒。
2. 从 rosbag metadata 读取开始时间、时长、消息数和 topic；文件 mtime 单独展示。
3. 展示已有三路抽帧预览：仅匹配相同原始目录和 metadata 哈希的样例才提供链接。
4. 为每条录制保存待审/通过/不通过及最多 4,000 字符备注；审核写到本工作台 runtime。
5. 观察现有 `ros2 bag record` 进程，不发布录制 UDP，不启停采集节点。

对原始目录仅列目录、stat 文件和读取有界 metadata，不读取全部大 MCAP、不回放、不改写、不移动。
发现路径中的符号链接时跳过，API 不接收任意文件路径。扫描深度最多 4 层，每次遍历限制 20,000 个条目；
这适合当前七条 LXL 数据，不是无限规模的数据湖索引。

首次确认的现有七条记录均为 2026-09-16。此版开发时再次通过 F1 SSH 只读确认七个 metadata 可解析，
实际 Python 环境已有 PyYAML 6.0.1；本次没有采集新数据。实时条数以页面为准。

## 审核与来源变化

`runtime/data_reviews/<episode-id>.json` 保存审核人、时间、结论、备注、metadata SHA 与 source_signature。
原始数据内容不写入此文件。source_signature 包含文件名、大小、mtime 与小型 metadata 哈希，成本低，便于目录刷新。
它只能发现这些来源特征变化，**不代表逐字节 MCAP 完整性校验**；同大小、同 mtime 的原始文件替换可能不被检测。

签名不一致时页面自动回到待审并保留 `previous_review`。只有再次明确审核才绑定新来源。
通过/不通过是内容审核意见；既不是自动清洗结论，也不等于 action/state 语义、图像解码、时间对齐或训练发布通过。
正式训练前分别核对原始数据完整性、三路图像可解码、时间对齐、state/action 语义和来源，再用目标训练 reader 回读；本包合同与待验收项见 [RECORDING](RECORDING.md)。原通用流程仅作为 [历史来源](history/SOURCES.md) 保留。

## 录制状态的含义

- `observed_active`：发现指向所配置数据目录的 `ros2 bag record` 命令；不证明 topic 实际写入或文件完整。
- `no_process_observed`：未发现这种进程；不宣称独立 SDK 或其他未知采集器也处于空闲。
- `unknown`：进程目录无法观察。

LXL bridge / Pico 进程存在不能作为“正在数采”的依据。
既有 LXL 观察接口 `control_enabled=false`；新 LeRobot 录制通过 `/api/recording/*` 独立控制，仍没有上传服务或默认服务器地址。

## 原图检查与存储副本

默认原图浏览逐次读取三路原始JPEG，最高5fps且受请求耗时限制，不是采集帧率；滑条定位、原始尺寸显示、1:1放大与原字节下载均可用。完整会话视频由服务器worker生成，ready后在折叠区提供三路MP4和曲线，明确为压缩副本；原始数据仍保留。视频采用30fps展示时间轴，对原始间隔的帧保持由timeline标记，不生成虚假的训练帧。

原件在机器人data或历史根目录；派生视频在工作台runtime/data_previews。worker的cache在处理时保存下载来源与渲染结果；F1确认发布成功后自动删除对应任务缓存，失败/未完成暂存以供重试。归档自动上传关闭不等于视频worker不传输来源；不得向用户声称所有数据仅存在机器人。LeRobot是数据格式，不是必然上传的远程平台；datasets保存本地转换产物。

接口沿用登录和同源校验，不取得动作控制权；采集/控制/录制服务运行时拒绝删除，视频有效租约或转换锁占用时也拒绝。整个选择预检来源签名、目录边界和身份；不接收客户端路径，不跟随符号链接，不删除数据根目录/含其他独立录制的父目录。r2允许录制目录内部正常缓存链接：只删除链接本身（包括目录链接、失效链接），不触碰目标；根路径及祖先路径含链接仍拒绝。批量中发生磁盘错误据实逐条返回；不是跨多个文件系统的原子事务。

删除意图、来源签名、结果与异常保存在 `runtime/data_deletions/<事务ID>.json`；先原子移动到同父目录 `.f1-delete-<事务ID>-<episodeID>`，再清理。中断遗留目录不会混入目录列表或训练转换，须依据审计记录人工处理；它不是用户可恢复的回收站。不会以隐藏卡片冒充磁盘清理成功。仅对显式确认的选择执行，测试使用临时假数据。
