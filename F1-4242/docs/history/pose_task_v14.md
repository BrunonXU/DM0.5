# 一份姿态，一个执行范围（v14）

2026-09-24。取代 v12“全身载入、按部位执行”的页面行为；旧接口保留兼容。

## 操作

姿态页只保留“调姿 / 移动”。调姿内左右臂并排，夹爪位于对应手臂下方；身体和头部可展开，身体 J4/J5 与工程说明折叠。升降、转身、侧倾和弯腰属于身体编辑。

所有编辑形成同一份待执行目标，切换视图不改变范围。载入预设替换旧目标；全身复位包含22轴，不隐式包含夹爪或底盘。顶部一直显示实际执行部位、预检错误或预计总用时。首次执行授权，之后保持红色操控模式，停止动作与退出操控分别提供。

右侧模型固定、取景放大，预设使用简洁列表，导出与删除放在每项“···”内。明确选择预设即载入；不启动动作。参数边界仍在输入约束中，去掉每行重复限位标签，反馈与目标各保留一个数字。技术JSON折叠在动作详情。

升降使用同源URDF相对高度；预览有错误或尚未完成时，不能执行上一份升降结果。升降与转身可合并；直接修改J3/J4/J5会替代升降意图。完成后清除该次已执行草稿，后续编辑从新鲜实测建立；被拒绝或中止则保留目标供检查，不自动续跑。

## 整套执行合同

新 `kind:pose` 接受具名关节 targets、左右 grippers 和可选 waist_delta_m。执行范围只取这些字段，绝不从当前页面或标签过滤。后端补齐所选机械臂/身体/头部的完整驱动向量，未指定轴用新鲜实测；所有部位完成限位、反馈、来源、模型地面与总预算检查后，才允许创建输出并开始。准备发布端之后再整套重算，发生状态变化拒绝本次任务。

所有参与部位使用同一五次进度和总时长，按最慢轴的固定速度/加速度限制求解；身体/头部200Hz，手臂/夹爪约30Hz，使用同一个绝对时钟，不启动相互独立的动作线程。身体的5ms循环不能每轮进行DDS图查询，仍使用既有命令监听缓存。总运动最多5.7秒，完整动作最多6秒，不自动串成多个六秒动作、不提速。相对升降沿原IK曲线按共同时间重采样，其他关节使用同一进度。

每个部位已经在既有到位误差内时，明确标记“已到位”，不向该部位发送微小重复动作。所有部位均到位时不创建发布端、不发送命令；返回 no_motion=true。运动后成功仍要求所有目标连续收到新鲜到位反馈，不能将请求受理或部分到位当整体成功。

中途任何必要反馈异常、外部命令冲突、身体节拍超时或总预算超时，都结束整次输出；只对已发送部位、在来源与反馈允许时补一次实测保持。结果记录各部位最后观察状态；未知反馈不保证已停稳。没有自动回滚或自动重试，网页停止不是硬件急停。旧接口 `joints` 的混合组拒绝策略保持，新协调逻辑仅走 pose。

## 检查边界

本次实现同步任务协调，没有实现任意姿态自动避障或通用复位顺序。地面检查仍只覆盖模型躯干/头部AABB路径采样；不覆盖手臂自碰撞、环境障碍与平衡。不同路径/头部标定/夹爪模型仍需现场核验。

F1-09当前头部J2约−27.64°，低于原驱动−25°且超出既有1°反馈容差，完整复位预检应整次拒绝，不得只执行双臂。深弯腰返回预设也可能超六秒预算。此版本没有改原限位或通过远程工具让其归位。

## v14：复位诊断与显式分段

GET `/api/pose/review` 使用同一快照逐部位检查，返回 `executable`、`issues`、合法的 `plan` 或建议 `segments`。与保留兼容的 `/api/pose/preview` 不同，预检失败可以成功返回诊断报告；`executable=false` 不可执行。实际 POST 仍走原完整预检与六秒预算，诊断不授予控制权。

仅当所有失败都为时长超限时，才在隔离的只读规划副本中验证完整路径，再按原真实预算验证每一段。关节目标沿同一关节空间线段等分，保持各部位与夹爪的完整范围；每段五次插补，两端速度和加速度为零。分段会增加总用时，不能视为整次六秒；六秒限制仍适用于每次明确点击的动作。相对高度 IK 目标不自动转成关节直线分段。

用户点击“查看 N 段目标”检查清单，点击“载入第 1 段”只更新模型和目标，仍需点击执行。到位后点击“载入下一段”，再执行。无后台串行动作或自动重试；重新编辑/重新对齐/载入其他预设/停止/失去租约/执行失败清除旧分段。每次执行重新取实测、校验范围、路径及来源，预览不是可跳过检查的执行令牌。

当前实机全身复位会同时报告头部起点约 −27.64° 超限和身体约 8.03 秒超预算；头部阻碍存在时不提供缺少头部的分段计划。身体单独目标在其余检查通过时可以分段。

### 头部回程的证据与未完成项

本机 `motor_ctl_node` 的 `loadJointLimits()` 硬编码 head_j2 的 −25/+25；0x4b0114 和 0x4b011c 写入限位表，对应 rodata 0x5f1a98 的 head_j2。函数没有读取 launch 限位参数；启动日志打印 Loaded fixed joint limits。`jointPositionCallback` 在 0x4a81bc 调用 `applyJointLimits`，之后 0x4a8600 调用 UDP setMotorAngle；低于下限的命令在 0x4b1008 被覆盖为下限。

因此从 −27.64° 发送逐步回程目标，驱动仍会将最初目标截为 −25°。不能通过放大反馈容差声称已完成平滑恢复，也不能将 launch 文件等同硬件机械极限。原生恢复接口/标定方式仍待核验；本轮没有放开这个限制。证据在 `results/reset_recovery_20260924/driver-*.asm`，并记录本机二进制哈希。
