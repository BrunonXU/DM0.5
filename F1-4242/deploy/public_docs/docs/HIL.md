# 手柄示教与 DAgger 接入

需要手柄遥操、人工示教或策略纠正时再接入本模块。使用 Pico 不需要配置 DAgger。

工作台提供路线指引、状态与数据入口；DAgger 机器人运行端、Windows sender 和策略模型服务需要独立准备。初始化选择 `dagger` 不会安装这些组件，也不会自动绑定模型或启动运行端。

## 部署人员配置

| 位置 | 配置内容 |
| --- | --- |
| `runtime/hil.json` | 运行目录、启动器、机器人 SSH 地址、原件数据目录；字段参考 `configs/hil.example.json` |
| `runtime/hil-routes.json` | `play`、`demonstration`、`policy` 对应的启动器、会话配置与路线信息 |
| 各路线 session JSON | 与外部运行端匹配的 `f1_hil_session_v1` 配置：用途、任务及策略端点 |
| 外部运行端与 sender | 配套版本、控制映射、连接端口、机器人合同与本机路径 |

机器人运行端的 `--data-root` 与工作台读取的 `data_root` 保持一致。自由接入不保存训练图像；人工示教保存原件；策略 HIL 还需匹配的模型端点与观测 / 动作合同。未绑定模型时，策略运行入口保持不可用。

路径、SSH 用户和 IP 使用各自机器的实际配置。工作台根据后端配置显示启动命令；不要把另一台机器的启动命令直接复制为本机配置。

## 三个终端

打开手柄页，选择需要的路线，在“连接与启动”中使用当前路线生成的三条命令：

| 终端 | 在哪里打开 | 执行什么 |
| --- | --- | --- |
| 隧道 | Windows PowerShell | 页面给出的 SSH 隧道命令，连接到自己的机器人 |
| sender | Windows PowerShell | 页面给出的手柄 sender 命令，使用与运行端匹配的版本 |
| 机器人运行端 | 机器人现场终端 | 页面给出的 F1 运行端命令，完成该运行端要求的现场确认 |

三个进程运行后，检查页面接收确认、手柄输入、机器人反馈与当前路线。SSH 连接成功只证明网络隧道建立，不代表输入已到达或机器人已跟随。页面切换路线只切换指引，不启动进程。

## 开始与结束

按已安装 sender / 运行端的配套手柄说明操作；先确认页面显示的模式与本次用途一致。分条录制协议由外部运行端版本决定，不混用不同版本按键表。

停止整套流程使用页面支持的结束入口，或在原机器人运行终端按一次 `Ctrl+C` 并等待整理结束。关闭 sender 或网页不等于原件已经保存。来源原件、视频派生、人工审核与训练导出分别处理，见 [统一数据](UNIFIED_DATA.md)。
