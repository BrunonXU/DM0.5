# Why&How 维护入口

这里维护6000D上的教学网页和Markdown阅读站。用户固定使用4243端口，页面部署在`/home/user/Artifacts/Why&How`；开发源位于`/home/user/Tools/WhyHow`，文章原件仍在所属任务维护。

新增讲解时同时登记交互HTML或Markdown到目录，优先让用户直接打开阅读链接。页面只读，不提供训练、机器人控制或任意系统文件访问。

## 固定约定

- 遵循[Projects根AGENTS](../../AGENTS.md)；只做桌面版。
- 全站沿用2026-10-20用户确认的阅读风格：近白背景、深色无衬线正文、清晰粗体标题、宽松段落和少量陶土色强调。正文默认22px，可切换20/24px；文章目录使用左侧抽屉，章节导航保持轻量。
- 风格覆盖Markdown、交互HTML、工具栏、目录、加载/错误提示和图片弹窗，不只改单篇文章。交互页的数据状态颜色仍需可区分。
- 交互HTML通过服务端附加`web/interactive.css`统一样式，不为了展示改写任务原件的数据或脚本；新增讲解应复用此主题并检查iframe与独立窗口。
- 固定服务端口4243，systemd用户服务`why-how.service`。预览可临时18443，不能把临时端口登记为正式入口。
- `catalog.json`维护用户可见目录；Markdown读取所属任务原件，刷新即反映修改，不维护第二份冲突正文。
- 扩展到其他任务时显式补`server.py`的文档范围及目录项，不开放整个HOME或服务器根目录。
- 保留本地Mermaid固定版本与许可证；浏览器不依赖外部CDN。
- 更新源文件后只发布本项目文件到指定Artifacts目录；不扫描或覆盖其他Artifacts。
- 网页可以独立部署；4242入口属于F1-4242，遵循其候选图确认和定向发布规则。
- 验收实际浏览器中的文档、表格、代码、图片、Mermaid、目录跳转、交互HTML和后退/前进；不要把HTTP200当成全部UI通过。
