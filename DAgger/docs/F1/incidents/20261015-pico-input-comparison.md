## 本机30Hz和输入更新的关系

只读现存9条示教`journal/observations.jsonl`，共10312组。按每条首末`available_monotonic_ns`计算，三图组平均29.676–29.981Hz；汇总10303个间隔/344.396秒约29.916Hz。各条间隔P99约41.1–58.0ms，最大间隔147.9–399.7ms；这是观测组完成的时间，不是单相机曝光间隔，也未证明与手柄延迟同因。

`F1/src/f1dagger/policy.py:_capture_loop`独立线程按30Hz网格采真实三图和状态，不等每个手柄包才采一组。输入迟到本身不要求降低采集频率，但当前保护调用episodes.finish确实会停止落盘；共享CPU/回调/网络堵塞还可能同时影响两条链路。30Hz仍可能记录迟到动作、停顿、补偿与过冲，所以正常帧率不等于专家动作质量正常。state必须是反馈，action必须是实际发布，不能用摇杆输入或反馈回填替代。

## meaxiao1.4.4：失鲜保持、释放恢复、录制分离

来源：[固定快照README](../../../../F1/reference/20260923_pico_comparison/files/meaxiao/README.md)。

| 环节 | 判据 | 行为 |
|---|---|---|
| XR源输入 | 源时间戳250ms未变化，或位姿/时钟异常 | 保持、清参考；普通停顿需至少3次新时间戳、控制全部释放且稳定200ms，再握Grip |
| 手臂输出 | 批准目标150ms没更新，或输出循环间隔>50ms | 清待发目标、保持；活动输入不能直接解锁，释放且稳定后待命 |
| 录制 | 独立检查相机/state/action有效性 | XR保持不直接停录；有效采集停滞>2秒、时钟/编码等故障才隔离保留 |

源码为`src/pico_f1/xr_readiness.py:14–56`、`arm_output.py:14–102`、`vendor/f1_bridge/lerobot_recorder.py:489–505,746–753,797–841,975–999`。规划失败/时钟倒退等特殊故障仍需检查后明确恢复，不能当普通短抖动解锁。

上游录制为独立进程：X双击开始、Y双击结束、B确认保存，X+Y复位不结束录制。偶发源图gap>55ms写quality_gaps继续任务，保存时隔离recovery，不冒充无缺口训练集。55ms是相机质量标记，2秒是持续采集停滞，均不是允许机器人继续旧动作的时长。

原UDP帧无发送时间/序号，收到后的本机时间不能证明源输入新鲜度。本地上肢适配`F1-4242/integrations/pico_upper/src/pico_upper/bridge.py`每轮最多读64包取最新，但只在127.0.0.1使用，不能照搬为Windows跨Wi-Fi完整协议。本地适配禁用了原生录制/ABXY，4242录制为另一模块，不能混成一个部署。也不能复用上游action缺失时以state回填的逻辑（lerobot_recorder.py:683–704,731–735）；我们的实际发布证据必须保留。

## 上游历史延迟数字的含义

快照README记载：106–110行，D070关闭Wi-Fi省电、清旧PCService后90秒仍17次输入更新间隔>250ms，原文明确未修复；129–130行，20°/s合成匀速测试输出层等效滞后270→195ms；70–75行，位置滤波模拟等效滞后慢速41ms/快速6ms；874–875行，180秒试录5394组、29.969Hz。

这些分别是输入停顿的历史陈述、两种单层模拟和录制频率，**均不是本机端到端延迟**。引用的原始reports未包含在快照，不能本轮重算或与F710故障率直接对比。没有证据证明Pico整体延迟更低。XRoboToolkit[官方协议](https://github.com/XR-Robotics/XRoboToolkit-PC-Service/blob/main/README-CN.md)虽包含源timeStampNs字段，也不能据字段存在就认定本地时钟映射/完整计时已做好。

## 后续顺序及验收

1. 优先解除控制暂停与录制结束的耦合。普通同会话输入失鲜停止使用旧意图、清旧目标/Home，原始episode保持并记input_gap_begin/end。新鲜输入、反馈及保护条件满足，操作者释放后重新按RB继续；不每次START，也不持续按RB后突然恢复追赶。START保持明确录制开始/结束语义，重连/换session及硬故障分别处理。
2. 暂保留200ms动作失鲜门槛，不用它决定录制结束。不能因为meaxiao250ms就抄数，其输出还有150/50ms检查。F710摇杆为持续方向/速度意图，旧值参与积分会继续走；LXL桥输入为绝对关节目标，行为不同。调整门槛须结合速度、停距、尾延迟和现场验证。
3. 原始材料保留、有效段训练。区分有任务意义的人工保持与网络异常保持；训练窗口不跨输入异常/恢复边界，前后分别审核，部分技能不冒称完整任务成功。证据不足区段保守排除，不补造帧或动作。
4. 做轻量分段计时，暂不重做传输协议。sender已有异步发送、单槽最新值、TCP_NODELAY；补Windows采样/发送、F1接收/消费/发布、ACK的同seq关联，有界统计和后台汇总。分别看RTT、本机排队/调度、活动期失鲜次数和暂停时长，不拿包间隔代替时延。
5. 根据瓶颈选择优化。网络/隧道问题做同负载链路对照；接收/ACK写阻塞或调度问题修对应环节。暂不盲目换UDP、扩大超时或提高采集频率；保留按钮可靠传递、旧包隔离和重新授权。
6. 当前平均观测频率支持继续受监测采集与审核，但频繁切录须在规模化前修。先无动作验证断流/迟到包/持续RB/释放RB/重连/Home/相机及写盘故障，再现场验证可恢复、整条保存、真实30Hz间隔与写盘无持续积压。不是承诺零网络抖动或零丢帧。
