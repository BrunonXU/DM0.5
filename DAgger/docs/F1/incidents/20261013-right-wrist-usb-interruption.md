**2026-10-28补证：同一只右腕相机再次出现USB传输错误、持续断流及重新枚举。** 重新连接后已恢复约30Hz。随后按用户授权尝试USB3对照，双腕各定向复位一次后仍为USB2；恢复检查正常，真正的USB3收益尚未测得，见[对照尝试](#usb3-comparison-20261028)。线缆、接头或供电的根因及运动中长期稳定性仍未确认。

## 直接证据

北京时间16:24:00，F1内核在`uvcvideo 1-2:1.1 / 1.3`连续报告`Non-zero status (-71) in video completion handler`。右腕RealSense节点350814随后持续报告`Frames didn't arrived within 5 seconds`。USB 1-2映射为Intel RealSense D405，驱动恢复时确认序列号260322276040。

同一时刻采集诊断最后回调ID为头3100、左3092、右3031，最后已消费为3038/3032/3031；右路队列为空，头/左仍有新图，但无法配出三路。输入包年龄6.8ms，写盘队列为空、writer_error=null、drop_count=0；不存在将此次归因为提示音或磁盘写满的证据。两秒相机等待到期触发`three new synchronized camera frames unavailable`，旧v21采集线程永久结束，主循环再因acquisition_error退出。

旧收尾把任何运行异常统一传成status=failed。payload/journal的close按合同不提交failed目录，返回False又被包装成两条`episode writer did not commit`。因此表面像两次磁盘失败，实际638组已持久化、无写盘错误，是运行中断与保存状态混用。

用户重新插接后，16:27:12 USB断开、16:27:16重新枚举，右腕驱动自动重建，Color/Depth均640×480@30，节点恢复Up；后续真实观测shadow成功取得三路图像。两只D405当前均协商480Mbps，尚未确认根因是线材、接头、供电、端口还是设备本身；不能将USB速度直接认定为本次故障原因，也不能声称重插已证明长时间稳定。

## 2026-10-28复发补证：USB断流后短窗恢复

### 现场证据与时序

以下时间均为北京时间。右腕仍为D405、序列号`260322276040`、USB路径`1-2`；其ROS驱动PID为`56399`，恢复前后保持同一进程。

| 时间 | 只读核对结果 |
|---|---|
| 09:50:05启动 | 驱动已报告USB type `2.1`，同一序列号，Color `BGR8`与Depth `Z16`均为`640×480@30` |
| 13:22:54 | 内核在`uvcvideo 1-2:1.1 / 1.3`共报告10次`Non-zero status (-71) in video completion handler` |
| 随后至13:47 | 右腕驱动日志持续出现`Frames didn't arrived within 5 seconds`及`Frames Timeout`，相机节点进程存活并不等于仍有新图 |
| 13:47:09 → 13:47:14 | 内核记录`USB disconnect, device number 3`，5秒后以`new high-speed USB device number 7`重新枚举；设备号改变，同一序列号相机恢复 |
| 恢复后 | 驱动报告USB type `2.1`，Color `BGR8`与Depth `Z16`均为`640×480@30`；内核识别仍为UVC 1.50 |

两腕实时USB速率均为`480Mbps`，sysfs版本为`2.10`。同一驱动的09:50启动与13:47恢复日志确认，**今天重连前后USB类型、序列号、分辨率、格式及配置帧率相同，没有发生从USB3降为USB2的变化**；10月13日及更早也已有480Mbps证据。重新枚举可能改变设备号，不表示相机上层协议或模型输入合同被改写。仅凭`-71`或480Mbps不能在松线、接头、供电、端口与设备故障之间定因。

完整进程日志共有580条`Frames Timeout`警告，第一条为13:22:59，最后一条为13:47:05；彩色／深度重复报错不能换算为580张丢帧。启动与重连字段、首末超时摘录见证据目录中的`driver-history.json`。

13:18发生的手臂—躯干碰撞保护早于13:22:54这组相机错误，**不能将该碰撞归因于这组USB日志**；碰撞诊断和现场姿态恢复继续按[对应报告](../../../../tasks/F1_ComplexyToys/inference/experiments/20261027-rlt-local-v2.md#protection-20261028)处理。

### 对数采、推理的影响与下一步

- **数采：** 当前采集要求三路真实新回调配对。短时断流会减少有效观测、造成时间缺口，严重时触发缺图保护并保存中断前缀；相机恢复不自动把中断条变为完整成功示教。采集层记录实际丢弃与不连续标志，导出按断点切窗口，不用旧图补成30Hz。
- **推理：** 右腕是当前模型有效输入。相机延迟、断流会让模型等待或使用年龄更大的合格观测，进一步触及时效或计划耗尽保护；没有证据表明本次直接拖慢GPU模型计算。现有相机接收龄200ms、三图接收偏差100ms与2秒配图等待分别约束不同环节，不应将“2秒缺图检测”解释成允许无限复用旧帧或松线瞬间已停止。
- **现场连接处理：** 在任务停止、姿态安全后检查并固定相机端与主机端插头，让线缆留出运动余量、由固定点承担拉力；接头仍松或反复断流时，替换适配的可靠数据线，按线材、端口逐一对照。随后复核速率、实际图像尺寸／帧率、连续新帧与内核错误；长期及运动中稳定性仍需现场验证。

当前参数与机制可核对[推理装配登记](../../../../tasks/F1_ComplexyToys/configs/inference_runtime_f1_09.json)、[采集代码](../../../F1/src/f1dagger/observation.py)、[相机中断处理](../../../F1/src/f1dagger/policy.py)及[导出断点处理](../../../F1/src/f1dagger/export.py)。代码链接指开发源码，本次未重新部署；软件保护不能代替修复不稳定的物理连接。
