在随机127.0.0.1端口启动独立v20 IntentServer，1000个中性包、50Hz约20秒：ACK p50=0.309ms、p95=0.642ms、p99=0.921ms、max=1.353ms。无ROS/动作模块导入，不连接生产7906，不创建输出；仅为空闲本机协议短测，不覆盖Windows/SSH/Wi-Fi或实际控制负载。结果 `artifacts/results/20261013-hold-review/loopback-idle.json`。

用户希望短时抖动保持等待而非反复START。建议分离“超时停止输出”和“撤销人工接管”：短暂同会话输入间断停住并清空旧目标，恢复必须通过新鲜输入/当前意图及硬件检查；真实断线、换session和硬故障仍需明确恢复授权。此项仅讨论，未放宽200ms保护、500ms ACK重连或实现自动恢复；须防积压包冒充新鲜输入，并先验证断流/旧包/重连等无动作场景。

## 2026-10-13 反复 START 只读排查

用户报告“碰限后需要重新START”，已交叉核对F1原始日志与用户提供的Windows sender日志。最近实际运行是10-12 16:07北京时间开始的 `f1_hil_20261012T080712Z_5437f8ea`，release v19、purpose=teleop_play；不是v20新人工示教会话。新demonstration目录尚无记录。本次未更换运行版本或修改保护。

最新会话没有target_rejected/publication_failed/arm_boundary_hold事件；30条safe_hold_entered包含7次断连、2次Broken pipe、6次输入watchdog、3次发布前watchdog、5次换session和7次故障后的使能包拒绝，并非30次独立限位。9次hold_to_hil恢复。control记录最大间隔23.124ms；Windows同段采样最大32ms，ACK达到300–450ms后又出现500ms超时重连。16:09:02附近同session相邻包2481→2482，发送时间戳差22.80ms、F1控制线程看到包的间隔204.16ms，支持输入交付延迟而非手柄采样卡顿；接收快照/线程、SSH/Wi-Fi各段尚未独立归因，ACK RTT不冒充单向网络延迟。

前一会话 `f1_hil_20261012T072708Z_3fd390d3`（v18、自由接入）含2次右arm_R_Link5与body_Link5模型碰撞拒绝，报告clearance -0.0022m/-0.0020m；其余还有断连、watchdog及连带门控。该距离为模型判断，不是实物接触测量。v15到v19的teleop.py差异仅公共包导入/类名迁移，robot_io.py逐字节相同；普通关节/耦合腕部可恢复边界仍保留，碰撞和真实失联此前一直锁存保护，不能概括成旧软限位修复失效。

10-13只读无线现状：wlan0接example-wifi、信号约-36dBm、power_save=on，同phy另有ap0在不同信道。它们仅为后续对照项，不足以推断10-12掉顿根因，未关闭接口或修改网络。优先补齐链路分段延迟证据；碰撞候选拒绝与已执行/反馈异常需分别设计，不能放宽碰撞检查或延长watchdog作为修复。原始会话未改；机器汇总与包间隔证据在 `artifacts/results/20261013-hold-review/`。


## Windows 日志的独立证据

用户提供的 sender 日志覆盖 2026-10-12 16:08–16:10：采样 p50=16ms、p99/max=32ms；同一 generation=9 内多次 SAFE_HOLD，说明不必发生 TCP 重连也会触发 F1 200ms 输入失鲜保护。16:10:33.732 最老待确认包516ms，超过500ms后重连至 generation=10；随后又有重连。ACK正常时仍可能有过短时输入间断，恢复后的 ACK 不会自动解除锁存。

16:10:35 START 重进人工，16:10:36 再次 START 又进入 manual_hold，之后仅反复按 RB 无法进入人工；16:10:39 START 才重新接管。这解释了部分“按键无效”的体验，但不解释最初的交付延迟。

## 尚未证明的部分

- ACK往返延迟不能定位为 Wi-Fi 单向延迟；接收快照也不是逐包抓包。
- 当前无线省电/同 PHY AP 是候选因素，不是已经确认的根因。
- 空闲本机 loopback 良好不能排除生产接收线程、磁盘、调度或 SSH/Wi-Fi 的负载抖动。
- 不把事件总数当作独立故障次数，不把模型碰撞距离当作物理触碰距离。

## 恢复工作的建议顺序（尚未实施）

1. 同一请求身份关联 sender采样/发送、F1接收/控制读取、ACK发送/接收；保留有界统计，区分各段耗时及旧包积压。
2. 经用户重新安排现场验证后，比较相同操作和网络条件下的预览开/关及有线/无线，保持采集30Hz和现有保护。
3. 设计“短时停止输出”与“撤销人工接管”分离：同会话瞬断先保持、清旧目标；新鲜输入和当前操作意图满足条件后可免 START 恢复。真实断线、换会话及硬故障单独处理。
4. 无动作测试必须覆盖迟到/重复包、旧 ACK、持续按 RB、松 RB、重连、相机失鲜和 Home；再安排现场验收。

单独增大 watchdog 会延长旧操作意图仍能影响输出的窗口；单独增大 ACK 超时也不会消除 F1 输入失鲜。没有证据支持直接把边界调大作为修复。
