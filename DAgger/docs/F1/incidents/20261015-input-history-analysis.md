## 范围与方法

按用户要求讨论和只读统计，不修改运行端、不改watchdog、不发动作、不做新的主动链路或负载测试。机器人以nice19读取事件/manifest及控制台，不读取相机pack或运行重编码。

遍历F1实际原始目录`/home/user/Bruno/data`、`/home/user/Bruno/DAgger-runtime/f1-09`：找到27份journal/journal.partial；加上上一轮保存的10月15日三条事件证据（本轮现存目录中已无此三条），合计30份。按inode去重，不重复计派生v3数据。22份具有可统计的相邻accepted operator_packet，25份manifest明确powered，shadow/空记录没有纳入有效间隔。包括旧版自由接入及未完成原始记录，不能称22条训练合格示教。Pico没有F710报文，不能混入F710统计。未保留日志的已删除记录不可恢复，故不是历史全量、无偏故障率样本。

同一记录、同一sender session、递增sequence的accepted消费事件才组成一个样本。换session不跨接；相邻消费事件可跨过被latest槽覆盖的报文，不要求sequence差1。统计111816对，按每对加权，分位数线性插值。记录内首末已消费包时间跨度合计2676.84秒（44.61分钟），不是有效运动时长或所有采集时间。

## 为什么现在没有可靠的平均端到端延迟

- `operator_packet.monotonic_ns`：控制线程消费时间，非网络接收时间。源码`shared/src/dagger_core/hil_network_shadow.py`由上层传入now；接收时间另由`F1/src/f1dagger/network.py`的latest保存。
- `packet_age_ms`：F1当时距最近网络接收的年龄。运行状态按变化和最长5秒汇报，样本有偏，不能平均后称全程延迟。
- `sent_at_unix_ns`：Windows墙钟；尚无同轮时钟偏差/误差界限，不能与F1单调时钟或墙钟直接相减。单向延迟的时钟同步误差会进入测量误差，参见[IETF RFC7679](https://www.rfc-editor.org/info/rfc7679/)。
- Windows ACK RTT在Windows单调时钟域可测，但机器人数据集未保存逐包往返样本。用户此前10月12日日志的滑动窗口p50约63–93ms，p95最高约297ms、p99最高约406ms、已收到ACK的max约454ms；516ms是最老未确认包超时，不是收到ACK的RTT。不能平均滑动窗口分位数作为总体平均，也不能将10月12日数据代表本次10月15日。
- ACK由网络线程发出，只代表接收协议处理，不证明物理动作或到位。镜头至屏幕、F710硬件无线、机器人跟随延迟也不包含在此次消费间隔指标里。

## 对控制与训练分别判断

当前证据说明常态更新可持续，但突发等待已反复中断操作，不能在规模化前宣布影响很小。200ms意味着在30Hz时间轴上跨约6个采集周期，并不证明相机同时丢了6帧。

停止运动与终止录制应分开。保持现有新鲜度保护是因为迟到期间旧摇杆意图可能继续用于生成动作；简单增加到500ms不是纯粹“多等300ms”。用户希望的等待应当是停住、清旧目标、保留本条记录、等明确的新鲜意图再恢复。

网络中断不使此前整条作废。现有`F1/src/f1dagger/export.py:select_segments`已筛选人工来源/完整发布，以真实反馈作state、实际submitted作action，并在Home、SAFE_HOLD、epoch/intervention和相机/时间缺口处分段。统一v3的`F1-4242/recording/unified/adapters.py`复用该入口，writer的review含outcome与accepted_segments。已完整提交的中断前有效段可以审核后利用；真正partial/损坏记录需先恢复审计。

仍有缺口：超时前沿用旧输入的部分仍可能标为人工，现有筛选未显式按输入失鲜/恢复段屏蔽。需要输入时间证据及质量边界，不能声称现有导出已彻底处理。正常人为松RB等待可有任务意义，不能把全部human_hold删除。暂停前后不直接拼成时间连续轨迹；训练action chunk不得跨暂停/恢复边界，使用独立训练episode或模型适配的有效mask。一个合法部分技能片段也不等同一次成功任务。

LeRobot v3通过episode元数据描述边界，并可在同一物理Parquet/MP4容纳多个episode；文件统一不要求所有原始采集是一段无中断轨迹。[官方格式说明](https://huggingface.co/docs/lerobot/lerobot-dataset-v3)。训练器是否读取自定义mask需单独验证，不能只写mask字段就认为已经屏蔽损失。

## 建议顺序（未实施）

1. 修录制生命周期与提示：普通输入超时进入输入等待、停止运动并清旧目标/Home；同一原始录制保留，记input_gap_begin/end及质量状态，不播放完成音。用户明确结束、进程结束或不可恢复故障才收尾；异常收尾保留可恢复前缀并标明原因。
2. 恢复语义明确化：同session短暂停顿可采用释放RB→已验证的新鲜中性输入→重新按RB，免重复START但不在一直按住RB时突然恢复。真实重连/换session和反馈/碰撞/驱动异常分别处理。递增sequence的TCP积压旧包仍可能很旧，需要握手/时效证明；不能仅靠本地收到时间判定源输入新鲜。START对录制的开始/结束含义必须保持明确。
3. 在正常采集时加轻量、有界统计：Windows采样/发送、F1接收/消费/发布、ACK发送/接收以session+seq关联；同机耗时和RTT先测，时钟误差有界后再报单向延迟。统计均值与P50/P95/P99/max、活动期输入断档次数/分钟、暂停时长和可用片段比例。
4. 无动作故障注入先验证迟到包、长短断流、持续RB、松RB、重连、Home取消、相机/写盘异常；现场另约，按同工作负载做Wi-Fi/有线或预览开关单变量对照。无需先给F1跑吞吐压力测试。
5. 预处理按连续有效段导出、保留来源和异常边界，逐段审核；先统计实际有效段和坏段比例再评价规模化质量，不臆测数据损失比例。
