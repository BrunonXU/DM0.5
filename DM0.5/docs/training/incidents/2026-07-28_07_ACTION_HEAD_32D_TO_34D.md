# 官方32D base适配G2 34D时权重可能丢失或截断

| 快速摘要 | 内容 |
|---|---|
| 遇到什么 | 直接以34D配置加载32D base可能重建整个action projection，其他路径还可能截掉最后2维 |
| 影响 | 32维预训练知识丢失，或第33/34维看似存在但从不训练/输出 |
| 根因 | checkpoint tensor shape与目标模块shape不一致；padding、保存和推理合同未端到端统一 |
| 如何解决 | 先按32D加载并保留权重，再扩展2维、初始化新增部分、加载LoRA，并全链路检查34D |
| 当前状态 | 权重保持、梯度、保存/恢复和推理合同测试已建立 |

## 第一性根因

模型层由tensor形状定义。配置写 `action_dim=34` 并不自动说明如何把已有32行/列映射到34维；默认构造器可能只能认为shape不兼容并随机重建。正确迁移必须显式定义嵌入映射：原32维是身份拷贝，新2维按初始化规则加入。

同样，任何一段 `PadAction(32)` 或输出slice都足以让末两维静默消失。因此维度合同必须跨dataset、model、loss、checkpoint和inference验证，而非只看模型配置。
