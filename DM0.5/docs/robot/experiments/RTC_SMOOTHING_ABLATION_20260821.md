# RTC轨迹平滑消融与实施方案（2026-08-21）

## 结论

最新完整Split RTC的模型效果已经可用，当前主要问题不是推理延迟或C0位置接缝，而是：

1. 30Hz waypoint线性插值到100Hz会在每个waypoint改变速度；
2. RTC已经做C1，Servo仍在每次切换套120ms“从静止anchor起步”的blend，重复处理反而
   压低入口速度后再恢复；
3. 双手5Hz且关闭V1，单次命令跨度可到0.425rad。

推荐并已实现的候选是：`d=16,s=20`、suffix jerk weight 10、双臂RTC入口速度约束的
C1三次Hermite插值、稳态RTC blend 0ms、双手`rtc_cap_v2`边界/内部单步上限
0.15/0.30rad。bootstrap仍保留原120ms blend；普通Sync默认仍是linear，不被本实验
无意改变。

## 数据范围与限制

主数据为`g2_powered_rtc_100s_20260821_120248.jsonl`，含39个完整action chunk、38次
RTC切换和逐段实际下发统计。鲁棒性复核还使用三份2026-08-20 arms-only RTC日志。

离线回放会递归重建每个候选自己的committed trajectory，包含RTC C0、suffix C1、
jerk正则、30Hz到100Hz采样和切换前3个100Hz历史样本。它可以比较确定性后处理，
但不能从日志重跑不同`s`的RTC模型条件，因为日志没有保存同步三图；因此本轮没有用
伪造的`s=25`结果替代真实模型A/B。

## 第一性原理

位置连续不等于运动连续。C0只要求切换点位置相同；C1进一步要求切换点速度相同；
肉眼可见的顿挫还受加速度和jerk影响。

原来的30Hz线性插值在每个区间内速度恒定，到下一个waypoint瞬间换成另一速度。即使
30Hz waypoint已被jerk正则平滑，100Hz目标仍会周期性换挡。三次Hermite使用每个
waypoint共享的切线，令相邻区间在waypoint处速度连续。

RTC入口不能只使用普通居中切线：新旧chunk各自估计会产生不同入口速度。实现因此从
旧committed trajectory的切换点取切线，一方面作为suffix平滑的C1条件，另一方面显式
覆盖新Servo段的首点切线，使生成约束和下发插值使用同一个速度。

旧120ms blend适合独立Sync chunk从实测状态柔和起步，却不适合已有C0/C1 committed
prefix的RTC稳态切换。它把首段运动乘以从0开始的smoothstep，相当于每0.667秒人为减速
再恢复。RTC稳态将其关闭；bootstrap没有旧计划，仍保留。

## 真机验证判据

先运行10秒而不是直接100秒。日志应满足：

1. `runtime_start.arm_interpolation_profile=cubic_hermite`；
2. bootstrap的`dispatch_summary.blend_seconds=0.12`，后续RTC段均为0；
3. `rtc_switch`双臂/双手seam继续为0；
4. 双臂`arm_nominal_max_jerk_rad_s3`的P95相对最新13247显著下降；
5. 手部boundary first delta不超过0.15rad、内部单步不超过0.30rad；
6. 人眼确认不再周期性减速再恢复，同时右手仍能完成抓紧。

第4项若没有同步下降，优先检查真实100Hz调度相位与telemetry算法，不直接继续增加
weight。第6项若抓握变弱，先把边界cap从0.15调至0.20，不恢复会改变时序的V1。

## 首轮真机结果（2026-08-21 13:40）

日志`g2_powered_rtc_100s_20260821_134025.jsonl`确认实际运行的是推荐配置：
`cubic_hermite`、稳态blend 0、`rtc_cap_v2` 0.15/0.30rad、d16/s20和suffix
jerk weight 10。共得到17次RTC切换；操作者因手指接近碰撞主动结束动作，但程序随后
记录的直接停止原因是第18次请求错过RTC窗口（实际延迟42步，高于可接受的30步）。

把16个完整稳态段与8月21日旧配置的98个稳态段比较：

| 实际下发指标 | 旧linear+120ms | 新cubic+0ms | 变化 |
|---|---:|---:|---:|
| 双臂每段delta P95均值 | 0.005185rad | 0.004111rad | -20.7% |
| 双臂每段最大delta均值 | 0.006160rad | 0.005498rad | -10.7% |
| nominal加速度最大值P95 | 81.20rad/s² | 63.52rad/s² | -21.8% |
| nominal jerk最大值P95 | 12948rad/s³ | 11288rad/s³ | -12.8% |
| 双手边界/内部最大步长 | 未限制 | 0.15/0.30rad | 命中设计上限 |

结论是方向正确、真机体感也更丝滑，但离线预测的约80% jerk下降没有在旧的真机
`nominal`指标上兑现。不能据此立即断言三次插值失效，因为该指标把实际命令当成严格
100Hz等间隔后求差分；本次发送间隔P95约11.66ms，单段最大值最高20.31ms。目标位置
曲线和Linux/GDK下发时序因此被混在同一个高阶差分里，而真实机器人也确实会受到这种
时序抖动影响。

为分离两者，下一版telemetry同时记录Powered RTC的完整双臂目标及实际发送时间，并
新增按真实时间间隔计算的速度、加速度和jerk。`rtc_schedule_missed`也补记完整HTTP/
服务端分段耗时，以判断第18次约1.39秒延迟发生在图像编码、请求解析、排队还是模型。
下一步只需再跑一次约10秒：若目标轨迹按真实时间仍平滑而发送间隔存在尖峰，优化重点
转向100Hz调度；若实际时间导数在间隔正常时仍出现尖峰，再回到Hermite切线和suffix
约束本身。此时不应仅凭nominal jerk继续提高weight。

## 与8月初最后三次真机的体感对照

按文件时间线，8月初最后一批是8月5日14:07、14:09和16:04三次Powered Sync，
之后到8月17日才重新开始。三次旧日志合计118个完整segment；最新RTC取16个完整稳态
segment。两者控制语义不同（旧Sync每段120ms blend，新RTC连续C1且稳态blend 0），
但它们正好对应操作者所说的“以前手感”和“现在手感”。

| 指标（每段均值，另注明者除外） | 8月5日末三次 | 最新RTC | 解释 |
|---|---:|---:|---|
| chunk边界首步 | 0.000122rad | 0.000823rad | 新版约6.7倍，但绝对值仍小；能解释边界小跳 |
| chunk内delta P50 | 0.002172rad | 0.002421rad | 新版+11.5%；典型小步更明显 |
| chunk内delta P95 | 0.004856rad | 0.004111rad | 新版-15.3%；较大抖动反而减少 |
| chunk内最大delta | 0.006611rad | 0.005498rad | 新版-16.8%；峰值减少 |
| 发送间隔P95 | 11.02ms | 11.66ms | 新版+5.8%；100Hz节拍更散 |
| 单段最大发送间隔均值 | 13.49ms | 15.46ms | 新版+14.6%，最新最坏20.31ms |
| 已完成请求延迟P50/P95 | 372/551ms | 276/326ms | RTC推理明显更快 |

所以操作者的两个观察都与日志一致。边界跳动变大来自关闭120ms blend：旧版每个独立
chunk都从近零速度重新ease-in，因此首步非常小；新版为了不周期性刹车，保留旧轨迹
入口速度，首步自然不再接近零。chunk内部并非整体变差：大步和峰值下降，但典型步长
略升，同时100Hz发送间隔尾部变差；视觉上可能表现为持续的细碎运动而不是旧版“停一下
再动、偶尔大跳”。是否主要由调度抖动造成，需要下一份带真实时间导数和完整arm trace
的日志确认。

## 第二轮算法消融：C2全局三次样条

当前`cubic_hermite`用相邻三点估计每个waypoint切线，保证位置和速度连续（C1），但
相邻区间的加速度一般不相等。针对chunk内部仍有细碎感，新增`cubic_spline`候选：RTC
入口速度继续钳制为旧committed速度，后续所有切线用三对角方程一次联合求解，使内部
30Hz waypoint的加速度连续（C2）；末端采用自然边界。运行时用O(N) Thomas算法，
不依赖SciPy或不确定的BLAS耗时。

三份旧RTC日志共101次切换的递归回放结果：

| w10、blend 0 | C1 Hermite | C2 spline | 变化 |
|---|---:|---:|---:|
| jerk样本P95均值 | 55.05rad/s³ | 34.08rad/s³ | -38.1% |
| 每段jerk最大值P95 | 808.79rad/s³ | 614.16rad/s³ | -24.1% |
| 每段加速度最大值P95 | 13.18rad/s² | 12.12rad/s² | -8.0% |
| policy偏差P95均值 | 0.002320rad | 0.002320rad | 基本不变 |
| policy最大偏差P95 | 0.013208rad | 0.013208rad | 基本不变 |
| 插值过冲最大值 | 0.000779rad | 0.000713rad | 略降 |
| 物理限位违反 | 0 | 0 | 不变 |

最新`134025`原始动作的17次切换上结论一致：同为w10时，spline相对Hermite的
jerk P95从49.5降到30.9rad/s³，jerk最大值P95从811.5降到626.8rad/s³，加速度P95
从13.38降到12.16rad/s²。

该profile已作为可选实现并通过单元测试，但尚未写入`09_powered_rtc.sh`默认参数。
实验顺序保持单变量：先用当前Hermite再跑一次带真实时间/GDK耗时trace的10秒基线；
确认调度来源后，仅把profile切换为`spline`做第二个10秒A/B。这样不会把调度诊断和
插值算法变化混为一谈。

### 移动轨迹blend消融

为同时缓和RTC边界而不复现固定anchor刹停，又测试了30/60/90/120ms的旧计划→新计划
移动交叉淡化。权重使用两端一、二阶导数均为0的quintic smootherstep。101次切换上，
C2 spline无blend的jerk峰值P95为614rad/s³；四档移动blend依次为849、1024、880和
663rad/s³。60ms以上还把加速度峰值P95从12.12提高到16.90--18.24rad/s²。因此该方案
被否决：RTC已有C0/C1，继续人为交叉淡化增加了额外曲率，不能解决当前边界体感。

`09_powered_rtc.sh`默认仍为`cubic_hermite`，并新增显式profile参数。完成基线后，C2
A/B命令为：

```bash
bash scripts/09_powered_rtc.sh --duration-seconds 10 \
  --arm-interpolation-profile cubic_spline
```

## 第二轮Hermite真机诊断（2026-08-21 13:56）

`g2_powered_rtc_100s_20260821_135624.jsonl`仍是w10、Hermite、稳态blend 0和手部V2，
包含51个chunk、50次切换，没有schedule miss、safe hold或动力学拒绝。文件名虽为100s，
本轮实际约34.8秒并在51次request budget耗尽后正常结束；正确100秒预算应为151次。
后续`runtime_start`会直接记录`max_requests`，不再只依赖文件名判断。

新增完整arm trace揭示了chunk内部抖动的主要实现原因。49个完整稳态段共3289条双臂
命令，其中33段出现至少一次小于5ms的相邻下发，合计37次。典型尖峰是：
`16.07ms → 1.05ms → 19.63ms → 0.36ms`。旧Servo循环错过deadline后把deadline重置
到当前时刻，却没有等待下一个周期，所以下一轮立即补发；这正是长间隔后紧跟近零间隔
的“追赶帧”。第42段因此得到5.36rad/s瞬时速度和188087rad/s³的内部jerk峰值。

GDK不是主瓶颈：双臂`joint_servo_control`调用耗时P50约0.25ms、P95约0.89ms，
单段最坏调用的全局最大值5.57ms。jerk峰值与GDK最大耗时相关系数仅约0.05，而与最坏
发送间隔相关系数约0.46。

离线删除37条近零间隔追赶帧，近似新的“miss后丢帧、完整等待10ms”调度语义：

| 真实采样时间指标 | 原调度 | 禁止追赶帧回放 | 变化 |
|---|---:|---:|---:|
| jerk样本P95均值 | 360.1rad/s³ | 233.1rad/s³ | -35.3% |
| 每段jerk最大值P95 | 39576rad/s³ | 4736rad/s³ | -88.0% |
| 加速度样本P95均值 | 2.60rad/s² | 2.32rad/s² | -11.0% |
| 每段加速度最大值P95 | 204.5rad/s² | 38.0rad/s² | -81.4% |

生产Servo现已改为：错过周期时不补发过期帧，而是从下一个完整10ms周期重新开始。
同时arm timestamp改为GDK调用开始时刻，而不是返回时刻。该回放是针对现有trace的近似，
最终收益仍需下一次真机日志验证。

## 当前实验规模与初步收敛

消融，不应表述为65次真机实验。

其中调度修复和C2 spline仍需要两轮10秒单变量真机A/B，其他选择已有离线和真机证据。

调度器会只睡原相位的剩余时间，例如16ms后睡4ms。第二版因此加入更强的不变量：
`next_tick >= current_tick_start + 10ms`。晚醒后直接丢弃旧相位，任何路径都不允许用
短周期追回平均频率。

在第一版真机trace上删除这42条残余短周期，近似第二版语义，预计jerk峰值P95还能从
