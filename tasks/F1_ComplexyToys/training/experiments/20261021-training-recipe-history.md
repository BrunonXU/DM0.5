## 3. 图像处理与正式随机增强

训练、验证、推理共用以下确定性路径：

```text
原始压缩图 → RGB解码
→ head固定ROI；两腕保留全图
→ 按比例BILINEAR缩放、居中黑色letterbox到224×224
→ 训练才执行下表随机增强
→ float32，像素 /127.5−1 → 模型
```

- head源图1280×720；归一化ROI `[0.24,0.04,0.96,1.0]`，实际整数框`[307,28,1229,720)`。图像分辨率/相机位姿变化须重审，不静默套错框。
- 当前ROI宽922、高692，确定性输出内容约224×168，上下各28像素黑边。左右腕同样等比缩放补边，不拉伸。
- π0.5库有基础预处理，但不会识别白桌ROI。保留当前 [process_image](../../src/f1_toys/processing.py) 的确定性算法，不能复制DM0.5的448分辨率。
- 2026-10-16 [ROI候选实图对照](../../DataPrehandle/visualizations/20261016-roi-comparison/README.md)：仅提高上界不改变物体像素尺度；再收右侧仅放大约5.9%，抬升/右移余量减少。当前建议保留原ROI；候选仅预览，未修改生产合同。

| 顺序 | 主图 | 左右腕图 |
|---|---|---|
| 1 随机裁剪 | 固定95%**面积**、正方形随机位置，resize回224；p=0.5 | 无 |
| 2 随机旋转 | 均匀±2°；p=0.5 | 无 |
| 3 ColorJitter | brightness0.3、contrast0.4、saturation0.3、hue0；p=0.5 | 同左 |
| 验证/推理 | 不做上述随机增强 | 不做上述随机增强 |

参数及每操作独立概率继承 [DM0.5/F1图像recipe](../../../../F1/foam_sort_whole_body/docs/training/dm05_eef_delta_recipe.md)；插值、边界填充和裁剪取整以冻结的真实增强实现为准，写入配置/预览参数，不能只记录“±2°”。无翻转、无额外大幅遮挡；几何增强作为温和观测扰动，不变换机器人动作坐标。

**增强只能有一个所有者：任务训练adapter。** 关闭core内部二次随机增强。本轮由 [augmentation.py](../../src/f1_toys/augmentation.py) 实际执行，core内部增强关闭。生产处理已与用户审阅的9张确定性图、27张增强图逐像素一致。

每次训练读取由NumPy RNG产生新的draw seed，再按相机/操作独立派生；不同读取draw应有变化，断点恢复能继续正确序列，多卡不重复同一随机流。预览固定seed并保存replay参数；正式数据不离线永久烘焙随机增强。

历史ROI抽查为5条录制/79时刻，不能替代随机裁切后的覆盖检查。新增 [真实图像预览](../../DataPrehandle/visualizations/20261016-recipe-preview/README.md) 展示当前确定性输入与候选增强输入；生产处理核验见本轮实验；以后相机位置、ROI或增强参数变化须重新审图。

## 4. EEF标签、原生运动学与IK

对每个观测起点t，使用右臂**反馈**和同一原生运动学模型：

```text
T_anchor = FK(q_feedback[t])
T_target[k] = FK(q_submitted[t+k])
DeltaT[k] = inverse(T_anchor) @ T_target[k], k=0..49
label[k] = [DeltaT平移3, DeltaT旋转矩阵前两行6, submitted右夹爪]
```

平移单位m，在当前末端轴系表达；50步均相对同一个锚点，不能逐步累积。rotation6D解码采用与旧F1 reader一致的正交化，明确拒绝非有限/退化结果，不能悄悄填单位旋转。

FK锚点始终使用**原始精度的物理state16**，绝不使用已经归一化、clip或token量化的状态；量化仅用于模型观测条件。

**沿用既有 F1 原生DH/FK＋受限连续IK，不再比较选型。** [ArmModel/ContinuousIK](../../../../F1/foam_sort_whole_body/robot/kinematics.py) 包含第8行末端固定变换；HAL度数输入、内部rad、位姿m。F1-09 [原生FK fixture](../../../../F1-4242/tests/fixtures/f1_native_fk.json) 与该模型绑定的DH配置SHA一致。

已有 [同批数值验证](../../../../F1/foam_sort_whole_body/results/continuous_ik_20260916/README.md)：FK对SDK60,806条请求最大位置差3.91e-7mm；连续IK19,900次通过。前20步右臂直接SDK限位失败2134/3980，受限适配0/3980。后续 [64条扩测](../../../../F1/foam_sort_whole_body/results/ik_coverage64_20260916/README.md) 中右臂73,300次无拒绝，但有局部关节变化放大；不能声称所有预测都可解或连续。

这里的IK实际为受约束连续求解，不是把SDK返回分支直接下发。当前未找到同模型/同数据的Pink对照正式报告；[URDF与native模型差异](../../../../F1-4242/docs/MODEL_AUDIT.md) 不等于求解器胜负实验。标签FK与输出IK必须绑定同一native模型，不能混用尚有几何差异的URDF。

本轮只做小范围接线核验：新V1首/中/末及抓取/插入起点的`joint→FK→相对EEF→解码→右IK→FK`；首步以当前反馈为参考，其后以前一接受解为参考。目标关节真值只用于评估，不作为求解种子。冻结模型/配置/限位/端点SHA。

沿用严格数值基线0.01mm/0.001°，这不是机械实测精度。泡沫的5mm/0.05°演示容差不迁入插孔任务。预测目标不可解则如实失败，不改标签、不放宽门槛、不裁关节后冒充原EEF解。

## 5. 分字段归一化与mask

现有smoke状态mean/std在910个窗口上使右臂状态41.82%、state16总体25.25%的元素超出tokenizer的[-1,1]范围。旧“与官方tokenizer一致”仅证明编码一致，不能证明输入分布正确。原数据未损坏。

| 字段 | 本轮处理 |
|---|---|
| 右臂状态关节 | 用本轮有效训练观测的min/max映射[-1,1]；去重观测统计并记录样本数 |
| 左臂状态关节 | 用冻结的实际控制器HAL度数合法量程映射[-1,1]，绑定范围/映射SHA；避免把单条静止噪声撑满token范围，不借用URDF/rad限位 |
| 状态常量/近常量 | 常量居中；报告物理range和量化误差，显式登记近常量处理，禁止用极小std放大静止噪声；不得静默引入任意阈值 |
| 状态夹爪 | `(g−50)/50`，固定0–100物理量程 |
| 推理状态越界 | 为离散编码限制范围，并记录原始偏离量/次数；不把饱和后看似合法当成观测正常 |
| 动作相对位置3 | 本次最终锚点/窗口下独立train-only mean/std；保存统计基数 |
| 动作rotation6D | identity；不把每个旋转分量再按std放大 |
| 动作绝对夹爪 | `(g−50)/50`，反变换`50x+50`；原件范围异常先报告 |
| padding | 归一化零，不纳入统计、不计loss |

动作不因状态token范围而硬clip；state/action统计分文件字段、跟随新合同绑定。真实目标位置常量维使用明确scale规则并可逆。十几条数据到齐后重新生成统计和数据版本，不能继续沿用单条范围。

新10维bool mask同时用于loss、带噪输入、初始采样噪声和每步采样更新。loss按有效时间×有效10维平均，不能按32维稀释；bool mask不充当loss权重。仍只使用完整有效H50窗口，不在本轮引入未经贯通的尾部padding时间mask。

## 6. LoRA与首轮训练预算

本轮已实现 [原生LoRA](../../src/f1_toys/lora.py)，保持`openpi_rlinf`后端。普通PEFT目标名不能直接覆盖其ModuleList/裸Parameter结构，因此只注入实际执行的叶子Linear。

本轮冻结范围：Gemma语言/动作两个expert真正执行的Q/K/V/O叶子Linear；SigLIP实际执行的MLP fc1/fc2，让视觉参与适配；动作in/out投影、时间MLP完整训练。r32、alpha16、dropout0、bias=none。不能把此范围叫“所有线性层”：Gemma FFN裸参数、SigLIP functional attention需另验，首轮不为扩大覆盖重写它们。

注入后输出模块白名单、requires_grad、参数数量/dtype、冻结项和实际梯度。adapter初始等价base；只有指定参数更新。FFN/视觉attention覆盖扩展属于后续有证据的改动，不能在同一个run中悄悄变更。

实际配置见 [sft_eef_lora.yaml](../../configs/sft_eef_lora.yaml)。本轮r3训练与下一轮默认值的差别明确列出：

| 项目 | 实际执行 / 后续默认 |
|---|---|
| GPU | H20物理4–7四张，microbatch2、累积1、global batch8；单卡预检保持global8 |
| 预算 | 1000 optimizer steps首轮上限；先20–50步链路/吞吐检查；不是保证1000步收敛 |
| 优化器 | AdamW，betas=(0.9,0.95)，eps=1e-8，weight_decay=0，clip_grad=1 |
| 学习率 | 本轮峰值1e-4、warmup50、cosine实际到1e-6：继承的min_lr_rate=0.01覆盖了min_lr。下一轮YAML设min_lr_rate=null以落实1e-5；恢复旧run必须保留原日程 |
| 精度 | 沿现有可验证bf16混合精度；adapter/优化器dtype显式记录，归一化与数值检查float32 |
| 种子 | 20261016；数据、增强、训练噪声、评估噪声分别记录 |
| 检查/保存 | 预检可恢复；正式每250步及末步保存/生成诊断；保留optimizer/scheduler/游标/RNG/增强身份 |
| 验证 | 固定真实窗口、无图像随机增强、固定多组生成噪声；10步采样质量基线 |
| 日志 | 每次都用W&B＋TensorBoard；本轮主训练和预检由真实TB回填，恢复测试已从启动在线记录。凭据和链路见infra/WANDB |

单条910窗口下1000步×global8约8.8次窗口曝光；不是8.8次独立任务。DM0.5的100K、global32、lr5e-4、448图、token1024均不机械照搬。预检如需要调整，先记录原因再冻结正式run日程，不在续训时悄悄重启warmup。

## 7. 生成动作、恢复与交付验收

1. 新真实batch：图像链、状态token/量化、EEF往返、10维mask、单位和window来源可审阅。
2. LoRA：有限loss/梯度、有效参数更新、冻结项不变；训练/采样mask一致。
3. 恢复：step/optimizer/scheduler/数据游标/增强随机序列与dtype均一致，不能仅以权重能加载认定恢复通过。
4. 固定首/中/末、抓取/移动/插入窗口，报告前20步执行前缀及完整H50的EEF毫米/角度误差、夹爪开合时刻、IK拒绝、首步跳变/关节连续性；与base和保持当前姿态比较。FM loss仅作辅助，不用“少动”换低平均误差。
5. 这条轨迹上的拟合结果不叫泛化成功率，也不从随机拆分重叠窗口得出独立验证成绩。
6. 合并adapter为裸core推理权重，固定输入/噪声检查合并前后误差；完整优化器checkpoint留H20，6000D接收所需推理包。

推理bundle必须包含base/adapter或合并权重身份、LoRA目标、state/action统计、ROI/增强策略、prompt、动作mask/表示、H/FPS、native运动学与限位、代码/依赖身份、训练及生成检查记录。不能把新的EEF checkpoint交给旧关节decoder。
