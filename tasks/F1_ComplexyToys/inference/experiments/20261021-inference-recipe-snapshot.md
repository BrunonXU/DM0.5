## 1. 模型与确定性输入

6000D加载由H20交付、验收过的PyTorch π0.5合并权重；不能把2026-10-15旧绝对关节smoke权重当作EEF policy。启动校验bundle内模型、任务合同、统计、ROI、prompt、mask、H/FPS、运动学及代码身份。

```text
F1当前三图压缩字节＋实测state16＋请求身份
→ 6000D解码RGB → 主图固定ROI、腕图全图
→ 等比缩放/黑边224 → 像素[-1,1]；状态有界编码
→ π0.5生成H50×32（只右侧EEF10有效）
→ 动作反归一化/rotation6D解码
→ 用本次观测锚点还原绝对末端目标
→ 原生模型的右臂受限连续IK
→ 关节/夹爪目标＋身份返回F1
→ Control校验，仅执行约定前缀；左侧保持
```

训练与推理共用确定性Processor；推理不做随机裁剪/旋转/颜色增强。网络端优先透传原生JPEG/PNG，在6000D只解码和处理一次，不为了ROI在F1先解码裁图再编码上传。若源流本身需要编码，单独计时，不能虚报为零成本。

左侧状态可以作为观测上下文；左侧未监督的动作输出绝不执行。动作mask在初始噪声和每步更新保持有效，与训练一致。

## 2. EEF还原、IK位置和执行窗口

- 10维布局、单位、rotation6D矩阵前两行与训练完全一致。`T_target[k]=T_anchor@DeltaT[k]`；T_anchor来自该请求原始精度的反馈，不能使用归一化/clip/token量化值，也不能在收到回复时换成另一时刻的反馈重新解释旧delta。
- 直接复用原生DH/FK＋既有ContinuousIK，冻结参数和代码。新chunk首步参考请求的实测右臂角度；后续参考上一接受解，不用示教未来关节或SDK任意分支。
- 首版建议在6000D CPU完成右臂IK，以复用已有x86数值环境并把实际关节目标交给现有F1边界检查。记录它的时间与拒绝率；以后移动到机器人侧必须另验ARM依赖/耗时/一致性。
- 采用**H50预测、执行前20个30Hz动作周期**，沿旧F1/G2经验；执行窗口是配置，不等于所有预测都必须执行。20周期约0.667s，不含推理等待；底层控制仍沿F1现有时间调度。
- 模型完整H50留作离线诊断；在线优先只为实际执行前缀求IK，避免计算不会执行的后缀。响应字段必须显式区分`prediction_horizon=50`和`execute_steps=20`。
- 现有F1 HTTP客户端要求H×16完整响应，不能偷偷返回20步冒充50步。新WS客户端已版本化响应语义；如保留旧HTTP兼容，必须真实解完整H50或明确调整受校验合同，不复制末行伪造后缀。
- 对外若使用16D打包，左侧只作非预测占位；Control最终以**当前最近有效submitted**重填左臂/夹爪。不得把服务计算时的陈旧左侧快照或零HAL目标下发。
- 解码失败、IK失败、限位/腕耦合不合法均不输出可执行轨迹；通过既有失败处理报告，不以裁剪关节或放宽容差掩盖。保持既有机器人保护，不新增未评估滤波来抹平模型动作。

数值容差默认沿严格基线0.01mm/0.001°，不代表机械精度；泡沫5mm演示例外不迁入插孔。详见 [原生模型/连续IK依据](../../TRAINING_RECIPE.md#4-eef标签原生运动学与ik)。

## 3. 同步服务和客户端合同

参考G2最终实现的设计，不复制G2的34D、100Hz或其端口。

| 项目 | 决定 |
|---|---|
| 健康/能力 | HTTP健康检查；只有加载、预热、合同检查完成才ready；返回model_id/contract/capabilities |
| 推理传输 | 持久binary WebSocket，compression=None；三图原生压缩字节＋小metadata |
| 服务端口 | 6000D loopback8096；专用SSH反向转发至F1 loopback8096，独立于DM服务 |
| 在途/排队 | 每客户端最多1个inflight，服务端有界队列/明确busy；禁止积压过期FIFO |
| 断线 | 当前请求失败，后续请求才重连；不自动重发旧观测/动作 |
| 请求字段 | request_id、observation_id、policy_epoch/session、state16、三相机key/encoding/shape/length、时间信息、合同和模型身份 |
| 响应字段 | 回显身份、模型/合同版本、30Hz、prediction_horizon、execute_steps、有效右侧mask、绝对关节动作、服务分段耗时或明确失败 |
| 配置来源 | prompt、ROI、统计、动作语义由bundle固定；请求不能随意覆盖 |
| 时间证据 | 保留现有可用源/接收时间；缺乏曝光时钟校准就明确未知，不伪称跨相机同步 |

新增 [WebSocketPolicy](../../../../DAgger/F1/src/f1dagger/websocket_policy.py) 已实现持久连接、身份与能力校验；旧HTTP行为保留。WS单元及真实socket/子进程测试通过，F1 ARM客户端inspect已通过；ARM最终真实模型客户端10次持久连接调用已通过，包含真实关节/腕耦合边界检查。

现场默认独立sync入口：`--duration-seconds`（默认60秒）或`--continuous`，Enter授权，无手柄和IntentServer；时长含推理等待，截止前最后发布检查，Ctrl+C/硬故障退出。IK恢复采用保持、新观测最多额外3次重试、耗尽暂停/Enter恢复；上线验收以STATUS为准。完整命令见 [启动说明](../STARTUP.md)。旧HIL接管模式仍独立保留，不伪造输入心跳。

当前唯一Control owner与既有接管/epoch保护保留；**已隔离的是网络子进程**，图片封包与采集仍在现有F1进程，大图经过网络子进程Pipe。本轮没有实现完整G2式Control/Policy进程分离，不能宣称已达到其隔离水平。复位/Home/接管后递增epoch，迟到回复拒绝。shadow脚本只创建ROS订阅，无owner和命令publisher。

## 4. 推理计算优化与RTC占位

已完成同checkpoint、9窗口×2噪声种子的10步/5步对照，**默认5步eager**：6000D前20步位置误差6.47→5.87mm、角度1.88→1.78°、夹爪误差1.87→1.94点，全部IK成功；模型中位179.84→118.99ms。范围仅该示教轨迹，尚未证明泛化不降。固定3×224、H50、内部32、token200；不要复制DM的448图或1024 token预算。

LoRA合并后部署，验证与未合并模型同输入/同噪声结果；避免动态adapter增加运行复杂度。之后优先只编译action expert，检查真实重编译和冷/暖态时间；DM的`reduce-overhead, dynamic=False`是参考，当前π0.5结构需要自己的验证，不盲套包装。

首版仍为同步：观测→等待推理→执行前缀→新观测。30Hz动作间隔不意味着每秒30次模型调用；不提前用异步双缓冲改变“同步”的含义。

RTC能力先声明`sync=true, rtc=false`。预留版本化可选字段：committed prefix、delay_steps、execution_horizon、prefix action-space/version和锚点身份；现在收到RTC请求明确不支持，不能忽略字段悄悄按Sync执行。

未来RTC由Control拥有已提交前缀；延迟计入网络、处理、模型、IK和IPC。旧前缀要先保留绝对物理语义，再用**新观测锚点**重表达/归一化，不把上次delta直接当新chunk的前缀。不在本轮实现RTC算法。

## 5. 延迟测量与DM0.5对照

每请求分段：采集/选帧与年龄→封包→client RTT→server排队→解码/ROI/resize/tokenize/H2D→模型及回CPU→反归一化/IK→响应编码→client校验/IPC→Control收到。持续时间各端使用自己的monotonic；不能直接相减两台机器的monotonic时间戳。

验收按三层区分：

1. 本地固定输入：模型身份/采样步数/compile/负载相同，分别报cold/warm、预处理、模型、IK。
2. 真实F1→6000D通信：相同图像载荷echo/固定响应，再实际模型。loopback不能替代网络测量。
3. 真实相机/状态shadow至少500次：零动作发送，报告P50/P95/P99/max、payload、观测年龄、timeout/重连/busy/旧响应拒绝和GPU负载。

历史参考：[DM0.5真实网络348次shadow](../../../../DM0.5/docs/robot/experiments/NETWORK_TRANSPORT_AB_20260825.md)：

| 指标 | P50 / P95 / P99（ms） |
|---|---|
| observation→Control | 184.95 / 211.37 / 260.69 |
| WebSocket roundtrip | 183.16 / 209.02 / 258.87 |
| model＋回CPU | 135.82 / 137.61 / 139.71 |

本轮F1五步模型＋回CPU中位116.63ms；500次真实观测WS RTT P50/P95/P99为208.74/330.95/382.20ms，选中观测起点→响应403.88/525.37/566.06ms。后者包含串行测试取帧造成的约190ms队列年龄，不是Control收到的时刻。连接恢复后已补完：持续真实取帧500次RTT为200.44/223.75/250.08ms，观测起点→响应261.70/306.66/324.94ms，观测年龄中位61.02ms；同载荷echo/模型各500次RTT分别81.83/99.84/145.73ms、184.99/212.81/260.58ms，全部成功。echo含解码和协议开销，顺序测量的网络状态不同，不能将两个P50相减当纯模型时间。

这些DM指标是G2→6000D、不同模型/图像的历史数据，只作量级参考。公平传输A/B要求同发起端、网络路线、图像字节；模型部分另报。逐请求`RTT−handler`仍含协议框架等开销，不叫纯物理网络延迟，也不能用不同分位数直接相减代替逐请求统计。

此前F1约125ms是5次离线样本中后4次的暖态本地完整调用，含本地读图/预处理/采样/还原，不含真实网络，也不是纯GPU前向。需要在新实验中重新分项测量。
