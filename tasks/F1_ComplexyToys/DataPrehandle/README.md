# DataPrehandle：机器人示教预处理 SOP

这份SOP说明如何把机器人原始录制变成可信的训练样本。核心是分别判断“当前能不能看”和“未来哪些动作值得学”：保留真实时间与动作来源，遇到标签断点就停止，不能删掉坏点后把两侧拼起来。

当前V1已纳入审核通过的自动回位和短动作窗口，取消了训练数据的96窗口门槛；V1＋DAgger单臂输入版本和阶段采样A/B均已完成训练。2026-10-23释放链路抽查未发现错帧或夹爪标签反转，但发现静止等待时输入近似、释放时机不同的问题，正推进小样本拟合诊断。相机曝光同步、新场景覆盖和新录制schema4适配仍是独立问题。

日常只需看下面的当前结论；复用或修改预处理时再读执行步骤。想理解每一帧怎样进入模型，可打开[逐帧讲解](reports/20261020-window-walkthrough.md)与[交互说明](../artifacts/20261020-window-walkthrough/window-explorer.html)；旧演示的完整窗口规则不能当作当前规则。

## 1. 先分清几个概念

| 名称 | 本文含义 | 不能据此认定 |
|---|---|---|
| 原始观测 | 当次组装的相机帧、实测状态及各自来源时间 | 多路曝光同时发生 |
| 导出时间点 | 训练频率下的规则时间网格 `t₀ + k/fps` | 对应时刻恰好拍到一组新图 |
| 观测可用时间 | 整组观测完成组装、可交给消费端的时间 | 每张图的拍摄/接收时间 |
| 图像接收时间 | 本机收到对应相机回调的单调时钟时间 | 相机曝光时间或图像已解码时间 |
| 动作标签 | 有发布证据的 `submitted` 目标 | 遥操候选、模型建议、实测到位状态 |
| 训练起点（anchor） | 一个有效当前观测及其对应的未来动作窗口 | 一次独立示教 |
| 真实终点 | 示教/任务实际结束 | 因丢图或人工筛选产生的切点 |

本任务中，π0.5 的典型监督为：

> **当前有效图片和状态 → 从当前开始的一串动作。**

假设第 1 秒的观测正常，第 1.2 秒缺一张图，但后续动作日志连续有效，那么第 1 秒的观测仍可能用于预测后续动作。未来每个动作点不必同时拥有一张新图片；当前输入必须有效。

规则时间轴不等于相机曝光同步。任何图像保持、状态取样和动作保持都应保留原始来源时间，不能把生成的网格时间写成原始传感器时间。

## 2. 不变量与输入要求

1. 原件和旧候选只读；输出另存新目录，不覆盖历史证据。
2. 先通过 journal、payload、计数与哈希审计。`.partial`、shadow、输入测试及自由试玩不能作为专家任务数据。
3. 所有时间比较注明时钟域。当前 `f1_ros_header_unverified` 不能直接当已标定曝光时钟；先使用共同主机单调时钟，并明确其局限。
4. 模型输入不能使用目标时间之后才可用的观测。诊断实验若仅依据帧接收时间重配，需要单独标记，不能直接宣称与线上整组输入等价。
5. 动作标签来自真实发布记录，不用 measured/state 回填，不把未发布的插值指令当成真值。
6. Home、控制 owner/epoch 或接管语义变化、无效/不完整发布、状态失效、时钟回退、日志缺口等边界必须按对应语义处理。仅图片缺失不能自动证明动作标签失效。
7. 训练/验证按原始示教或采集场次划分。同一条示教切出的若干片段不能当成独立采集，跨集合复用来源。
8. 技术诊断不代替人工审核。manifest 哈希、审核有效范围、任务指令、处理配置须绑定；reader 通过不代表任务成功或训练已验收。

## 3. 执行顺序：先诊断，再改变配对方式

### 步骤 A：冻结基线与建立来源清单

**输入：** 完整原始 episode、journal/payload manifest、当前导出配置及已有报告。

**操作：** 记录源 manifest/流文件哈希、实际代码版本、相机字段、状态和动作布局；区分技术检查与人工审核。保持原始成功/失败/接管/复位等信息。

**产出：** 本次运行 manifest 与参数记录。对每次对照，明确唯一变化：选帧规则、动作窗口筛选、频率或视觉变换中的哪一项。

**验收：** 原件前后哈希不变；输出可定位每个观测、图像和命令的原始记录。无法追溯的输入停止导出并报告具体原因。

### 步骤 B：查清偏差来自队列配组、传输还是源时间戳

按以下顺序检查，不能由接收时间差直接推断曝光差或网络延迟：

1. **队列配组。** 检查各路 callback 序号、FIFO 取帧方式、排队年龄、组内接收时差、丢弃原因。比较当前整组配对与已有帧中逐路最近过去配对；保持同一组目标时间点，分别报告主图和右腕的变化。
2. **数据传输。** 查看回调间隔、突发到达、接收与组装的间隔。只有记录具备可比较的发送/接收时钟或额外测量，才能把延迟拆成相机、传输、解码、排队等部分；当前原件不足时明确记录“无法辨识”。
3. **源时间戳。** 核对 header 时间的产生位置、时钟域、单调性、重复/回退和时钟偏差。重复 source timestamp 与重复 JPEG 字节分别统计；字节不同不自动证明曝光时间正确。

最低统计项：原始/导出数量、逐路有效帧数、帧间隔 P50/P95/P99/max、相机间接收时差、各路接收到输入时间的年龄、整组就绪到网格的年龄、状态年龄、命令完成到标签时间的年龄、异常发生位置。分清中位数、尾部与少数异常，不能只用平均 FPS 掩盖缺口。

抽查异常前后的主图/右腕画面与状态曲线，尤其是夹爪闭合、物体接触和插入阶段。数据检查能确定配对差异；任务效果还需后续模型评测。

**验收：** 每个结论标记为直接证据、合理推断或待验证。任何固定时间补偿都需要经过时钟和实际延迟验证。

### 步骤 C：把输入有效性和标签有效性分开

#### C1. 输入判断

在候选时间 `t` 检查：

- 本任务必需相机是否具备可用帧、来源是否可信、各自年龄和相互时间差是否满足已选规则。
- 状态是否来自有效反馈，时间是否不晚于消费时刻，是否足够新。
- 观测是否处于允许学习的任务/控制范围；不能把接管前的图片标成人工接管后的示教。
- 不使用的相机保留原始记录，但不因其单独的图像缺口自动否定必需输入；必须与模型 image mask 和在线输入配置一致。

先实现“最近过去整组观测”的离线基线，以便单独验证动作解耦；逐路选帧作为另一个候选单独比较。旧原件中未保存的帧不能重新生成。

#### C2. 标签判断

在 `[t, t + (H−1)/fps]` 范围内，检查每个动作点及两点之间的完整控制日志：

- 选最近已完成发布的有效 `submitted` 命令；时间差不过期，16D 来源清晰。
- 同一允许学习的控制范围、intervention/epoch、powered 与完整发布状态。
- 不跳过窗口中间的未批准Home、无效发布、未知控制、过长控制日志空缺再拼接。明确批准的已完成V1 Home是监督来源例外，保留连续原始发布及source，详见本轮SOP。
- 不超出真实 episode 终点或明确的人工审核范围；当前 F1 夹爪未变化时可保持原发布值和时间，不能把“没有重新发同值夹爪”误当丢失指令。

**当前决策：** 输入无效只拒绝相应起点。输入有效时，从该起点检查连续的未来动作，遇第一处标签无效即停止；若已有至少1步可信动作，就保留这段真实前缀并mask剩余位置；连第1步都无效才拒绝该起点。未来图片缺失本身不截断可信动作标签。动作真值与当前输入的质量分开计数、分开解释。

伪代码：

```text
for t in 固定的真实时间网格:
    observation = 当前时刻已经可用的观测
    if not input_valid(observation, t):
        记录拒绝起点的原因
        continue
    actions = []
    for j in 0, ..., H-1:
        target = t + j / fps
        if target超出原件或审核范围:
            记录截断原因
            break
        if not label_and_intervening_control_valid(上一目标时刻或t, target):
            记录截断原因
            break  # 不跳过坏点，不连接断点之后的动作
        actions.append(最近已完成发布的有效submitted命令)
    L = len(actions)
    if L < 1:
        记录拒绝起点的原因
        continue
    time_mask = [True] * L + [False] * (H-L)
    保存 observation、真实actions、time_mask、来源与时间、规则版本
```

上面的逐区间检查包含原始控制序列完整性、发布新鲜度和控制来源；并非只检查网格上抽中的几条命令。只有审核清单绑定的已完成V1 Home允许作为自动控制标签例外；其他自动Home和policy动作不会因此自动变成专家标签。批准Home与人工段相接仍须满足同一intervention/epoch及全部发布连续性条件。

被拒绝的起点是采样索引上的排除；不是把底层轨迹删行后压缩时间。当前RLinf reader已消费此索引和时间mask；迁移到其他reader时也必须检查，不能在普通LeRobot随机索引后重新把被拒绝起点取回来。旧完整H50基线在标签不足50步时拒绝整个起点，仅用于历史对照。

### 步骤 D：频率与质量条件分别配置

- 采集目标频率、训练动作采样频率、模型重规划周期和底层控制频率分别记录。
- 生成网格时按有理周期独立计算 `round(k×10⁹/fps)`，避免反复累加取整周期；不外推到原件结束之后。
- 以毫秒单独配置观测、相机、状态、命令与控制日志缺口条件。现有旧导出 `1.5/fps` 会在 30Hz/20Hz 间将部分门槛从 50ms 变成 75ms；频率对照不得悄悄同时放宽门槛。
- 比较相同源数据、审核范围、必需相机和质量条件下的 30Hz/20Hz；25Hz按需要增加。
- 相同 H=50 时，首尾跨度 30Hz 为 49/30≈1.633s，20Hz 为 49/20=2.45s。频率实验必须注明这个变化；若要求公平比较同样预测时长，另设计按秒匹配的窗口实验。
- 推理必须保持训练动作的时间间隔；高频底层保持/插值目标需单独定义，不能把 20Hz 标签逐点按 30Hz 播放。

**验收：** 不只是统计多少行，还要统计唯一来源观测、观测沿用、有效时间覆盖、有效训练起点、完整动作窗口和拒绝原因。不能把复用观测算成新增曝光。

### 步骤 E：区分自然终点与人为切点

当前V1保留连续真实前缀 `1≤L≤50`，不足50的尾部只为张量形状补零，并通过时间mask排除。它不是“在结束后继续保持”的监督，也不是把短轨迹补成另一条完整示教。

- 任务成功自然结束后，保持最终绝对位置可能合理，但必须有任务语义和原始发布证据；本轮不向原件结束以后外推。
- 因缺图、审核裁剪或日志故障形成的末尾，不代表机器人应该停止；不能把重复末动作默认当真监督。
- 时间mask已进入真实训练路径：padding动作和噪声清零、无效位置不作为有效attention query/key、每个起点的loss先按真实L归约再平均batch。动作维度mask独立存在，不能用它代替时间mask。
- 归一化统计只使用训练集真实有效标签，padding与验证不参与。推理仍生成H50；离线误差只评估有真实标签的前缀。
- OpenPI 某些绝对位置动作配方使用末动作保持；这不构成对任意人为断点的通用处理许可。

**96和50是两件事。** 50是每个样本的动作张量长度；96曾是整条记录进入打包的错误门槛。现在训练分支只要求至少1个有效窗口，验证分支仍要求96个互异窗口用于固定抽样，短验证记录会明确报错，不能复制凑数。取消96门槛允许短记录中已有的窗口进入训练；时间mask进一步允许不足50步的起点获得部分监督。旧15条均超过96，旧门槛没有删掉这批V1记录。

CPU、reader和Full GPU验收及训练记录已分别留证，见[mask细节](reports/20261020-home-time-mask.md)与[Full训练记录](../training/experiments/20261020-v1-fullsft.md)。复用时仍须检查mask真正进入统计、输入、attention和loss；仅返回 `action_is_pad` 不等于完成支持。

### 步骤 F：视觉、动作与统计适配

主视角 ROI 必须覆盖白桌、物体、桶/孔和夹爪实际路径；坐标/原图分辨率/缩放方式版本化。旧冻结版本保留三路有效图像；当前V1＋DAgger单臂版本已屏蔽左腕，使用固定占位加有效的image_mask=false，不能只给黑图。图像处理与状态隔离在训练/推理共享，具体合同见[训练recipe第0节](../TRAINING_RECIPE.md#right-only-input-fix)；训练专用随机增强只处理有效图。

F1 原始 16D 是左臂 7 维、右臂 7 维、左右夹爪各 1 维，角度为 degree、夹爪 0..100；动作来自发布目标，state 来自反馈。是否转换单位、关节 delta、模型内部 padding 均通过明确的适配器与往返检查实现，不能套用 ALOHA 14D/其他机器人的统计。

原始16D与模型输入分开：单臂adapter只让右侧8维信息进入模型，不能原地改写左侧实测数据、伪造缺失反馈，或把模型占位送给FK/IK/控制器。硬件拆除造成的缺失字段需另有能力/记录schema，不由模型mask自动解决。

只用训练划分计算最终采用表示的归一化统计，与 checkpoint 及处理配置一同保存。验证/推理采用同一统计，统计后再次检查常量维度、范围、NaN/Inf 和夹爪方向。

### 步骤 G：逐级验收与回退

1. 合成回归：微小抖动、未来图片缺失而动作完整、当前观测过旧、控制空缺、Home/epoch/无效发布、真实终点与无未来输入。
2. 历史原件只读对照：原件哈希不变，起点/标签来源可追溯，频率对照参数明确。
3. 图像与动作回读：从候选源指针实际解码，检查 ROI/mask、状态和动作值及顺序。
4. RLinf 真实 batch：确认采样索引被采用、无跨边界窗口、归一化/维度/掩码正确。没有这一步不能声称新索引已是正式可训练数据集。
5. 小数据训练、离线推理，再由现场操作者执行固定场景 rollout。比较成功率、夹爪时机、接触/插入偏差与轨迹节奏，不能只看 loss。

每一候选与旧基线并列保存；替换依赖验证结果，不以更高利用率自动判定更好。

### 历史候选结果（2026-10-14，不是当前数据规模）

四条历史原件各生成 30Hz/20Hz 两份完整 H50 动作索引，原件双次审计通过；逐窗口独立核对 state、实际发布 action、来源时间戳、中间控制流及边界。30Hz 下三条任务候选的完整窗口合计 **1564→2252**；仅 Home/保持条目仍为 0。29秒条目 **627→823**，其中185个候选窗口跨过未来图片缺口或 callback 断点，实际动作仍连续。

上述变化包含全局网格替换旧逐段网格、必需相机规则与动作解耦，不能全部归因为单一变量。窗口彼此重叠，不代表新增示教；任务成功未人工批准。20Hz 同样 H50 覆盖更长未来时间，不能直接比较窗口数判断效果。

时间配组诊断使用旧候选相同862个时间点：主图接收年龄中位数 **81.812→15.924ms**，三路接收时差中位数 **58.212→15.829ms**。这是独立相机缓存可实现的离线选帧候选空间；当前整组输入接口尚不能在那些时刻提供所选帧，未切换为正式训练/推理方案，不能宣称曝光同步已修复。

原件、新索引、时间诊断及视觉抽查分别保存，位置见 [任务 artifacts](../artifacts/README.md)。候选不得写回原 episode 子目录，不得覆盖旧报告。
