# V1真实逐帧例子：观测、H50动作窗口与96门槛

本页用已经进入正式训练的V1记录，解释“一条示教怎样变成多个训练样本”。每个样本输入当前三路图片、状态和指令，监督从当前开始的有序动作；训练不是把整条录像按顺序播放给模型。

这是一份旧LoRA完整H50版本的逐帧讲解：96门槛没有删掉当时15条V1中的窗口，但会错误阻挡未来短记录。原始逐帧数字保留，用于理解起点、动作标签和窗口的区别。

## 1. 什么被输入，什么被监督

本文核查的旧LoRA reader单个样本是：

```text
条件输入：当前三路图片＋当前实测状态＋固定任务指令
监督答案：当前时刻起的50个有序发布动作
```

训练flow matching时还会对这份动作标签加噪并学习去噪；这不等于推理时能看到未来答案。模型条件输入没有整条过去视频，也没有需要跨训练样本保持的循环隐藏状态。

样本池可以先抽第100个起点，再抽第400个起点。每个样本内部的动作仍按0、1/30、2/30……49/30秒排列，没有乱序，也没有把两个片段拼接。H50固定的是当前动作输出的形状和时间范围，不是“只有50步才可以产生学习信号”的理论限制。

在DAgger中，原始混合轨迹完整归档；监督构造另行筛选：

| 状态与动作 | 用途 |
|---|---|
| 正常状态A＋导致偏离的自主动作 | 不自动作为专家监督样本 |
| 已经偏离的状态B＋经审核的人工恢复动作 | 保留为恢复学习样本 |
| 正常状态A＋成功示教中的正确动作 | 保留为正常执行样本 |

错误状态B是模型需要理解的条件，不是让它主动制造的目标。当前实现还要求anchor已经处于有效人工上下文，未来整窗同样有效；不能只审核起点。不能把B的纠正动作倒贴给更早A的图片。

数据筛选消除了“直接监督错误动作”的问题，不保证模型绝不发生视觉混淆或错误泛化；仍需正常状态/偏差状态的成对评估，避免纠正过采样让正常行为退化。

## 3. 跟随一个真实训练样本

以下`g100`表示从0计数的第100号时间网格，不等于相机帧ID。时间零点取这条记录的首个训练网格。

### 3.1 选当前输入

- `g100`时间为3.333333秒，精确单调时钟`6132330414339 ns`。
- 使用原`observations.jsonl`第101行，`observation_id=12912`。
- 三图frame ID为主图13102、左腕13130、右腕13130；组装后的观测早于网格0.164155ms。**这不是曝光年龄**：主图接收年龄约49.046ms，左右腕约1.340/7.568ms。
- 当前实测状态、三图经过既有ROI/224与训练增强，固定prompt沿用正式包。
- 它实际进入训练包`samples.jsonl`第11276行。

### 3.2 找50个动作标签

查询网格100至149，各时刻取最近过去的有效已发布目标，检查中间控制来源与边界。以下为真实抽取结果：

| 窗内第几个动作 | 原网格 | 相对当前输入的目标时间/s | 原control.jsonl行号 | 右夹爪发布值 |
|---:|---:|---:|---:|---:|
| 1 | 100 | 0.000000000 | 724 | 0 |
| 2 | 101 | 0.033333334 | 731 | 0 |
| 3 | 102 | 0.066666667 | 738 | 100 |
| 25 | 124 | 0.800000000 | 884 | 100 |
| 49 | 148 | 1.600000000 | 1050 | 100 |
| 50 | 149 | 1.633333334 | 1059 | 100 |

因此这个样本确实包含时间信息，例如前两个动作夹爪目标为0，第3个改为100。这里只陈述发布目标变化，不能凭它认定抓取成功。标签不是连续50行控制日志，也不是未来50张图片。

每一步的精确时间、来源行、发布序号、完整16维关节目标和正式10维EEF标签都在[50步逐项CSV](../../artifacts/20261020-window-walkthrough/anchor-100-h50-all-actions.csv)。关节目标经原生FK转换为相对**本次当前观测锚点**的EEF10，再按train-only统计归一化；不是逐步累加相邻动作delta。其他22个内部动作维保持既有mask。

### 3.3 再向前移动一个起点

两个窗口共享49个原始绝对发布目标，但以不同当前实测状态作为EEF锚点，不能直接复制归一化后的相对动作标签。完整对照见[g101的50步CSV](../../artifacts/20261020-window-walkthrough/anchor-101-h50-all-actions.csv)。

### 3.4 真实缺图和控制边界

- `g180`的窗口180…229被保留；其中`g206`因当前观测过旧，不能单独成为新样本起点，但它对应的发布动作仍可以作为g180的未来标签。输入/标签解耦已经在真实数据中生效。
- 最后一个合格起点`g618`在20.6秒，监督618…667，进入训练包第11791行。
- 下一起点`g619`需要619…668；第668点已进入Home。因此旧完整H50规则拒绝整个g619样本，不能把Home当专家任务动作。
- Home后`g725…731`只剩7、6……1个动作点，都因未来不足而拒绝。这些是后期`human_hold`，不能因为有时间mask就自动认定它们有学习价值。

## 4. 用真实数据截一个教学片段，解释41与96

**这里人为假设数据到g189就结束，教学片段为g100…189共90个动作点。真实原件没有在这里结束，这90个起点在原完整记录里全都有H50。不能把以下数量写成本次实际丢失。**

| 教学片段的起点 | 从该处到假设终点189可用动作数 | 当前完整H50是否成立 |
|---|---:|---|
| g100 | 90 | 是，取100…149 |
| g101 | 89 | 是，取101…150 |
| g140 | 50 | 是，取140…189 |
| g141 | 49 | 否，尚缺第50个 |
| g142 | 48 | 否 |
| g160 | 30 | 否 |
| g188 | 2 | 否 |
| g189 | 1 | 否 |

从100到140含两端共41个完整窗口。两个不同的限制由此分开：

1. **取消96门槛：** 已经合格的41个完整窗口可以打包训练。它们本身完全不需要短时间步mask。
2. **未来时间mask方案：** g141的49步、g160的30步等，可能成为额外监督；占位不当专家标签，具体最短长度/质量与模型接线仍待讨论。

后49个起点不能构建完整窗，不等于后49个动作完全没学。例如g189仍然是g140完整窗口的第50个标签。

逐起点90行表见[教学截取CSV](../../artifacts/20261020-window-walkthrough/TEACHING-EXCERPT-90-grid-points.csv)。

## 5. 为什么本次V1没有被96影响

逐条原索引与正式包计数一致，15条完整窗口数量为616–1597。训练12条共11,791窗口全部保留；验证3条共2,965窗口也全部存于包中。周期验证只从每条验证记录抽96，共288，训练reader没有这项子集抽取。

`prepare_formal.py`的错误是训练分支也执行`count < 96`就报错。如果真的触发，会拒绝构包，不是静默只保留96或悄悄删除短段。本次每条远高于96，因此没有触发。逐条证据见[episode-counts.csv](../../artifacts/20261020-window-walkthrough/episode-counts.csv)。
